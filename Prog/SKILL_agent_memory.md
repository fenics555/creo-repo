# Направление: Программирование
# Priority: critical
# When: memory, context, long-term, agent, state, management, letta, memgpt, stateful

## СТАТУС: ЗАВЕРШЕНО (ЭТАП 1)

## КОНЦЕПЦИЯ
Принципы управления состоянием (state) и памятью ИИ-агента для работы в условиях ограниченного контекстного окна. Основано на архитектуре MemGPT/Letta. Позволяет превратить "краткосрочную" сессию в "долгосрочного" агента.

## ТРИ УРОВНЯ ПАМЯТИ
Для эффективного управления контекстом агент должен разделять информацию на три типа:

1. **Core Memory (Ядро)**:
   - **Что это**: Самая важная информация, которая должна быть всегда в контексте (Identity, текущая цель, ключевые ограничения, "якоря" проекта).
   - **Управление**: Нельзя забивать Core Memory деталями. Только суть.
   - **Действие**: Если информация становится второстепенной, она должна быть перемещена в Archival Memory.

2. **Archival Memory (Архив)**:
   - **Что это**: Огромный объем данных (документация, старый код, логи, история прошлых сессий).
   - **Управление**: Доступ через поиск (RAG/Search). Информация не находится в контексте, пока агент её не запросит.
   - **Действие**: Использовать `search_codebase` или специализированные инструменты поиска для извлечения данных из архива.

3. **Ephemeral/Contextual Memory (Эфемерная память)**:
   - **Что это**: Текущий поток рассуждений, детали текущего шага, временные переменные.
   - **Управление**: Очищается при завершении задачи или передаче эстафеты.
   - **Действие**: Использовать для "рабочего черновика" внутри одного сообщения.

## АЛГОРИТМ УПРАВЛЕНИЯ КОНТЕКСТОМ (STATE MANAGEMENT)
При работе над длинной задачей агент должен следовать циклу:

1. **Assess (Оценка)**: "Сколько информации в моем окне? Есть ли в нем 'мусор' или устаревшие данные?"
2. **Retrieve (Извлечение)**: "Нужна ли мне информация из архива? Если да, использую поиск."
3. **Consolidate (Консолидация)**: "Могу ли я сжать текущие рассуждения в короткий 'якорь' (Summary), чтобы освободить место?"
4. **Update (Обновление)**: "Нужно ли обновить Core Memory (например, если цель изменилась)?"

## ПАТТЕРН "ЯКОРЬ" (ANCHOR)
Для передачи задачи между "ногами" (сессиями) или при перегрузке контекста, агент ОБЯЗАН создать **ЯКОРЬ**:
- **Состав якоря**: 
  - `CURRENT_GOAL`: Текущая подзадача.
  - `LAST_SUCCESS`: Что было сделано.
  - `NEXT_STEP`: Что нужно сделать следующим шагом.
  - `CONTEXT_SUMMARY`: Краткая суть окружения (пути, версии, состояния).
  - `BLOCKERS`: Что мешает прогрессу.

## ПРАВИЛА ПРИМЕНЕНИЯ ДЛЯ АГЕНТА
- **Не доверяй памяти**: Если сомневаешься в факте из прошлого сообщения — перечитай файл или используй поиск.
- **Экономь токены**: Не копируй огромные файлы целиком, если тебе нужна только одна функция. Используй `read_files` с диапазоном строк.
- **Следи за "дрейфом"**: Если ты начал рассуждать о чем-то, что не относится к `CURRENT_GOAL`, немедленно вернись к цели.
