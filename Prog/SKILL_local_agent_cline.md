## 1. ПРИВЫЧКИ ПРОТИВ ВЫЛЕТОВ (главное)
1. Сообщение заканчивается ЛИБО вызовом инструмента, ЛИБО явным маркером
   «ПАУЗА: жду слова пользователя». Тихо закончить рассуждением нельзя (crash_agent_silence).
2. Пересказ плана — не шаг (13.2): план сложился → в том же сообщении идут вызовы.
   Не повторять один и тот же план 3+ раза (crash_plan-loop-replan-no-exec).
3. Мини-спека на ногу — до 5 шагов; длинную задачу дробить и передавать якорем (13.12).
4. Контекст экономить: читать только нужные файлы (1-2 за раз), большие файлы — диапазонами
   по якорям, не тащить в контекст простыни. 131k не бесконечны: держи в окне цель и якорь.
5. Больше ~20 вызовов на ногу — остановка, отчёт, передача.

## 2. ТРАНСПОРТ run_commands (PowerShell)
1. Одна команда ≤ 25 секунд: таймаут инструмента 30 с, а Start-Sleep его съедает
   (crash_command-30s-timeout). Ожидание — чанками по 20-25 с, длинное — детачем в лог.
2. Питон живёт ТОЛЬКО в .py-файле, запуск: `cmd /c "python -X utf8 file.py > out 2>&1"`,
   чтение: `Get-Content -Path out -Encoding utf8`. Инлайн `-c` через PowerShell обрезает
   stderr и врёт (crash_ctl-inline-stderr-truncated).
3. Кавычки — без обратных слэшей; сложные строки выносить в .py/.ps1
   (crash_quoted-escape-parse-failure).
4. Не читать файл в той же пачке, где его создали: после `Copy-Item` сначала `Test-Path`,
   потом чтение (crash_runcommands-copy-race).
5. Параметры командлетов — из живой цитаты (`Get-Help`/`Get-Command`), не из памяти:
   у `Get-Content` нет `-LineNumber` (есть `-TotalCount`, `-Tail`; номера строк — `Select-String`).
6. Кириллицу консоль не несёт: verbatim-русский входит в файлы только через редактор;
   ASCII-скрипты — с эскейпами \uXXXX.
7. ПРОТОКОЛ ОЖИДАНИЯ ДЕТАЧ-ПРОЦЕССА: запустил детач → ОДИН контрольный опрос
   через 20-25 с; результата нет → стоп-отчёт («запущено, PID, где будет результат,
   приёмка в следующей ноге»); второй опрос того же файла ЗАПРЕЩЁН
   (crash_sleep-poll-loop-after-timeout). Тяжёлые приёмки гонять на изолированном
   тестовом корне, не по живым сетевым дискам.

## 3. РЕДАКТОР (editor / write_file)
1. Блоки правки — до 3 КБ; `old_text` брать из СВЕЖЕГО чтения, а не по памяти.
2. «text not found» = устаревший якорь или CRLF/LF-расхождение
   (crash_editor-text-not-found, crash_editor-mismatch): укоротить якорь, перечитать файл,
   либо якорный патч ASCII-скриптом (скрипт сам проверяет, что якорь найден, и НЕ пишет
   файл, если нет).
3. Файла нет → `write_file` одним вызовом; файл есть → правка якорями.
   полная замена файла = один write_file по существующему пути (перезапись, old_text не нужен, удаление не нужно); Remove-Item по файлам дома без прямого слова пользователя = нарушение пункта 5 манифеста, veto.
4. Большой файл не собирать вставками вразнобой (5.8): либо один полный вызов, либо
   дописывание строго у последней строки.
5. Вес блока считается ДО вызова editor: new_text свыше 4 КБ = запрет целого вызова,
   дробление якорями до 3 КБ или полная замена каналом дома.
6. Файл с дублями (неуникальные якоря) = задача перезаписи, а не правки: восстановление
   из последнего чистого коммита гита + запись каналом дома (один write_file до 8 КБ или
   часть 1 + дописывание строго у последней строки); PowerShell Set-Content для файлов
   с кириллицей запрещён — консоль её не несёт.
7. После правки .py — `py_compile`; после правки витрины — `dev\ui_probe.py` и `dev\ui_check.py`.
8. Приёмка UI — только в живом браузере (Ctrl+F5, чистая консоль, слово пользователя).

## 4. КРАХ: ЧТО ДЕЛАТЬ
Сообщение пользователя о тихой смерти или вставка консоли/скрина = достаточная цитата краха; новая нога пишет крах-скилл от имени умершей с пометкой источника цитаты.
Отчёт в задаче (что делал, строка ошибки дословно) + скил в `crash\` по шаблону
конституции.
Та же подпись повторилась — прочитать профилактику скила и увеличить счётчик;
3+ = пользователю.
Сначала зафиксируй, потом лечи.
Упавший шаг дословно не повторять: либо смена метода, либо процитированная
причина (13.2/7).
ОТВЕТ ВОСКРЕШЕНИЯ — НЕДЕЛИМЫЙ АТОМ (одно сообщение, пять точек в этом порядке,
пропусков нет): 1) read_file D:\AI\repo\SKILL_local_agent_cline.md целиком одним
вызовом; 2) если диагностика назвала подпись с крах-скиллом в crash\ — прочитать и его,
профилактика до хода, а не после; 3) диагностика: пять вопросов цитатами + якорь
(что на диске + следующий шаг); 4) РЕГИСТРАЦИЯ: подпись с живым скиллом = счётчик +1
в нём с цитатой строки; подпись новая = write_file нового скилла в crash\ по шаблону
конституции в том же сообщении; не можешь писать скилл сейчас = строка в сообщении
«скилл долг: <подпись>, причина, запишу следующим шагом»; без вызова регистрации или
долговой строки атом неполон = нарушение; лечебные вызовы (editor, правки, лечение)
в сообщении ДО регистрации запрещены; 5) строка-доказательство в конце того же
сообщения: «скилл выживания прочитан; крах-скил: <имя | создан <имя> | долг>» —
без токена регистрации строка неполна, и нарушение видно с одного взгляда пользователя.
Сообщение без любой из пяти точек = неполное = нарушение; в режимах Crash/Revive
оптимизация вызовов и чтений запрещена: ритуал — механизм синхронизации, а не
накладной расход (crash_omission_of_revive_protocol).

### 9.1 Пять запретов, за которые платят петлёй
1. Два одинаковых вызова инструмента с теми же параметрами — смена метода; третий = петля

1. `editor` > 6 КБ, `insert_line` по номерам строк, правка существующего файла без `old_text`

   второе несовпадение → полная замена файла одним `write_file` по существующему пути.
3. Не читать файл в той же пачке `run_commands`, где его создали: сначала `Test-Path`
   (crash_runcommands-copy-race).
4. Параметры командлетов — только живой цитатой `Get-Help`/`Get-Command`; у `Get-Content`
   нет `-LineNumber`.
5. Разрушительный скрипт удалять СРАЗУ после пробы; перед запуском любого tmp-скрипта —
   прочитать его (crash_destructive-probe-rerun: так потеряны две живые сессии Creo).
6. Удаления вне `data\tmp` и `data\backup` — только прямым словом пользователя;
   pid-файл агента = `D:\AI\tools\agent\agent.pid`, НЕ `data\agent.pid`.
7. Кириллица и русские кавычки — только через редактор; консоль их не несёт.
8. Вставка блока в витрину: цитата числа вхождений блока ДО правки (Select-String с подсчётом совпадений) и ПОСЛЕ; число ПОСЛЕ равно ожидаемому, иначе стоп и цитата в отчёт.

### 9.3 Если понял, что в петле

2. Сменить метод (инструмент, файл, изоляция) ИЛИ выдать стоп-отчёт с якорем.
3. Поднять счётчик в соответствующем крах-скиле; 3+ одной подписи — вынести пользователю.
