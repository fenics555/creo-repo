# ШАБЛОН ИНСТРУМЕНТА ДОМА (обязательный состав) — V1, 25.09.2026

Закон дома (MANIFEST §19, три руки) + требования хозяина 25.09.2026. Инструмент, родившийся без
любого из пунктов ниже, = **долг**, а не готовый инструмент.

## ОБЯЗАТЕЛЬНО у каждого нового инструмента
1. **Своё окно** (tkinter, дизайн Давыдовки) — самостоятельный пуск, работает без агента.
2. **Свой лог** — `D:\AI\log\<имя>\<имя>.log`; каждая операция одной строкой (дата · что · сколько).
3. **Запись времени работы** — сколько шла операция: в окне после неё («готово: N за X с») и в логе.
4. **README.md** (как пользоваться) **+ кнопка «README» на панели**, которая выводит этот текст прямо в окно.
5. **Настройки** — своим файлом `settings\<имя>_settings.json` (папка `settings\` РЯДОМ с инструментом, не в `data\`);
   переживают перезапуск окна, не дублируются в коде; **версионируются** (`settings_version` + цепочка миграций),
   старые файлы уезжают в `settings\backup_settings\`.
6. **Кнопки послойно:**
   - **слой 1 — настройки**: папка, пороги, галочки, «Настройки…», «README»;
   - **слой 2 — рабочие кнопки**: «Сканировать», «Выгрузить», «Сравнить версии» и т. п.
7. **Версия в шапке** — `V1`, `V2`, `V3`, `V4` … в ТРЁХ местах: заголовок окна, первая строка README,
   шапка кода. Чтобы человек сразу отличал старое у него или новое.
8. **Три руки** (MANIFEST §19): библиотека + CLI + окно (+ блок визарда под щитом). Одна библиотека,
   один лок, один лог, один отчёт. Одна рука = долг до добора остальных.

## Наследие дома (тоже обязательно)
- Своя папка `D:\AI\tools\agent\<имя>\`: движок + `.bat` + `README.md` + подпапки `db\` (данные) и `settings\` (настройки).

## КАНОН САМОДОСТАТОЧНОГО ИНСТРУМЕНТА (Волна 0 плана, 09.10.2026 — эталон `cmnm_scan`)

Одно тело правды о составе папки. Инструмент = папка, которая переживает копирование на другой ПК.
Полный разбор и волны — `ПРОЕКТ_ОБНОВЛЕНИЕ_АГЕНТА\ПЛАН_архитектура_инструментов_2026-10-09.md`.

```
tools\agent\<tool>\
   tool.json            ← манифест: schema, id, class, engine, gui, settings, db,
                           commands, inherits (какие ОБЩИЕ настройки берёт)
   <tool>.py            ← ДВИЖОК (CLI), код возврата 0/1/2
   gui.py               ← ОКНО на ui_common
   <tool>.bat / _gui.bat← входы: окно и CLI
   settings\settings.json      ← ЛОКАЛЬНЫЕ настройки (schema, типы) + backup_settings\
   db\<tool>.db         ← СВОЯ база, пишет только этот инструмент
   README.md
   log\                 ← по умолчанию внутри папки (путь из настроек, не из кода)
```

**Пять законов канона:**
1. Нет папки — нет инструмента.
2. **Ни одного абсолютного пути в коде** (`D:\`, `Z:\`) — только `__file__`, настройки, поиск.
3. **Пишет только в свою `db\`**; общую БД агента **читает, не пишет**.
4. **Настройки автономны:** иерархия `default (tool.json) → общий (data\shared.json, только через
   `inherits`) → локальный (settings\settings.json)`. Локальный побеждает. Без общего конфига
   инструмент работает на default + своём.
5. **Живой прогон вне агента и после переноса обязателен** — `python dev\portable_check.py <папка>`
   даёт вердикт ПЕРЕНОСИТ / НЕ ПЕРЕНОСИТ.

**База (одно направление данных):** источник правды — локальная `<tool>\db\`; общая `agent.sqlite`
= производный свод (пишет агрегатор из локальных, пересобираем; инструменты только читают).
Зоны общей: свод (`models/files/bom/fts`) и мозг агента (`chat/history/journal`).

**Приёмка инструмента:** `py_compile` + `dev\portable_check.py` → ПЕРЕНОСИТ + `win_check` (окно) +
строка в `PROGRAM_REGISTRY.md`. Инструмент без `portable_check` ПЕРЕНОСИТ = долг, не готов.

- Логи — `D:\AI\log\<имя>\`; временное — в свою урну; отчёты — `D:\AI\log\reports\`.
- Свои таблицы в базах — с префиксом; чужое — только чтение.
- **Новое — самостоятельный инструмент со СВОЕЙ базой** (решение хозяина 25.09.2026); старое не смешивать.
- **Самостоятельность/переносимость:** по возможности автономный — чтобы инструмент легко перенести на
  другую машину (свои файлы и своя база рядом, минимум внешних зависимостей, без привязки к чужим каталогам).
- Перед записью — копия; пишущие режимы отделены флагом (`--apply`).
- **Бэкапы с retention (обязательно):** любые копии (базы, настроек, снимки кода) хранятся **окном последних N**,
  а не бесконечно; при создании новой копии старая сверх окна удаляется; глубину задавать константой/настройкой
  (пример: `engine.BACKUP_KEEP` = 3 для `db\backup\`; 5 для `settings\backup_settings\`).
  Грабля 30.09.2026: `db\backup\` без ротации дорос до **2 ГБ** — папка раздулась, чистка освободила ~1.7 ГБ.
- **Автообновление (если инструмент живёт у внешних пользователей)** — через репозиторий:
  *   **Версия — РОВНО ОДИН источник.** Одна константа (`APP_VERSION` в коде окна); движок и все проверки
      читают её, а не держат копию. Двойник (`engine.VERSION = "V31"` рядом с `APP_VERSION = "V32"`) = вечное
      «есть обновление»: шапка V32, а движок считает себя V31 (см. `crash\SKILL_crash_update-version-mismatch.md`).
  *   манифест `version.json` (версия + SHA256 файлов; хеш — по **нормализованному** содержимому `\r\n`→`\n`,
      иначе локаль CRLF и репозиторий LF не сойдутся);
  *   генератор `make_version_json.py` — запускать перед каждым коммитом; версию он берёт из `APP_VERSION`
      (тогда шапка и манифест не разъедутся);
  *   **и манифест, и файлы тянуть через GitHub API** (`Accept: application/vnd.github.raw`) — он **всегда свежий**;
      `raw.githubusercontent.com` только резерв (CDN кэширует надолго, cache-busting НЕ помогает). Манифест по raw —
      отдельная грабля: удалённая версия «залипает», а скачивание упирается в несовпадение SHA;
  *   установка = скачать → сверить SHA → снимок кода в `settings\backup_update\<дата>\` → заменить →
      лишние файлы кода (нет в манифесте) убрать в `…\obsolete\`; снимки — retention 3;
      при несовпадении SHA снимок удаляется (ничего не заменено — снимок не нужен);
  *   **тест установки — только на КОПИИ инструмента**, не на живой (см. `crash\crash_update-test-self-overwrite.md`).
  *   **приёмка обновления — живой проверкой:** `check_updates()` даёт `local == remote` и `available=False`
      (баннер «есть обновление» гаснет); после пуша манифеста дать CDN/API ~минуту и свериться, а не «на глаз».
- Приёмка: `py_compile` + самопроверка окна + `skills_check`/`culture_check` чисто.

## АВТОНОМНОСТЬ ИНСТРУМЕНТА (правило 02.10.2026, вынесено из пробы с `creo_pdf`)
1. **Ни одного зашитого пути в коде.** Пути живут только в файле настроек `settings\<имя>_settings.json`.
2. **Поиск внешних программ — по ПРИЗНАКУ, а не по имени папки.** Пример (Creo): человек называет
   `D:\PTC\CREO12`, программа внутри создаёт `Creo 12.4.2.0\Parametric\bin\parametric.exe`.
   Искать надо `Parametric\bin\parametric.exe` **рекурсивно вглубь**, а не `CREO*`/`Creo *`.
   Рекурсия по всему диску запрещена (минуты) — корень выбирается узким, глубина ограничена.
   **Самописные батники владельца (CREO-START и подобные) НЕ являются источником истины** —
   они есть только на его машине; алгоритм поиска обязан работать без них.
3. **Логи и рабочие файлы — от места нахождения `.bat`**, а не от каталога разработки.
4. **Отсутствие необязательной базы/файла — не поломка:** инструмент печатает об этом строкой и работает дальше.
5. **README перечисляет всё стороннее:** что обязательно, что необязательно, где ищется, как указать руками.
6. **Проверка автономности — переносом папки** на другой диск и запуском оттуда, а не рассуждением:
   скопировал → запустил → смотрел вывод, а не «должно работать».
7. Окно инструмента обязано уметь показать, что оно нашло: кнопка «Пути» / `--show`.
