## СТАТУС: ЗАВЕРШЕНО (ЭТАП 2 + НОВЫЕ ПРАВИЛА)

## КОНЦЕПЦИЯ
Переход от \"текстового\" редактирования к \"структурному\" (AST-based). Вместо того чтобы искать строку текста (которая может дублироваться или быть частью другого слова), агент должен оперировать **узлами дерева синтаксиса** (nodes).

Это обеспечивает \"хирургическую точность\" при внесении изменений и гарантирует, что правка не нарушит синтаксис программы.

## ОСНОВНЫЕ ПОНЯТИЯ

1. **AST (Abstract Syntax Tree)**: Дерево, представляющее иерархию элементов кода (файл $\\rightarrow$ класс $\\rightarrow$ метод $\\rightarrow$ выражение).
2. **Node (Узел)**: Элемент дерева. Каждый узел имеет:
   - `type`: Тип (например, `function_definition`, `identifier`, `if_statement`).
   - `range`: Точные границы (начальная и конечная строки/колонки).
   - `children`: Вложенные узлы.
3. **Query (Запрос)**: Специальный язык паттернов для поиска узлов в дереве. 
   - Пример: `(function_definition name: (identifier) @func_name)` — находит все определения функций и присваивает имя функции метке `@func_name`.

## ИНСТРУМЕНТАРИЙ: TREE-SITTER
Для высокоточного парсинга рекомендуется использовать **Tree-sitter**, такing как он обладает ключевыми преимуществами:
- **Fast (Быстрота)**: Позволяет парсить код почти мгновенно, даже при каждом нажатии клавиши.
- **Robust (Надежность)**: Способен строить дерево даже при наличии синтаксических ошибок в коде.
- **Incremental (Инкрементальность)**: Эффективно обновляет дерево только для измененных частей файла, а не перестраивает его целиком.

## АЛГОРИТМ \"ХИРУРГИЧЕСКОЙ ПРАВКИ\"

При необходимости изменить код, используй следующий протокол:

1. **Identify (Идентификация)**: 
   - Не ищи текст. Ищи **структурный узел**.
   - Определи тип узла, который нужно изменить (например, \"мне нужно изменить тело функции `calculate_total`\").
2. **Locate (Локализация границ)**:
   - Получи точные границы (`start_line`, `end_line`) целевого узла.
   - **ВАЖНО**: Всегда проверяй, что границы захватывают весь нужный блок (включая отступы или декораторы, если это необходимо).
3. **Verify (Верификация контекста)**:
   - Проверь \"соседей\" узла. Не находится ли твой целевой узел внутри другого узла, который ты не планировал менять?
4. **Apply (Применение)**:
   - Используй `editor` для замены именно этого диапазона.
   - Никогда не используй \"поиск и замену текста\" для структурных изменений.

## ПРАВИЛА ПРИМЕНЕНИЯ ДЛЯ АГЕНТА
- **Приоритет AST над текстом**: Если есть возможность использовать инструмент парсинга (например, `tree-sitter` или `grep-ast`), всегда выбирай его.
- **Защита от \"ложных срабатываний\"**: Если ты ищешь переменную `x`, убедись, что это узел типа `identifier`, а не часть слова `example`.
- **Контроль границ**: Перед отправкой правки, мысленно (или через `read_files`) проверь, не \"отрезал\" ли ты лишнюю скобку или не захватил ли лишнюю строку.
