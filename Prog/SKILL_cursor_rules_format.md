## СТАТУС: ЗАВЕРШЕНО (ЭТАП 1)

## КОНЦЕПЦИЯ
Стандарт оформления правил для редактора Cursor с использованием формата `.mdc`. Основная цель — обеспечить ИИ-агенту четкие, контекстно-зависимые инструкции, которые легко интерпретируются.

## ФОРМАТ (.mdc)
Каждое правило должно иметь структуру:

1. **Frontmatter (Метаданные)**:
   - `description`: Краткое описание того, когда применять правило.
   - `globs`: Шаблоны путей файлов (например, `**/*.ts`), к которым применяется правило.
   - `alwaysApply`: Булево значение (true/false) — применять ли правило всегда или только по совпадению `globs`.

2. **Role Definition (Определение роли)**:
   - Четкое описание того, кем должен быть агент (например, "You are a senior full-stack developer").

3. **Structured Content (Структурированный контент)**:
   - Разделение на логические блоки (Coding Standards, Architecture, Testing и т.д.).
   - Использование списков для правил.

## ПАТТЕРН "WHY" (Обоснование)
Критически важный элемент для повышения качества рассуждений (reasoning) агента. Каждое правило должно сопровождаться объяснением:
- **Правило**: `[Действие]`
- **Обоснование**: `> WHY: [Причина]`

**Пример:**
- `Use strict TypeScript. Never use any.`
  `> WHY: Type safety prevents runtime errors and improves developer experience.`

## ПРАВИЛА ПРИМЕНЕНИЯ ДЛЯ АГЕНТА
- При создании новых правил для проекта всегда придерживайся этого формата.
- Если правило не содержит `WHY`, оно считается неполным и требует дополнения.
- Используй `globs` максимально точно, чтобы не перегружать контекст лишними правилами.
