# БАЗА ЗНАНИЙ ПО ОШИБКАМ (Creo / CREOSON / агент)

Пользоваться: искать по фрагменту текста ошибки. Все входы с пометкой
«проверено» подтверждены тестами или повторением; непроверенное лечение
помечать «гипотеза» и не выдавать за факт.

## 1. CREOSON (порт 8080)

### 1.1 file:rename → «A Pro/TOOLKIT error has occurred: General Error»
Причина: file:rename не работает на асинхронном соединении CREOSON.
Лечение (проверено 09-01, creoson_full_test ПРОЙДЕН): file:rename не
вызывать вовсе. Копия: file:backup с target_dir → переименовать бэкап
средствами ОС в нужное имя → file:open копии. Финальный rename:
file:erase, затем rename ОС-файла.

### 1.2 file:backup → «No 'target_dir' parameter given»
Причина: вызов без target_dir.
Лечение: передавать и dirname, и target_dir всегда.

### 1.3 file:open → «Could not open file '…' in directory …»
Причина: файла нет в текущей рабочей папке (бэкап/rename не выполнен,
или папка другая; бэкап ложится с суффиксом версии .1).
Лечение: проверить creo:pwd, сделать creo:cd, убедиться, что файл
фактически создан (rename бэкапа ОС-ью), затем открывать.

### 1.4 parameter:list → «Error: Invalid File Name»
Причина: имя без расширения («CREOSON_TESTS-01» вместо
«creoson_tests-01.asm»).
Лечение: имя файла всегда с расширением .asm/.prt/.drw.

### 1.5 «File '…' was not open»
Причина: rename/relations_set/save вызваны на модели, не открытой в сессии.
Лечение: сначала file:open (display:false допустимо), потом операция.

### 1.6 CREOSON молчит (порт 8080 недоступен)
Лечение: ctl.py up — поднимает только недостающее; ctl.py status;
сторож ctl.py --watch. Лог старта: D:\AI\tools\startup.log.

## 2. Creo / CreoJS (переименование, семейства, копия сборки)

### 2.1 Схема «переименовать в сессии → сохранить → вернуть имена» портит оригинал
Причина: Rename в CreoJS переименовывает и файл на диске; возврат имён
уносит созданную копию обратно в файлы оригинала.
Лечение: копия сборки — только через временную папку: Backup состава →
закрытие окон → выгрузка из сессии → rename во временной папке → перенос
готовых файлов в рабочую папку сервером → возврат сессии.

### 2.2 «В сессии Creo остались модели оригинала» / подмена моделей
Причина: пока модель показана в окне, Creo не выгружает её;
GetModelFromFileName вернёт оригинал вместо файла временной папки.
Лечение: сначала закрыть все окна (текущее — очистить), затем
EraseUndisplayedModels ОТДЕЛЬНЫМ вызовом. ProMdlErase на показанной
модели → XToolkitInUse; Erase активной модели с продолжением работы в
том же вызове роняет Creo (документация требует вернуть управление сразу).

### 2.3 Экземпляр семейства не открывается составным именем
Симптом: RetrieveModel падает на ИМЯ<ПРОМЕЖУТОЧНЫЙ>.prt.
Причина: файл на диске называется по верхнему generic.
Лечение: пробовать оба имени (с промежуточным и с верхним generic); к
верхнему подниматься цепочкой GetImmediateGenericInfo — GetTopGenericInfo
может молчать, пока immediate generic не загружен в сессию.

### 2.4 Два исполнения с одинаковым именем не открываются одновременно
Лечение: при копировании семейства все экземпляры копии получают новые
имена; оригиналы на время операции переименовываются во временные t_…
и восстанавливаются в finally.

### 2.5 Объект модели без методов pfcSolid (Creo 13.4.1.0)
Симптом: CurrentModel/GetActiveModel возвращает базовый прокси без
GetMassProperty/ListRows/Rename и т.п.
Лечение: повторно получить тот же объект через
session.GetModelFromFileName(имя) — возвращается наиболее производный прокси.

### 2.6 Общее наименование (CommonName) не записывается
Причина: модель под Windchill, IsCommonNameModifiable() === false.
Лечение: не валить операцию — собрать в commonNameErrors и продолжать.

### 2.7 XToolkitNotFound в ListDependencies / GetSkeleton
Не ошибка: у модели нет зависимостей / скелетона. При сканировании игнорировать.

### 2.8 Чертёж не переименовался вместе с моделью
Причина: чертёж не был загружен в сессию к моменту Rename — ссылка не переключилась.
Лечение: чертежи загружать до переименования модели; переименовывать после
модели; сохранять снизу вверх, чертежи последними.

## 2.9 Дерево таблицы семейств НЕ доступно через API без загрузки экземпляров
Симптом: переименование вложенных семейств требует загрузить сотни моделей.
Причина: pfcFamily отдаёт generic и список строк; тип строки (экземпляр /
вложенная таблица) известен только после загрузки в сессию.
Правило: для стандартных деталей не строить вложенные таблицы семейств и не
копировать стандарт с новыми именами; дерево показывает только штатная
функция Creo «Проверить экземпляры таблицы семейств».
Источник: Давыдовка (автор rename-инструмента), cccp3d.ru topic 207294, 02.09.2026.
2.10 Копия: открытие исходника регенерирует и поднимает версию в сессии
Симптом: «Создать копию» → «файл один и тот же»; в папке .1, в сессии .2.
Причина: открытие пересчитывает модель; сессия держит новую версию.
Лечение: сохранять модель ДО копирования; не сохранять программно без
пользователя; сверять версии сессии и папки перед rename.
2.11 Чтение состава длится минуты — подгружаются все экземпляры; это норма,
не зависание. Нужны логи с метками времени.
2.12 «Обработок: 3» = mfg + заготовка + наладка; «1 из 1» — только про mfg.
Не принимать за рассинхрон счётчиков.

3. Агент / Python

### 3.1 AttributeError: 'list' object has no attribute 'startswith' (learn_tools)
Причина: creo_get_relations вернул список, код ждал строку.
Лечение: нормализовать результат инструмента (list → "\n".join) до
строковых проверок. Проверено: diag_learn после правки — PASS.

### 3.2 Ollama 500 на /api/chat
Лечение: автоматический повтор один раз через 2 с (уже в run_loop).
Если повторяется — проверить порт 11434, ctl.py up.

### 3.3 Ответ модели вне формата
Лечение: invalid-парсер шлёт служебную подсказку один раз; второй invalid
отдаётся как есть. Ручное вмешательство не требуется.

### 3.4 Зацикливание одного инструмента
Лечение: сигнатура (имя+аргументы) предыдущего вызова останавливает цикл,
ответом становится последний результат (уже в run_loop).

## 4. Когда причина не ясна
1. creo_open_errors — ошибки открытия модели.
2. trail_analyze / trail_problems / trail_trend — болезни трейлов
(медленные открытия, перевод afx_options.txt и т.п.).
3. creo_read_trail — хвост трейла: ошибки, таймауты.

## 5. Как добавлять входы
После вылеченной ошибки дописать подраздел: симптом (точный текст
ошибки) / причина / лечение / дата и подтверждение. Непроверенное
лечение помечать «гипотеза».
