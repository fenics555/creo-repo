# РУТИНА ДОМА: ВЫВОД И ОБНОВЛЕНИЕ PDF ЧЕРТЕЖЕЙ CREO

## 1. ПРАВИЛО
Рядом с чертежом `<имя>.drw[.N]` должен лежать **`<имя>.pdf` той же папки** и быть **не старше** чертежа.
Нет PDF или PDF старее — обновить. Обход — по **всем подпапкам** выбранной папки.
Масштаб дома: в базе агента **24 607 пар** чертёж↔PDF, из них **8 687 «устарел»**.

## 2. ТРИ УСЛОВИЯ PDF (каждое проверено отказом)
| Условие | Ошибка при нарушении |
|---|---|
| модель — **чертёж**, не деталь | `pfcExceptions$XToolkitInvalidType` |
| рабочая папка Creo = папка чертежа | деталь чертежа не находится |
| **`Model.Display()`** до экспорта | `pfcExceptions$XToolkitNotDisplayed` |

**Сборочный чертёж** (`X.drw` при наличии `X.asm`) по имени не открывается — `XToolkitNotFound`;
лечение: **сначала поднять сборку** `RetrieveModel(MDL_ASSEMBLY, "X")`, затем чертёж (проверено: 0 ошибок).
`ModelDescriptor_CreateFromFileName` тут НЕ помогает (`XToolkitNotFound` / `XInvalidFileName` /
`XUnknownModelExtension` — версионный `.drw.1` не принимается).

## 4. ИНСТРУМЕНТ
`D:\AI\tools\agent\creo_pdf\` — `creo_pdf_gui.bat` (окно, «дизайн 2») и движок `creo_pdf.bat` (прямой JLINK, **без CREOSON**):
```
creo_pdf.bat scan   <папка>              # отчёт: где PDF нет / PDF старше (Creo НЕ нужен)
creo_pdf.bat export <папка> [лимит]      # создать недостающие/устаревшие (лимит 0 = без ограничения)
creo_pdf.bat pdf    <папка> <имя> [out]  # один чертёж
creo_pdf.bat config-scan | config-find | config-read [файл] | config-load <файл>
creo_pdf.bat creo-find | creo-start [config.pro] [--dry]
```
Внутри: `ChangeDirectory(папка)` → `ModelDescriptor_Create(MDL_DRAWING, имя)` → **`Display()`** →
`Export(<имя>.pdf, PDFExportInstructions_Create())` → **чертёж убирается из сессии** (`Model.Erase()`),
рабочая папка Creo возвращается назад. Просмотрщик PDF — по галочке «открывать PDF» (`PDFOPT_LAUNCH_VIEWER`).
В агенте: инструменты `creo_pdf_scan` (чтение) и `creo_pdf_export` (под щитом).

## 4а. ПАПКА ВЫВОДА PDF (V2, 02.10.2026) — PDF не обязательно рядом с чертежом
Три режима, поле «Папка PDF» + галочка «и копия рядом с чертежом» в окне:
| Поле/галочка | Результат |
|---|---|
| поле пустое | PDF рядом с чертежом (прежнее поведение) |
| поле задано | PDF в отдельной папке, структура подпапок **зеркалится** |
| поле + галочка | оба места: в папке вывода И копия рядом с чертежом |
CLI: `scan <папка> [--out <папка>] [--dup] [--limit N]` · `export <папка> [лимит] [--out <папка>] [--dup]`.
- **Зеркало подпапок обязательно** (`outDirFor`): без него одноимённые чертежи из разных веток схлопываются в один PDF.
- **Скан при заданной папке вывода смотрит ТУДА**: обход папки вывода идёт ОТДЕЛЬНЫМ проходом
  (`walkTree` по ней) — иначе, лежащую вне сканируемой папки, она не увидит и всё пометит «НЕТ PDF».
  При `--dup` дополнительно проверяется копия рядом: «в папке свежий, но рядом нет» → тоже в работу.
- **Проверка «директория пустая»:** пустая строка — не ошибка (это режим «рядом»); `--out` без значения —
  `ERR: --out без значения`; папку не создать — `ERR: папка назначения не создаётся`, прогон не начинается.
  В окне `_out_dir()` возвращает `None` (пусто), `False` (ошибка с сообщением) или путь.
- Настройки инструмента — `settings\creo_pdf_settings.json` (поля `pdf_out`, `dup_near`,
  `settings_version`), старый `gui_settings.json` мигрируется, бэкапы с ротацией 5.
- Приёмка 02.10.2026 (копия полигонного `калибр` в урну, живой Creo): экспорт `--out --dup` →
  `PDF OK 23305 б` + `+ копия рядом с чертежом`, 0 ошибок; повторный скан → `PDF в порядке: 1`;
  сдвиг mtime PDF назад → `УСТАРЕЛ … устарели: 1`. Проба настроек (14 проверок) —
  `D:\AI\log\urn\cline\TEST_creo_pdf_settings.py`.

## 4е. ПОЧЕМУ «НЕТ PDF», КОГДА ФАЙЛЫ ЕСТЬ (02.10.2026) — РАЗБОР ПО ФАКТАМ
Владелец заметил противоречие: в отчёте «НЕТ PDF … X.pdf», а файл `.drw` рядом лежит. Разбор
открытых байтов `.drw` показал настоящую причину — **имя чертежа ≠ имени модели внутри него**:
| Чертёж | Что записано внутри (ссылка на модель) | PDF рядом | Модель рядом |
|---|---|---|---|
| `c5-028_102-01.drw.1` | `C5-028_102.PRT` | нет | `c5-028_102.prt.1` **есть** |
| `hst-116r-01.drw.1` | `HST-116L-01.PRT` | нет | — |
| `sdfa.drw.1` | `PRUZHINA_ESKD.PRT` | нет | — |
| `уисвгд-401-040-00.drw.1` | `УИСВГД-401-040-00.PRT` | **есть** (30 155 б) | есть |
Вывод: чертёж переименовали (или перенесли) вопреки внутренней ссылке — Creo ищет модель по
имени из чертежа и не находит. **Это не «PDF без модели» и не сирота** — кнопка «Искать ПДФ без
модели» ищет обратное (PDF без `.drw/.prt/.asm` рядом), поэтому эти случаи она не ловит.
**Теперь движок читает `.drw` и печатает правду** (`modelsInside()` + `explainMismatch()`):
```
ПРИЧИНА: чертёж называется c5-028_102-01, а ссылается на модель(и): c5-028_102
рядом в этой папке ЕСТЬ: c5-028_102 → чертёж, вероятно, переименован;
откройте модель c5-028_102 в Creo и переименуйте чертёж под неё.
```
**Два технических факта, найденных пробой:**
- имена в `.drw` лежат в **UTF-8** (`УИСВГД-401-040-00.PRT`); при windows-1251 получается мусор
  `РЈРИР…`, при ISO-8859-1 имя обрезается — и диагностика врёт дважды;
- чертёж может ссылаться на **несколько** моделей — берём все уникальные, а не «последнее найденное».
Приёмка на стенде не сломана: `сделано 1, сирот 1, ошибок 0` после правки.

   `model=������.drw` вместо `калибр.drw`; кириллица в bat ломала cmd — bat переведён на ASCII.
**Правила для этого класса инструментов:**
- **модель — полным путём** (голое имя даёт `XToolkitNotFound`, полный путь движок разбирает сам);
- **bat — 100 % ASCII**, кириллица в bat ломает разбор `cmd`;
- **скобки с `exit /b` внутри bat** дают пустой вывод и код 1 — ветки ошибок через `goto`;
- **`javac -encoding UTF-8`** обязателен, если в исходнике есть не-ASCII.

## 6в. КАК ЧИТАТЬ ЛОГИ ИНСТРУМЕНТА (замер 02.10.2026 по `D:\AI\log\creo_pdf`)
Логи инструмента **накопительные (append), а не по одному прогону** — это ломает чтение цифр.
- `runs\run_<дата>_<время>.txt` содержит **все** прогоны дня: живой файл `run_2026-09-23_1538.txt`
  = 26 669 строк и **три** сводных `ИТОГО` (строки 4 224 / 10 659 / 26 666). Считать «ошибки прогона»
  по всему файлу нельзя — только по диапазону строк между двумя `ИТОГО`.
- `history_last_run_log.txt` **дублирует** последний `runs\run_*.txt` байт в байт
  (оба 3 827 809 б, 23.09.2026 15:38:06) — считать дважды нельзя.
- В шапке каждого прогона печатается **полный README** (~20 КБ на файл, 12 прогонов ≈ 240 КБ мусора);
  полезную часть лога начинать искать после строки `====`.
**Считать отказы по КЛАССУ подписи, а не по числу строк.** Разбор 2 748 строк `ОШИБКА` за 23.09:
| Подпись | Всего | В финальном прогоне |
|---|---|---|
| `XToolkitCommError` | 2 643 | 0 |
| `XUnknownModelExtension` | 104 | 81 |

## 6в. ПРАВИЛО ПРОВЕРКИ ДО «УСТАРЕЛ» (V2, 02.10.2026)
Отвечать на «PDF устарел?» надо **там, где PDF реально лежит**, а не всегда рядом с чертежом:
- поле «Папка PDF» пустое → сравнивать PDF рядом с чертежом (прежнее правило);
- поле задано → сравнивать PDF **в папке вывода** (зеркало подпапок);
- поле задано + галочка «и копия рядом» → обе проверки: и в папке вывода, и копию рядом.
Грабля, найденная пробой: папка вывода лежит **вне** сканируемой папки, поэтому обход чертежей её
не видит. Если скан смотрит только дерево чертежей, он пометит «НЕТ PDF» всё, что уже выведено.
Отсюда правило: **скан и экспорт обязаны смотреть в одну и ту же папку** — иначе приёмка «повторный скан чист»
невозможна в принципе.

9. **Пробелы в bat — источник тихих поломок** (V3, 02.10.2026, живая проба):
   - `call set %%L` вместо `call %%L` даёт `set set NAME=…` — переменные пустые, и ошибка выглядит
     как «не нашёл Creo», хотя путь есть;
   - предупреждения нельзя отдавать в bat через `for /f`: bat выполнит их как команды и упадёт
     на пробелах (`'Common' is not recognized`). Отдельный режим `--warnings` и обычный вызов;
   - `--out`-подобные флаги не должны приниматься за путь: разбор аргументов по признаку `--`.
10. **Путь с пробелами через `--set` обрезается без кавычек** (`cmd /c`): `--set "k=D:\A B\Parametric"`.
    Плюс защита в коде: перенос строки в значении = отказ с понятным сообщением (иначе испорченный JSON).
11. **`null` вместо папки = `XToolkitCantWrite` (регресс V2, найден живым прогоном 02.10.2026).**
    В режиме «рядом с чертежом» (`export` без `--out`) движку передавался `out = null`, путь
    получался `null\имя.pdf`. Одиночный режим `pdf` при этом РАБОТАЛ — дефект виден только в цикле.
    Правило: режим по умолчанию обязан подставлять настоящую папку, а не «отсутствие аргумента».
12. **Несколько команд в одном `run_commands` выполняются ПАРАЛЛЕЛЬНО** (02.10.2026): связанные
    прогоны «экспорт → скан» в одной пачке дали ложное расхождение (`сделано 2` при `PDF в порядке: 0`).
    Зависимые шаги — строго по одному вызову, каждый со своим чтением вывода.
