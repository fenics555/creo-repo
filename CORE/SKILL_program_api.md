# API-СЛОЙ ПОДПРОГРАММЫ ДОМА (управление без вспомогательных скриптов)

> Живой образец (боевой): `D:\AI\tools\agent\plm_reader\plm_api.py` + `plm_api_adapter.py` (V221, 21 команда).
> Эталон-первоисточник: `D:\AI\AGENT_SETTINGS\checks\stand_gui_v2.py` (методы `_api_*`, строки ~2546–2760).
> Дорожная карта и эстафета темы: `D:\AI\ЭСТАФЕТЫ\PLAN_AGENT_API.md`, `ESTAFETA_AGENT_API.md`.

## СУТЬ (одной фразой)

**ИИ (или внешний вызов) кладёт JSON-команду в `api\in\<имя>.json` — программа исполняет её СВОИМ методом
(как кнопку) и кладёт ответ в `api\out\<имя>.json`. Никаких внешних скриптов-обёрток.**
Единственный исполнитель — сама программа (её окно/движок); API — лишь ещё один её «орган управления».

## КОГДА ПРИМЕНЯТЬ

- Нужно управлять подпрограммой (`D:\AI\tools\agent\<имя>\`) **без** агента-обёртки и **без** HTTP-портов.
- ИИ должен читать/менять **настройки, базу, логи, состояние окна** и запускать **операции** программы.
- Нужен **самодокументируемый** канал: команда `schema` отдаёт список всех команд с параметрами.

## КОГДА НЕ ПРИМЕНЯТЬ

- Программа — «тело агента» (`agent.py`, `loop.py`, `http_handlers.py`) → это не класс Р, API не нужен.
- Разовая правка одного файла → хватит `editor`/скрипта, API избыточен.
- Уже есть рабочий канал (агент-обёртка `*_tools.py` через `importlib`; HTTP-витрина порт 8765) —
  API **дополняет**, не заменяет (`ESTAFETA_AGENT_API.md` §4.8).

## АРХИТЕКТУРА (что где лежит)

| Слой | Файл | Роль |
|---|---|---|
| **Каркас** | `<программа>_api.py` (напр. `plm_api.py`, ~9 КБ) | транспорт `in\|out`, поток, реестр команд, `schema`, журнал |
| **Адаптер** | `<программа>_api_adapter.py` (~тонкий) | регистрирует команды программы; зовёт ЕЁ методы |
| **Транспорт** | `<программа>\api\in\` (\*.json), `api\out\` (\*.json), `api\out\_api_journal.log` | файловый обмен |
| **Окно** | вкладка «API» в GUI | живой журнал команд/ответов (кнопки «Обновить», «Открыть папку») |
| **Запуск** | в `run_gui()` перед `mainloop` | `_API_GLOBAL.server = build_api(); server.start()` (поток-демон) |

## 🔴 ЗАКОН ДОМА: каркас — СВОЙ у КАЖДОЙ программы

**НЕ выносить общий каркас в единый модуль** (решение владельца 28.11.2026, `ESTAFETA_AGENT_API.md` §4.9).
Причина: перенос программы на другой ПК = копия её папки; общий модуль вне папки **потеряется**.
Дублирование ~9 КБ — **осознанная плата** за самодостаточность (`PROGRAM_REGISTRY.md` §Паспорт класса Р, п.1,7).
Каждая новая подпрограмма получает **свою** копию каркаса + тонкий адаптер под неё.

## ГРУППЫ КОМАНД (шаблон покрытия)

| Группа | Что | Примеры |
|---|---|---|
| **A. Жизнь** | состояние, версия | `ping`, `schema`, `status` |
| **B. Настройки** | чтение/запись реестра настроек | `settings_get/spec` (read), `settings_set/reset` (write, бэкап `.pre_`) |
| **C. База** | статистика, SELECT, обслуживание | `db_info/stats/tables/query/doctor` (read), `db_backup/repair` (write) |
| **D. Логи/окно** | журналы, снимок состояния | `log_list/log_tail`, `window_state` |
| **E. Операции** | запуск движка | `op_where/tree/changes/check` (read), `scan_start` (write, фоном) |

## БЕЗОПАСНОСТЬ (обязательные правила)

- **read** — свободно; **write** (`read=False`) — **только** с флагом `"apply": true` в JSON-команде.
- Настройки — **только** через реестр программы (напр. `plm_settings.SETTINGS_SPEC`), с **бэкапом** перед записью.
- База — **только** через модуль-владелец схемы (напр. `plm_database`); `db_query` — **только SELECT**.
- **`Z:` (шара) и UNC — только чтение.** Запись в сетевой путь запрещена (проверка `_is_writable`).
- Файлы Creo (`*.prt/.asm/.drw`) читает **только** штатный сканер (напр. `plm_scanner.py`), API их не парсит.
- API обёрнут в `try/except` — сбой API **не должен ронять окно** программы.

## ПЕРЕНОСИМОСТЬ (миграция на другой ПК)

- Все пути — **относительно файла** (`os.path.dirname(os.path.abspath(__file__))`) → `api\` рядом с программой.
- Жёсткий путь дома разрешён **только для лога**: приём `os.path.join('D:', os.sep, 'AI', 'log', '<имя>')`
  с **fallback** `os.path.join(HERE, 'log')`, если `D:\AI\log` нет (как в `engine.py`, `plm_reader.py`).
- Проверка автономности: `python -c "import tool_contract as t; print(t.problems(r'<папка>'))"` → **ошибок быть не должно**.
- `portable_check.py` для больших программ (с базой) может таймаутить 30 с — запускать **фоном** с логом.

## КРАСНЫЕ ЛИНИИ (грабли темы)

- 🔴 **НЕ оптимизировать** дубликаты каркасов в общий модуль (см. «ЗАКОН ДОМА» выше).
- 🔴 **Кольцевой импорт:** каркас НЕ должен импортировать адаптер; адаптер импортирует каркас (`from plm_api import AgentApi`).
- 🔴 **`importlib` под другим именем** ломает внутренние `import` модуля → папку программы класть в `sys.path`.
- 🔴 **Вложенный `cur.execute` на одном курсоре** обрывает цикл → материализовать `.fetchall()` ДО вложенных запросов.
- 🔴 **Проверка версии в пробе:** при подъёме `APP_VERSION` обновить пробу (иначе ложный провал `status`).
- 🔴 Окно **не запускать** для проверки API — проба гоняет `build_api().start()` в отрыве от GUI (быстро, без риска).
- 🔴 После правки каркаса/адаптера — пересобрать манифест: `python make_version_json.py "<notes>"` + `--verify`.

## ПОРЯДОК ПОДКЛЮЧЕНИЯ К НОВОЙ ПРОГРАММЕ (чек-лист)

1. Разведка: движок, окно, настройки, база программы (`tool.json`, README).
2. Скопировать проверенный каркас → `<программа>_api.py` в папку программы.
3. Написать `<программа>_api_adapter.py` — тонкий, команды A–E по её модулям.
4. Пробу в `D:\AI\PROBA` (не в боевой папке): `ping/schema/status/settings_get/...` — все OK.
5. Встроить запуск в окно (`run_gui`) + вкладку «API» (живой журнал).
6. Раздел «API» в README программы + `.gitignore` → `api/in/`, `api/out/`.
7. Релиз по чек-листу программы; для PLM — `AGENTS.md` §7 (APP_VERSION → манифест → тесты → адресный git).
