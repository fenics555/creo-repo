# СТРАТЕГИЯ РАЗВИТИЯ АГЕНТА И КБ (обновлено 23.09.2026)

## БЛИЗКИЕ ПЛАНЫ (дни)
- **Чесалка деталей и сборок** (`creo_comb`): режим `add` — добавить отсутствующие параметры
  (только имена; значения из эталона; `ТИП` = Деталь/Сборка по типу модели) и уравнения
  (обычные + пострегенерации), затем **регенерировать и сохранить**; копия `pre_` и отчёт.
  Набор параметров у детали и сборки один и тот же — различается только `ТИП`.
- **Ограничения параметров (варианты)**: читать ограничения из эталона, генерировать `.lst`
  (`ND_ParamDefArr_K01`) для `ТИП`, `ТИП2`, `ФОРМАТ`, `РОЛЬ_В_ЛИТЕЙНОЙ_СИСТЕМЕ` и включить
  `restricted_val_definition` в config.pro (с копией в БЕКАП). JLink умеет только ЧИТАТЬ ограничения.
- **Чертежи (DRW)**: найти способ добавлять настройки отображения (опции детализации) и тоже
  массово — проба `Model.Import`/`ConfigImportInstructions`, затем C-API `ProMdlDetailOptionSet`
  или UI-проход; после — регенерация и сохранение.
- **PDF-рутина — разобрать 52 ошибки** последнего прогона (диагностика сделана 23.09):
  1) чертёж-сирота (нет `.prt/.asm` с тем же именем) — Creo не откроет, PDF не сделать, это не глюк;
  2) `XToolkitCommError` — обрыв связи с Creo: рутина должна останавливаться с понятным сообщением;
  3) попытку открыть файл С ВЕРСИЕЙ (`X.drw.1`) Creo отвергает (`XUnknownModelExtension`) — убрать
     из списка диагностических вариантов; отчёт делить: сделано / сироты / связь / прочие ошибки.
- **Логи программ** — `creo_pdf` и `creo_export` перенести в `D:\AI\log\<имя>\`; паспорт класса Р
  и реестр программ (начато: `agent\dev\PROGRAM_REGISTRY.md`).
- **Z: аудит по `СПЕКА_CREO.md`**: механизм старта `CREO-START.bat` (кто что исполняет, куда пишет,
  где ошибки), разбор `config.pro`, структуры `Work` и копируемых трейлов → отчёт
  `START-STD\logs\AUDIT_CREO_<дата>.md`.
- **Битые настройки шаблонов в config.pro**: `template_mold_layout` (нет файла), `template_drawing`
  (`$PRO_DIRECTORY\ШАБЛОНЫ` — каталога нет), `template_boardpart` и `template_new_ecadasm`
  (опечатка `ШАБЛОНЫs`) — привести в порядок с копиями в БЕКАП.

## ДАЛЬНИЕ ПЛАНЫ (месяцы)
- **ПЛМ-лайт** (всё в базе агента, рядом с деталями — только Creo): карточка изделия
  (обозначение, наименование, ТИП, материал, масса, формат, путь, ЧТ, PDF), состав и «где применено»
  (обогащать `usage`, не дублировать), история изменений по снимкам (кто/когда — трейлы; что — параметры
  и уравнения до/после), быстрый скан по расписанию (инвентарь + хеши, только изменившиеся файлы).
- **Похожие детали** («колесо мопеда и мотоцикла»): ИИ + визор сам шерудит по PDF-чертежам и картинкам.
  Двойники по содержимому — уже есть (`dup_scan`, sha1).
- **Спецификации и ведомости**: XLSX из живого Creo уже работает (`spec_tools.spec_create_active`),
  состыковать с реестром ПЛМ, добавить ведомость состава (ГОСТ 2.106).
- **Флот машин**: телеметрия уже собирается (`fleet`, `logs`, `netdiag`) — сводить в отчёты,
  раздавать конфиги/шаблоны на все машины одной командой.
- **1С-мост** (активно): выгрузка → индекс → сверка по шифру/обозначению.
- **Web-карточки изделий** из Creo-параметров (витрина).

## САМЫЕ ДАЛЁКИЕ ПЛАНЫ (полгода+)
- Полный цикл без ручного труда: ПЛМ ↔ 1С ↔ Creo ↔ документы (чертёж, PDF, спецификация).
- Замена CREOSON целиком на JLink (перенос блоков: `creo_tools` 28 обращений, `diagnostic` 27,
  `copy_tools` 11, `pdf_tools` 7, `rename` 6, `spec` 3) — и удаление его из дома.
- Сравнение геометрии (TDO/Compare) — «что именно изменилось в форме», если понадобится.
- Ревизии и извещения об изменениях по ГОСТ 2.503 (отложено словом хозяина).

## ЧТО БЫ Я ХОТЕЛ )))
- Память агента — маленькая (0,5–1 ГБ) и быстрый старт. Сделано 23.09: **13,29 ГБ → 0,78 ГБ**,
  база знаний 6,38 ГБ → 0,19 ГБ (FTS5, без эмбеддингов и мусора).
- Одна задача — одна программа: батник/окно, свой лог в `D:\AI\log\<имя>\`, агент не тащит всё в себе.
- Конфиг и шаблоны — источник правды: читать из `config.pro`, ничего не хардкодить.
- Поменял настройки один раз — чесалка прогнала **все** модели, включая старые, без ручной правки.
- Сканеры — быстрые (как PDF: вся папка за секунды) и по расписанию, а не по кнопке.
- Ничего не удаляем: мусор — в `_trash`/`_trash_dup`/`БЕКАП`, решение — за человеком.
- Варианты (ограничения) параметров работают во всех моделях.
- Чужое не ломаем: чужие базы и чужие файлы — только чтение.
