# СПЕЦЫ, PLM, 1С
PLM/1С — ВНЕШНЯЯ база: агент не хранит её, только опрашивает инструментами one_c/plm.
plm_mine — мои изделия в PLM; plm_bom q=<сборка> — состав из PLM; plm_audit — сводка: изделий, без материала, без массы (цифры недели: 28885 / 19095).
spec_read path=<путь.xlsx> — чтение таблицы спецы; spec_tools собирает ГОСТ-разделы по настройке bom_sections
(Документация, Комплексы, Сборочные единицы, Детали, Стандартные изделия, Прочие, Материалы, Комплекты).
Проверка: one_c_status — жива ли 1С; пространство «🚀 Флот и служба».
Болезни: 1С недоступна = plm-инструменты отвечают ошибкой сети, это не дефект агента;
«нет MASS» = параметр не задан в модели, аудит подсказывает задать или исключить;
спеца старого формата = порядок разделов плавает, сверяй с bom_sections.

## 23.09.2026 — СВОИ ТАБЛИЦЫ PLM (важное, чтобы не снести чужое)
Модуль `agent\plm_tools.py` держит реестр **в своей базе** (`data\agent.sqlite`), а не в 1С/PLM.
Таблицы модуля — **с префиксом `plm_`** (закон дома: своё — с префиксом, чужое — только чтение):
`plm_items` (реестр изделий), `plm_bom` (состав), `plm_revisions` (ревизии), `plm_changes` (изменения).

**Что было (и почему это ловушка):** модуль держал таблицы без префикса (`items`, `bom`, `revisions`,
`changes`) и в `plm_mine` делал `DELETE FROM bom`. А `bom` в базе дома — **ЧУЖАЯ** таблица:
36 811 строк, схема `parent, child, qty` (без колонки `source`). Значит первый же запуск `plm_mine`
стёр бы чужой состав и сразу упал на вставке (`no column named source`).
Пустые таблицы модуля (`items`, `revisions`, `changes`) переведены в `plm_*` автоматически (`_migrate()`)
с проверкой колонок через `PRAGMA table_info` — чужие при этом не трогаются.
Проверено живьём после правки: `bom` = 36 811 (цела), `usage` = 2 400 (цела), `models` = 44 154,
наши `plm_*` созданы, `plm_audit` отвечает. Бэкап базы: `data\backup\2026-09-23_2006_pre_plm_schema_agent.sqlite`.

**Как пользоваться:** `plm_mine xml_dir=<папка>` — наполнить реестр (approval); `plm_item q=<обозн>`,
`plm_bom q=<сборка>`, `plm_where q=<деталь>`, `plm_audit` — чтение; `plm_lifecycle`, `plm_ii` — запись (approval).
