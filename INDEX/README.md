# INDEX — поиск по СМЫСЛУ по дому (эмбеддинги)

> **ВРЕМЕННОЕ расположение.** Перенесено из `AGENT_SETTINGS\think_probe` 13.10.2026.
> По плану переедет в `D:\AI\tools\agent` — когда он заработает (у него свой сканер).

## Что это
Семантический поиск по скиллам / правилам / карте / инструментам дома. Не «по словам», а **по смыслу**:
текст превращается в вектор (768 чисел, модель `nomic-embed-text-v2-moe`), и находится ближайший по смыслу.
Задача — чтобы модель **одним вызовом** находила нужный скилл, не угадывая имя файла.

## Файлы
| Файл | Что делает |
|---|---|
| `index_skills_v2.ps1` | строит/обновляет **БАЗУ** (инкремент: только изменённые файлы; версии `ver_<дата>`) |
| `find_skill.ps1` | **поиск**: `-Query "<текст>" [-Top 5] [-Full]` — пути кандидатов + оценка |
| `demo_embed_skill.ps1` | демо (показать, что такое эмбеддинги) |
| `index\` | **БАЗА**: `CURRENT.txt` (указатель версии) + `versions\ver_<дата>\` |
| `log\` | логи индексации |

## Как работать
```powershell
cd D:\AI\repo\INDEX

# 1) Построить/обновить базу (после правок скиллов/правил). Обычно секунды (инкремент).
powershell -NoProfile -ExecutionPolicy Bypass -File .\index_skills_v2.ps1
#   -Full           — полная пересборка
#   -KeepVersions N — сколько версий держать (по умолчанию 3)

# 2) Найти скилл по смыслу задачи
powershell -NoProfile -ExecutionPolicy Bypass -File .\find_skill.ps1 -Query "сделать коммит по правилам дома" -Top 5
#   -Full — печатать ПОЛНЫЕ пути (для чтения через read_file)
```

## Ключевые правила
- Модель эмбеддингов обязана быть в Ollama: `nomic-embed-text-v2-moe:latest`.
- **Префиксы:** индексация — `search_document: `, поиск — `search_query: ` (уже зашиты в скрипты; без них качество рушится).
- В корпус идут: скиллы `repo\**`, `.clinerules`, `MANIFEST.md`, инструменты `tools\agent`, md-настройки. Шум (`repo\data\backup\`) исключён.
- База — **производная**: в гит не хранится (см. `..\.gitignore`), пересобирается из файлов дома.
