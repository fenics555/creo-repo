## ПОЧЕМУ ОТДЕЛЬНО
Окна в доме — **самостоятельный слой**, который до сих пор жил в соглашениях внутри
`Prog\SKILL_tool_template` и в шапках README программ. Отдельного скилла про окна в доме
**нет вообще** (проверено поиском по репо: `*окн*` — 0 файлов, `*gui*` — только логи Creo).
Значит каждое новое окно пишется заново, и ошибки повторяются.

## КРАТКО (главное из изучения)
1. **Каркас один и тот же везде**: `tk.Tk()` → `root.title(...)` (с версией V1/V2/V7) →
   `root.geometry("WxH")` (+ `minsize`) → `class App/Win` → `root.mainloop()` в `__main__`.
2. **Все окна — tkinter**, стандартная библиотека; внешних GUI-библиотек в доме нет.
3. **Дизайн-константы повторяются буквально**: `Consolas 9`, `bg="#f8f9fa"`, плашка состояния
   `bg="#fff1c7"`, рамка `LabelFrame` с ПРОБЕЛАМИ в тексте (« НАСТРОЙКИ »).
4. **Обязательные элементы**: кнопка **README** (читает `README.md` в лог окна), кнопка **СТОП**
   (где есть процесс), статусная плашка, поле лога (`tk.Text`), окно запускается `*_gui.bat`.
5. **Потоки**: работа — в `threading.Thread(daemon=True)`, обратно в GUI — только
   `root.after(0, …)`; вывод процесса качается через `queue` (`pump`).
6. **Размеры окна** — от 820×520 (`copy`) до 1560×820 (`plm_reader`); у больших есть `minsize`.
7. **Проверки уже есть**: `dev\stop_button_check.py` (кнопка СТОП в витрине агента),
   `dev\ui_check.py` + `dev\js_balance.py` (витрина `ui\app.js` + `index.html`).
   Для окон tkinter **автоматической проверки нет** — дырка.
