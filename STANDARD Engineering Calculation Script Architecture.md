# 📐 STANDARD: Engineering Calculation Script Architecture

Этот стандарт обязателен при генерации, рефакторинге и аудите кода для инженерных расчетов (Creo Relations, Mathcad, Python-скрипты параметрического моделирования).

## 1. Блочная архитектура

При объеме кода >100 строк расчет **обязан** быть разбит на последовательные этапы-блоки.

### 1.1. Нумерация и структура
Каждый блок должен иметь:
- Уникальный номер (для навигации и ссылок)
- Мнемоническое имя
- Четкие границы

```c
/* ================================================================= */
/* БЛОК 3. CONST_ НЕИЗМЕНЯЕМЫЕ КОНСТАНТЫ                             */
/* ================================================================= */
```

### 1.2. Рекомендуемая последовательность блоков

| № | Имя блока | Назначение | Допустимые зависимости |
|---|-----------|------------|----------------------|
| 1 | `INPUT` | Исходные данные пользователя | Нет |
| 2 | `SPLAV` / `MAT` | Паспорт материала/сплава | `INPUT` |
| 3 | `CONST` | Физические и технологические константы | Нет |
| 4 | `SAFE` | Валидация и защита входных данных | `INPUT` |
| 5..N | Расчетные блоки | Гидравлика, геометрия, теплофизика | Только предыдущие блоки |
| N+1 | `ECO` / `COST` | Экономика и ТЭП | Только выходные переменные расчетных блоков |
| N+2 | `REPORT` / `VERDICT` | Выводы, предупреждения, текст | Все блоки |

### 1.3. Правила независимости блоков
- ❌ **ЗАПРЕЩЕНО** использовать внутренние (промежуточные) переменные другого блока
- ✅ **РАЗРЕШЕНО** использовать только явно объявленные выходные переменные с правильным префиксом
- ✅ Каждый блок должен быть самодостаточным: при удалении любого промежуточного блока код не должен падать (деградация должна быть контролируемой)
- ✅ Если блоку нужны данные из другого блока, они передаются через интерфейсные переменные с префиксом блока-источника

## 2. Соглашение об именовании параметров

### 2.1. Префикс = Имя блока

**Железное правило:** Каждая переменная начинается с префикса, который **в точности совпадает** с именем блока, в котором она определена.

```c
/* Блок HYDRO */
HYDRO_Q_MM3_S      = ...   /* ✅ Правильно */
FLOW_RATE          = ...   /* ❌ Неправильно: нет префикса */
ST_AREA_MM2        = ...   /* ❌ Неправильно: чужой префикс в блоке HYDRO */
```

**Исключение:** Локальные вспомогательные переменные, используемые только внутри одного выражения и не являющиеся выходом блока. Но даже их рекомендуется именовать с префиксом блока для избежания коллизий.

### 2.2. Суффиксы единиц измерения (СИ)

Каждая физическая величина **обязана** иметь суффикс единицы измерения. Безразмерные величины получают суффикс `_FRAC` или `_RATIO`.

| Суффикс | Единица | Пример |
|---------|---------|--------|
| `_MM` | миллиметр | `ST_D_NIZ_MM` |
| `_MM2` | мм² | `HYDRO_S_ST_MM2` |
| `_MM3` | мм³ | `PRIB_V_TOTAL_MM3` |
| `_M` | метр | `HYDRO_H_RASCH_M` |
| `_M_S` | м/с | `HYDRO_V_TORR_M_S` |
| `_MM_S` | мм/с | `FILL_V_LIFT_MM_S` |
| `_KG` | килограмм | `ST_M_KG` |
| `_KWH` | кВт·ч | `ECO_MELT_KWH` |
| `_SEC` | секунда | `HYDRO_TAU_SEC` |
| `_H` | час | `TO_CYCLE_TOTAL_H` |
| `_FRAC` | доля (0..1) | `ECO_KIM_FACT_FRAC` |
| `_RATIO` | безразмерный коэффициент | `CONST_PRIB_H_V2_RATIO` |
| `_TEXT` | строка | `PRIB_VERDICT_TEXT` |

### 2.3. Структура имени переменной

```
[ПРЕФИКС]_[ОПИСАНИЕ]_[СУФФИКС_ЕДИНИЦЫ]
```

Примеры:
```
HYDRO_S_ST_MM2          ← Блок HYDRO, площадь стояка, мм²
PRIB_LAT_V_REQ_ONE_MM3  ← Блок PRIB, объем боковой прибыли требуемый на одну, мм³
ECO_COST_ONE_DETAL_RUB  ← Блок ECO, себестоимость одной детали, рубли
CONST_MIN_TAU_SEC       ← Блок CONST, минимальное время заливки, секунды
SAFE_MASSA_OTL_KG       ← Блок SAFE, безопасная масса отливки, кг
```

## 3. Правила выполнения уравнений

### 3.1. Порядок определения
- ❌ Переменная **НЕ ДОЛЖНА** использоваться до её объявления/вычисления
- ✅ Все зависимости блока N должны быть полностью вычислены в блоках 1..N-1
- ✅ Внутри блока: сначала определяются все промежуточные переменные, затем — выходные

### 3.2. Защита от некорректных операций
Каждое деление и извлечение корня **обязано** иметь защиту:

```c
/* ❌ ОПАСНО */
AREA = VOLUME / HEIGHT

/* ✅ БЕЗОПАСНО */
IF HEIGHT > 0.0
    AREA = VOLUME / HEIGHT
ELSE
    AREA = 0.0
ENDIF
```

### 3.3. Запрет на магические числа
- ❌ Числа в формулах без имени запрещены
- ✅ Каждое числовое значение должно быть именованной константой с комментарием-источником

```c
/* ❌ */
H_NAP = (H_MM / 1000.0) / 3.0

/* ✅ */
CONST_PRIB_HEAD_DIVISOR = 3.0  /* Эмпирический коэф. приведения высоты к напору (Василевский) */
H_NAP_M = (H_MM / 1000.0) / CONST_PRIB_HEAD_DIVISOR
```

### 3.4. Единообразие масштабирования
- В пределах одного физического расчета все размеры должны быть в **одной системе** (либо все в мм, либо все в м)
- Перевод единиц выполняется **один раз** на границе блока, а не внутри каждой формулы
- Коэффициенты усадки/масштаба применяются **единообразно**: либо ко всем размерам элемента, либо ни к одному. Смешанное масштабирование запрещено.

### 3.5. Запрет на двойные эмпирические коэффициенты
- ❌ Нельзя накладывать два независимых эмпирических коэффициента на одну физическую величину без доказательства их совместимости
- ✅ Если существует несколько методик расчета одной величины, выбирается **одна**. Выбор документируется в комментарии.

## 4. Подробный аудит уравнений

При аудите любого расчетного кода выполнять проверку по следующему чеклисту. Результаты оформлять таблицей.

### 4.1. Чеклист аудита

| № | Проверка | Что искать | Критичность |
|---|----------|-----------|-------------|
| A1 | Размерностная согласованность | Все слагаемые в сумме имеют одинаковую размерность. Аргументы тригонометрических функций безразмерны или в градусах (указать). Левая и правая часть равенства совпадают по размерности | 🔴 CRITICAL |
| A2 | Деление на ноль | Каждое деление защищено проверкой знаменателя > 0 | 🔴 CRITICAL |
| A3 | Извлечение корня | Подкоренное выражение ≥ 0 во всех ветках выполнения | 🔴 CRITICAL |
| A4 | Порядок определения | Ни одна переменная не используется до объявления | 🔴 CRITICAL |
| A5 | Префиксная дисциплина | Все переменные имеют префикс своего блока | 🟡 MAJOR |
| A6 | Суффиксы единиц | Все физические величины имеют суффикс единицы | 🟡 MAJOR |
| A7 | Магические числа | Все числовые литералы в формулах — именованные константы | 🟡 MAJOR |
| A8 | Двойные коэффициенты | На одну величину не наложены два независимых эмпирических множителя | 🔴 CRITICAL |
| A9 | Независимость блоков | Блок не использует внутренние переменные других блоков | 🟡 MAJOR |
| A10 | Неиспользуемые переменные | Нет объявленных, но неиспользованных переменных и констант | 🟢 MINOR |
| A11 | Масштабирование | Усадка/масштаб применены единообразно; нет смешения масштабированных и немасштабированных размеров в одном объеме/площади | 🔴 CRITICAL |
| A12 | Физический смысл | Результат каждой формулы находится в физически допустимом диапазоне (не отрицательный объем, не нулевая скорость при ненулевом расходе и т.д.) | 🟡 MAJOR |
| A13 | Повторные вычисления | Одна и та же величина не вычисляется дважды в разных местах с риском расхождения | 🟡 MAJOR |
| A14 | Защита после вычислений | Результаты вычитаний, которые могут стать отрицательными, защищены `max(0, ...)` | 🟡 MAJOR |
| A15 | Округление | Округление применяется только на финальном этапе выбора стандартного размера, не в промежуточных расчетах | 🟢 MINOR |

### 4.2. Формат отчета аудита

```markdown
## Отчет аудита уравнений

### Критические ошибки (CRITICAL)
| ID | Блок | Переменная | Проблема | Исправление |
|----|------|-----------|----------|-------------|
| A8 | PRIB | PRIB_V_REQ | Двойной коэффициент: K_VOL × TAU/8 | Убрать TAU/8, оставить K_VOL |
| A4 | PIT  | SHL_DENOM | Используется переменная из блока SHL | Заменить на локальную PIT_DENOM |

### Замечания (MAJOR)
| ID | Блок | Переменная | Проблема | Рекомендация |
|----|------|-----------|----------|--------------|
| A5 | ST   | R_LOWER   | Нет суффикса единицы | Переименовать в ST_R_LOWER_MM |
| A10| CONST| SQRT2     | Не используется | Удалить |

### Информационные (MINOR)
...
```

### 4.3. Верификация формул
Для каждой ключевой формулы в аудите выполнять:
1. **Аналитическую проверку**: вывести формулу из первых принципов и сравнить с кодом
2. **Предельные случаи**: проверить поведение при нулях, единицах, экстремальных значениях
3. **Размерностный анализ**: подставить единицы вместо переменных и убедиться, что результат имеет правильную размерность
4. **Числовую проверку**: подставить типичные значения и оценить порядок результата

---

## 5. Применение этого стандарта

- При **генерации нового кода**: следовать разделам 1–3 как обязательному шаблону
- При **рефакторинге**: привести существующий код к стандарту, начиная с префиксов и суффиксов
- При **аудите**: использовать чеклист из раздела 4 без исключений
- При **code review**: отклонять изменения, нарушающие разделы 1–3, как архитектурные дефекты

> **Принцип:** Код расчета — это не программа, это *исполняемая спецификация*. 
  Каждое имя переменной должно нести информацию о том, **откуда** она взялась (префикс), 
  **что** означает (описание) и **в каких единицах** измерена (суффикс). Любая неоднозначность 
  в именовании — это потенциальная инженерная ошибка.
