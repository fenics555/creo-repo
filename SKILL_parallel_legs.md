# ЗАКОН ПАРАЛЛЕЛЬНОЙ НОГИ (дом работает несколькими ногами одновременно)

## 1. Суть
Дом не однопользовательский: `D:\AI\repo` и `D:\AI\tools` — **общие** репозитории. Параллельная
нога может в любой момент: застейджить свои файлы, сделать `rebase`, запушить. Твоя нога обязана
при этом **остаться целой и не унести чужое**.

## 2. Как узнать, что рядом работает чужая нога (ДО коммита)
- `git log --format='%h|%an|%ad' --date=format:'%H:%M' -8` — чужие коммиты **в те же минуты**.
- `git stash list` — чужой stash (`On master: parallel-leg-…`).
- Test-Path `.git\rebase-merge`, `.git\rebase-apply` — идёт rebase.
- `git status --short` — есть файлы, которых ты не редактировал.

## 3. ЗАПРЕТЫ (каждый уже стоил работы — см. ПОВТОРЫ)
1. **`git add -A` / `git add .` в общем репозитории ЗАПРЕЩЁН.** Только адресно:
   `git add -- <свои пути>`.
2. **`git commit` БЕЗ pathspec ЗАПРЕЩЁН** — он коммитит ВСЁ staged, включая чужое.
   Только `git commit -m "<текст>" -- <свои пути>`.
   Пустой коммит-обёртка (`--allow-empty`) тоже делается **с pathspec**.
   *Краш `crash_git_commit-sweeps-foreign-staged`, ПОВТОРЫ: 2 (22.09).*
3. **Перед каждым коммитом — цитата `git diff --cached --name-only`**, сверка со своим списком.
   Расхождение = стоп-отчёт, коммит не делать.
4. **Чужое staged не разстейдживать молча** (не трогать чужую подготовку).
5. **Чужой `rebase` НЕ продолжать и НЕ отменять.** Достать своё из `stash`, доложить.
   *Краш `crash_git_parallel-leg-rebase-reverts-worktree` (22.09): rebase застэшил чужие правки
   и откатил массовые `git mv`.*
6. **Перед массовыми `git mv`** — цитата `git status` и `git stash list`.
7. **Историю не переписывать**: `push --force` запрещён. Свою аварийную копию без `--force`:
   `git push origin master:refs/heads/backup-<дата>` (приёмка — `git ls-remote origin`).
8. **Push — в свою ветку или master после адресного коммита.** `git push` в чужую ветку,
   которую ты не коммитил, запрещён.

## 4. Кто в доме работает параллельно (живой факт 02.10.2026)
В `D:\AI\repo` параллельно шла нога по теме PROMPT (коммиты `9fb41ed`, `38435ca`, `2ccc0cc`,
`678154e` — «Фаза 26», «ОТКАТ H2», «Указатель PROMPT»), мои ноги — рядом по минутам.
В `D:\AI\tools` автоматически появляются коммиты `autosave <дата>` — ещё один источник изменений:
перед своим коммитом всегда смотри `git log -3`, чтобы не принять автосейв за свою работу.

## 5. Приёмка своего коммита
`git show --stat <свой-хэш>` — в списке файлов только свои. Это **обязательная** проверка:
она ловит случай «коммит без pathspec унёс чужое» после факта.

**Грабля (02.10.2026, случилось в этой же ноге):** проверять надо `git show <свой-хэш>`,
а **НЕ `git show --stat HEAD`** — в доме с параллельными ногами `HEAD` уезжает вперёд за секунды:
мой коммит `701186f` содержал ровно один файл, но пока я его проверял, чужая нога сделала
свой `ed8609a` (через 17 секунд), и `HEAD` показал **чужие** файлы. Я решил, что унёс чужое.
Вывод: после `commit` сразу `git show --no-patch --format='' <свой-хэш> --name-only` —
хэш берётся из вывода самого коммита, а не «последний».

## 6. Грабли
- «Мои файлы попали в коммит» не значит «в коммите только мои файлы» — смотри `--stat` целиком.
- `git add .` и `git add -A` в PowerShell/PowerShell-обёртке ведут себя как ожидает, но в доме
  с чужим staged это всё равно запрет.
- Пустой коммит «чтобы зафиксировать» — тоже должен идти с pathspec, иначе он подметает staged.
