# ЗДОРОВЬЕ НОГИ — контроль деградации и передача эстафеты

**Суть:** локальная модель кажется рабочей до тех пор, пока не начнет портить файлы из-за переполнения контекста. Ошибки в якорях замены, выдуманные имена инструментов и потеря нити задачи — это сигналы исчерпания ресурса.

**Главный закон:** при появлении двух признаков деградации — **не чинить дальше, а остановить работу и передать эстафету**.

## 1. Счетчик вызовов инструментов (пороги усталости)

Модель не видит точный остаток токенов в окне, поэтому состояние оценивается по количеству сделанных вызовов инструментов за текущую сессию:

*   **0–40 вызовов (Свежая):** штатная работа по плану.
*   **40–55 вызовов (Зона внимания):** тщательно сверяй якоря замены со свежим чтением файла, проверяй результат каждой правки.
*   **55–70 вызовов (Усталость):** при появлении хотя бы одного признака деградации — немедленно готовь эстафету.
*   **70+ вызовов (Предел):** обязательная остановка и передача эстафеты, даже если кажется, что все идет гладко.

## 2. Три признака деградации (наблюдаемые факты)

1.  **Промах якоря замены:** `editor` не нашел фрагмент, и пришлось перечитывать файл заново для поиска нового якоря.
2.  **Повторный сбой правки:** ошибка `text not found` (или иная ошибка редактирования) два раза подряд — это признак потери точного представления о структуре файла.
3.  **Потеря памяти о контексте:** необходимость повторно перечитывать уже изученный в этой сессии файл, чтобы вспомнить, что в нем находится.

*(Предупреждающие сигналы: попытка вызвать несуществующий инструмент, опечатка в пути или забытое условие из начала задачи).*

## 3. Порядок действий при деградации

Если сработали **два признака из трех** или достигнут предел вызовов:

1.  **Остановиться на безопасной точке.** Не бросай файл в недописанном или сломанном состоянии.
2.  **Прочитать правила эстафеты:** откройте `D:\AI\repo\SKILL_handover.md`.
3.  **Зафиксировать состояние:** обнови журнал задачи в `PROGRESS_*.md` (если он ведется по задаче) и запиши файл эстафеты строго в `D:\AI\ЭСТАФЕТЫ\<ТЕМА>.md`.
4.  **Сохранить результат:** если есть проверенные, рабочие изменения — зафиксируй их в git (соблюдая `SKILL_parallel_legs.md`) и напиши итоговый отчет в `D:\AI\log\reports\`.
5.  **Сообщить пользователю одной строкой:** укажи путь к файлу эстафеты, что сделано и какой шаг будет первым для следующей ноги.

## 4. Учет сжатий контекста (Compaction)

Если среда Cline выполнила автоматическое сжатие истории диалога (компакцию) — это прямой сигнал к завершению ноги. После **второго сжатия контекста** за одну сессию работа над сложными правками запрещена — разрешено только оформить передачу эстафеты.
