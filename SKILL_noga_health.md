# ЗДОРОВЬЕ НОГИ — контроль деградации и передача эстафеты

**Суть:** локальная модель кажется рабочей до тех пор, пока не начнет портить файлы из-за переполнения контекста. Ошибки в якорях замены, выдуманные имена инструментов и потеря нити задачи — это сигналы исчерпания ресурса.

**Главный закон:** при появлении двух признаков деградации — **не чинить дальше, а остановить работу и передать эстафету** (Downshift).

## 1. ШКАЛА КОГНИТИВНОЙ ЕМКОСТИ (Capacity-Based)

Состояние оценивается по проценту заполнения окна (window_pct) от 
um_ctx активной модели (с дефолтным MAX_CTX = 131072 при сбое).

* **ЗЕЛЁНАЯ ЗОНА (0–45% окна, < 40 вызовов):** Штатная работа. Любое число микро-вызовов.
* **ЖЁЛТАЯ ЗОНА (45–70% окна, 40–55 вызовов):** Принудительный переход в режим **ДИСПЕТЧЕР**. Запрет на прямое чтение файлов > 50 строк в главном окне. Вся разведка — через субагентов.
* **ОРАНЖЕВАЯ ЗОНА (70–80% окна, 55–70 вызовов):** Автоматический **Downshift**. Остановка автономного цикла, завершение текущего атомарного шага, подготовка эстафеты.
* **КРАСНАЯ ЗОНА (> 80% окна или 1-е сжатие контекста):** **БЕЗУСЛОВНЫЙ СТОП**. Запрет на правку кода. Немедленная запись ESTAFETA_<ТЕМА>.md силами свежего субагента-приёмщика.

## 2. ТРИ ПРИЗНАКА ДЕГРАДАЦИИ (наблюдаемые факты)

1.  **Промах якоря замены:** editor не нашел фрагмент, и пришлось перечитывать файл заново для поиска нового якоря.
2.  **Повторный сбой правки:** ошибка 	ext not found (или иная ошибка редактирования) два раза подряд — это признак потери точного представления о структуре файла.
3.  **Потеря памяти о контексте:** необходимость повторно перечитывать уже изученный в этой сессии файл, чтобы вспомнить, что в нем находится.

## 3. ПОРЯДОК ДЕЙСТВИЙ ПРИ ДЕГРАДАЦИИ

Если сработали **два признака из трех** или достигнут порог зоны (Жёлтая/Оранжевая/Красная):

1.  **Остановиться на безопасной точке.** Не бросай файл в недописанном или сломанном состоянии.
2.  **Прочитать правила эстафеты:** откройте D:\AI\repo\SKILL_handover.md.
3.  **Зафиксировать состояние:** обнови журнал задачи в PROGRESS_*.md (если он ведется по задаче) и запиши файл эстафеты строго в D:\AI\ЭСТАФЕТЫ\<ТЕМА>.md.
4.  **Сохранить результат:** если есть проверенные, рабочие изменения — зафиксируй их в git (соблюдая SKILL_parallel_legs.md) и напиши итоговый отчет в D:\AI\log\reports\.
5.  **Сообщить пользователю одной строкой:** укажи путь к файлу эстафеты, что сделано и какой шаг будет первым для следующей ноги.

## 4. УЧЕТ СЖАТИЙ КОНТЕКСТА (COMPACTION)

Если среда Cline выполнила автоматическое сжатие истории диалога (компакцию) — это прямой сигнал к завершению ноги. После **первого сжатия контекста** за одну сессию работа над сложными правками запрещена — разрешено только оформить передачу эстафеты.
