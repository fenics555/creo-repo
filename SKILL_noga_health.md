# ЗДОРОВЬЕ НОГИ — контроль деградации и передача эстафеты

**Суть:** локальная модель кажется рабочей до тех пор, пока не начнет портить файлы из-за переполнения контекста. Ошибки в якорях замены, выдуманные имена инструментов и потеря нити задачи — это сигналы исчерпания ресурса.

**Главный закон:** при появлении двух признаков деградации — **не чинить дальше, а остановить работу и передать эстафету**.

## 1. Счетчик вызовов инструментов (пороги усталости)

Заполнение окна **можно измерить** прямым запросом к файлу сессии Cline (метод — `SKILL_local_agent_cline.md` §8). Если замер недоступен — состояние оценивается по количеству сделанных вызовов инструментов за текущую сессию:

*   **0–40 вызовов (Свежая):** штатная работа по плану.
*   **40–55 вызовов (Зона внимания):** тщательно сверяй якоря замены со свежим чтением файла, проверяй результат каждой правки.
*   **55–70 вызовов (Усталость):** при появлении хотя бы одного признака деградации — немедленно готовь эстафету.
*   **70+ вызовов (Предел):** обязательная остановка и передача эстафеты, даже если кажется, что все идет гладко.

## 2. Три признака деградации (наблюдаемые факты)

1.  **Промах якоря замены:** `editor` не нашел фрагмент, и пришлось перечитывать файл заново для поиска нового якоря.
2.  **Повторный сбой правки:** ошибка `text not found` (или иная ошибка редактирования) два раза подряд — это признак потери точного представления о структуре файла.
3.  **Потеря памяти о контексте:** необходимость повторно перечитывать уже изученный в этой сессии файл, чтобы вспомнить, что в нем находится.

*(Предупреждающие сигналы: попытка вызвать несуществующий инструмент, опечатка в пути или забытое условие из начала задачи).*

### 2.1. Шкала заполнения окна от MAX_CTX (v3.0)
База: `DEFAULT_MAX_CTX = 131072`. Знаменатель `MAX` — из `globalState.json` по провайдеру (см. `SKILL_local_agent_cline.md` §8), когда известен. Оценка заполнения окна объединяется с тремя признаками деградации (§2):
* **0–45% [ЗЕЛЁНАЯ]:** штатная работа по плану.
* **45–70% [ЖЁЛТАЯ]:** принудительный переход в режим `ДИСПЕТЧЕР` (микро-субагенты).
* **70–80% [ОРАНЖЕВАЯ]:** Downshift — торможение, подготовка эстафеты `ESTAFETA_<ТЕМА>.md`.
* **> 80% или 1-е сжатие [КРАСНАЯ]:** СТОП, немедленная передача эстафеты.

**Страховочный счётчик вызовов** (когда % окна неизвестен): 40 — внимание, 55 — усталость, 70+ — обязательная передача ноги. **Главная шкала — `%` окна (§2.1); счётчик вызовов применяется только когда `%` неизвестен.**

**Единый полный футер (последняя строка каждого ответа-остановки):**
`[НОГА: старт <HH:MM:SS> (<M>м <S>с) | вызовы: гл <M> + суб <S> | окно: <X>% (<YYk>/<MAXk>, downshift <70%k> / стоп <80%k>) | сжатий: <K> | git: <clean/dirty> | зона: <ЗЕЛЁНАЯ/ЖЁЛТАЯ/ОРАНЖЕВАЯ/КРАСНАЯ>]`

## 3. Порядок действий при деградации

Если сработали **два признака из трех** или достигнут предел вызовов:

1.  **Остановиться на безопасной точке.** Не бросай файл в недописанном или сломанном состоянии.
2.  **Прочитать правила эстафеты:** откройте `D:\AI\repo\SKILL_handover.md`.
3.  **Зафиксировать состояние:** обнови журнал задачи в `PROGRESS_*.md` (если он ведется по задаче) и запиши файл эстафеты строго в `D:\AI\ЭСТАФЕТЫ\<ТЕМА>.md`.
4.  **Сохранить результат:** если есть проверенные, рабочие изменения — зафиксируй их в git (соблюдая `SKILL_parallel_legs.md`) и напиши итоговый отчет в `D:\AI\log\reports\`.
5.  **Сообщить пользователю одной строкой:** укажи путь к файлу эстафеты, что сделано и какой шаг будет первым для следующей ноги.

## 4. Учет сжатий контекста (Compaction)

Если среда Cline выполнила автоматическое сжатие истории диалога (компакцию) — это прямой сигнал к завершению ноги. После **первого сжатия контекста** за одну сессию работа над сложными правками запрещена — разрешено только оформить передачу эстафеты.

**КАК СЧИТАТЬ СЖАТИЯ (метод, 24.11.2026).** Не по памяти и не «на глаз»: смотреть данные Cline на диске —
`C:\Users\User\.cline\data\sessions\<id>\<id>.compaction.json` (**mtime файла = момент последнего сжатия**;
у нас был 24.11.2026 13:45:01 при старте ноги 13:24:29 ⇒ в футере обязано быть `сжатий: ≥1`, а не 0).
Окно модели берётся из `C:\Users\User\.cline\data\globalState.json` — поле `actModeOpenAiModelInfo.contextWindow`
(или `actModeOpenRouterModelInfo.contextWindow`); для нашего прогона 24.11 = **1 048 576**.
Печатать в футере выдуманный ноль запрещено (`.clinerules` §1.7).
**`н/д` ЗАПРЕЩЁН, если данные добываемы** — метод замера паспорта (inputTokens / contextWindow / модель / провайдер) даёт **одна команда** из `.clinerules` §1.7. `н/д` — только если сессия или `globalState.json` физически недоступны.
**Пример заполненного футера (образец формата):** `[НОГА: старт 13:24:29 (35м 12с) | вызовы: гл 41 + суб 0 | окно: 23% (30k/262k) | сжатий: 0 | git: dirty | зона: ЗЕЛЁНАЯ]`
