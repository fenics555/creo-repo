## 2. Как плагин встраивается в Creo (механизм)
По документации вендора + по механизму VERICUT в доме:
1. В `<продукт>\bin` лежат `protk.dat` + DLL плагина (+ каталоги ресурсов/текстов).
2. В `config.pro` появляется строка `protkdat <путь>`; либо плагин кладёт свой `protk.dat`
   в `Common Files\text\protk.dat`, а Creo читает его автоматически при старте.
3. `protk.dat` — текстовый файл вида:
   ```
   name <имя>
   startup dll
   exec_file <путь\DLL>
   text_dir <путь\тексты>
   revision <версия Creo>
   end
   ```
4. При старте Creo DLL грузится **внутрь процесса Creo** и регистрирует свои функции (Pro/TOOLKIT).
5. Модуль получает права работать с моделью, как Creo сам: команды, меню, обработчики событий.

**Следствие для дома:** плагин — это «код, живущий внутри Creo». Он видит всё, чего не видит
внешняя программа: внутреннее дерево признаков, параметры в контексте регенерации, отверстия
в геометрии, штриховку на чертеже. Именно поэтому плагины умеют то, чего агент не умеет.

## 3. Что из этого берём (важно)
Мы **не ставим** плагины. Но стоит понять, где их сила и как её повторить **снаружи**:
| Сила плагина | Почему агент так не может | Чем закрыть снаружи |
|---|---|---|
| разбор отверстий в геометрии (`SHC`) | нужны признаки и геометрия изнутри | читать `.hol` + параметры модели + наш `plm_reader` |
| штриховка/паттерны чертежа | рисуется при построении чертежа | аудит результата (PDF/файл), а не сам рисунок |
| правила и цветовая кодировка | события модели в реальном времени | свой движок правил поверх файлов/индекса |
| пакетное обновление параметров | массовые операции в памяти Creo | агент уже умеет (creo_ops) — тут мы сильнее |
| MBD/PDF-экспорт с выбором | штатные средства Creo | агент делает своё (см. сравнение) |

**Общий принцип:** берём у вендора **схему проверок и суть правил**, а выполняем — **своими
руками класса Р (по файлам)** либо живым Creo через CREOSON/JLINK там, где без этого никак.
