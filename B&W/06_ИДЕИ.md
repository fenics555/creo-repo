# 06. ИДЕИ (что можно построить/сделать)

_03.10.2026, Cline. Идеи — предложения, не согласованные решения. Каждая помечена ценой._

## Идея 1. «Валидатор .hol» без установки плагина (⭐ главная)
Дом уже умеет читать `.hol` и уже нашёл 4 битых файла. B&W в 19.3.0.1 сформулировал ровно наши
правила валидации. Значит, можно сделать **программу класса Р** `hol_check`:
- вход: папка `ТАБЛИЦА_ОТВЕРСТИЙ` (+ подпапки);
- проверки: (1) у `THREAD_DATA` есть шапка; (2) число колонок шапки = число колонок данных;
  (3) нет разорванных имён (эвристика: имена колонок известны из эталона `g6111_konich_60.hol`);
  (4) кодировка/разделители (cp1251/utf-8, TAB/пробелы);
- выход: отчёт + CSV, режимы scan/apply, свой лог, три руки по закону трёх рук.
**Цена:** средняя (логика уже есть в конспекте и в наработках `trail_tools`).
**Ценность:** снимает ошибку в каждом трейле флота без установки чужих плагинов и без
изменения боевых файлов в `Z:`.

## Идея 2. Правило «любой сторонний плагин ломает mapkey»
Из Changelog SMARTOptics: вендер сам предупреждает, что смена имён кнопок ломает mapkey.
**Закон дома:** при установке любого стороннего плагина — (1) записать в журнал список
используемых домом mapkey; (2) после старта Creo с плагином проверить 2–3 ключевых mapkey
живым прогоном (`creo_mapkey`); (3) результат — в отчёт и в `БЕКАП\ЖУРНАЛ.md`.
Куда: `Prog\SKILL_tool_routing` или новый раздел в `Creo\SKILL_creo_index.md`.

## Идея 3. Реестр плагинов дома (одна таблица)
Сейчас в боевом `config.pro` одна строка `protkdat` (VERICUT) и одна закомментированная
(KeyShot). Через год будет ещё. Идея: файл `D:\AI\repo\B&W\PLUGINS.md` (или раздел в
`config_audit`) — таблица: продукт · версия · путь protk.dat · версия Creo · активен ·
дата установки · кто ставил · источник. `config_audit` мог бы её читать и проверять
(сегодня он проверяет только «путь живой»).

## Идея 4. «Инвентарь возможностей плагинов» как источник требований
Changelog-файлы вендора — это, по сути, бесплатный перечень мировых практик: rename features,
relations checking, allowed-value list, parameter translation, batch update, цветовые правила,
MBD-экспорт. Их можно читать как **список пробелов в доме** и превращать в задачи
(например, «relations checking» у нас есть ли? — `RELATIONS\` есть, но отдельной проверки нет).

## Идея 5. Прототип установки в урне (без риска)
Не ставить, а **распаковать в урну** `D:\AI\log\urn\bw\` один модуль (`smartoptics`/`smartholechart`
— они `exe`, распаковываются 7z/Inno/NSIS) и посмотреть: какой `protk.dat` он кладёт,
какие DLL, какие `xml`/`cfg` настроек, есть ли текстовые базы. Это даст **факты** вместо
гипотез о внутренностях, не трогая Creo. Нужны 7z и любопытство, админ не нужен.

## Идея 6. Changelog-и как зеркало чужих багов
В Changelog-файлах перечислены сотни реальных багов Creo-окружения (Windchill + hatchings,
PAT-штриховки, merge-фичи + UDF, family table + параметры, `Cannot get THREAD_DAT`-подобные).
Их можно выгрузить в таблицу «известные грабли → наши скиллы», чтобы дом заранее знал,
где опасно: это дешёвый способ поднять надёжность без своего аудита.

## Идея 7. Разделение «своё vs покупное»
Для каждой задачи, где B&W умеет (таблицы отверстий, штриховка, примечания, пакетные
параметры), решить осознанно: **своя программа (класс Р, читает файлы, ничего не ломает)** или
**плагин (класс Ж, работает в Creo, но меняет окружение)**). Домашний стиль — «руки без Creo»,
поэтому по умолчанию первое; плагин — только там, где без Creo никак (правила, физика).

## Идея 8. Если решить ставить — порядок безопасной установки
1. Согласование с хозяином (письменно). 2. Бэкап `config.pro` в `БЭКАUP\`+ запись в журнал.
3. Ставить **на одну машину**, не в `Z:`. 4. Проверка: `config_audit` (RC 0), старт Creo без
ошибок, 2–3 mapkey-прогона, замер времени старта (плагин может замедлять старт — дом это уже
меряет на флоте). 5. Только потом решать про флот.
