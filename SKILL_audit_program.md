# АУДИТ ПРОГРАММЫ (не дома)

Двойник `SKILL_audit_protocol.md`, но предмет — **одна программа** (`D:\AI\tools\agent\<имя>`),
а не дом. Здесь лежит методика и **шаблон спеки** для вставки в задачу владельцу.

== 0. ЖЕЛЕЗНЫЕ ПРАВИЛА АУДИТА ПРОГРАММЫ ==
0.1 Сначала **читаем чужой скилл на инструмент** (`Creo\SKILL_creo_file_reading.md` и т.п.) и
    предыдущие `REPORT_*` по нему — не открываем историю заново.
0.2 **Пробы — только на копии и во временной папке** (`D:\AI\log\urn\<исполнитель>\`).
    Грабля 02.10.2026: `load_settings_file(чужой_путь)` ПИШЕТ в боевой `SETTINGS_FILE`;
    проба с несуществующим `db_dir` СОЗДАЁТ папку на диске.
0.3 Перед любой правкой кода — бекап в `D:\AI\tools\agent\data\backup\pre_<метка>_<файл>`.
0.4 **Тяжёлое железо — только с разрешения:** полный скан (`--full`), прогон по всему складу,
    загрузка модели. Быстрые прогоны (`check`, `count`, `--limit 5`) — можно.
0.5 **Удаления — только по прямому слову владельца** (MANIFEST п.5). Найденный мусор —
    не «чиним», а перечисляем с командами и ждём слова.
0.6 Каждая находка: номер, факт-цитата (путь:строка или команда+вывод), риск, статус.
0.7 Правки кода — **после** правок в отчёте и по слову владельца (если он не дал его заранее).

== 1. ЧТО ПРОВЕРЯЕМ (карта проверок) ==

| # | Блок | Как проверяем |
|---|---|---|
| 1 | **Состав папки** | список файлов на диске против README и против манифеста `version.json` |
| 2 | **Настройки в одном месте** | `DEFAULT_SETTINGS` ↔ ключи файла ↔ миграции; есть ли «сироты» настроек в других папках |
| 3 | **Карта путей** | что куда пишет и что откуда читает: база, кэш, бэкапы, замок, логи, отчёты, черновик |
| 4 | **Переменные окружения** | какие `VAR=` читает программа (порядок приоритета) |
| 5 | **Все вызовы** | каждая команда CLI и каждая кнопка окна — код возврата + осмысленность вывода |
| 6 | **Целостность данных** | для sqlite: `PRAGMA integrity_check`, счётчики таблиц, мета-значения |
| 7 | **Логи** | куда пишутся, растут ли, что в хвосте, есть ли ошибки |
| 8 | **Ротация/хранение** | сколько копий, что удаляется, не растёт ли папка |
| 9 | **Согласованность источников** | CLI ↔ окно ↔ визард берут ОДНО И ТО ЖЕ (частое расхождение!) |
| 10 | **Живой запуск окна** | старт, заголовок версии, stderr пуст, selfcheck |
| 11 | **Мусор** | временные файлы, старые логи, legacy-файлы, копии вне гита |

== 2. ФОРМАТ ОТЧЁТА (обязательные разделы) ==

`D:\AI\log\reports\REPORT_<инструмент>_audit_<ГГГГГ-ММ-ДД>.md`

1. Итог в одном абзаце (сколько находок, сколько багов, что исправлено).
2. Карта: что куда пишет и что откуда читает (таблицы).
3. Живая проверка вызовов (таблица: команда → код → вывод → вердикт).
4. Находки: `D1 (баг/мусор/наблюдение, исправлен/ждёт решения)`.
5. Что сделано в этом заходе.
6. **Что НЕ сделано / требует решения владельца** (удаления, тяжёлые прогоны).
7. Грабли (что не повторять).
8. Приёмка: `py_compile`, код вызовов, integrity, пуш `rev-list 0 0`.

== 3. ШАБЛОН СПЕКИ ДЛЯ ЗАДАЧИ ВЛАДЕЛЬЦА ==

Вставляется в задачу как есть:

```
СДЕЛАЙ ПОЛНЫЙ АУДИТ ПРОГРАММЫ <путь-к-папке> (не дома целиком).

1. ПРОЧТИ скилл на инструмент и прошлые отчёты по нему (не начинай историю заново).
2. ПРОВЕРЬ по карте: состав папки · настройки (одно ли место, все ли ключи, миграции) ·
   что куда пишет и что откуда читает (база, кэш, бэкапы, замок, логи, отчёты, черновик) ·
   переменные окружения · согласованность CLI ↔ окно ↔ визард.
3. ПРОВЕРЬ ЖИВЫМ ВЫЗОВОМ: каждая команда CLI и каждая кнопка окна — код возврата и
   осмысленность вывода; целостность данных (integrity_check); логи; ротацию.
4. ПОЛОЖИ отчёт в файл `D:\AI\log\reports\REPORT_<имя>_audit_<дата>.md`
   с разделами: итог · карта путей · таблица вызовов · находки (D1, D2…) ·
   что сделано · что НЕ сделано и требует решения · грабли · приёмка.
5. ОБНОВИ README (сверь с диском: файлы, команды, цифры) и паспорт программы.
6. ДОПИШИ в скилл инструмента найденные грабли и новые правила.

ОГРАНИЧЕНИЯ:
- пробы — на копии и во временной папке `D:\AI\log\urn\<исполнитель>\`, боевые
  настройки/базу не трогать;
- перед правкой кода — бекап в `D:\AI\tools\agent\data\backup\`;
- тяжёлое (полный скан, прогон по всему складу, загрузка модели) — спросить;
- удаления — только по моему прямому слову, найденный мусор перечислить и ждать;
- каждый факт — с цитатой (путь:строка или команда+вывод), «ФАКТ» без цитаты запрещён.
ПРИЁМКА: py_compile 0 · все вызовы код 0 · integrity ok · пуш с rev-list 0 0.
```

== 4. ТИПИЧНЫЕ НАХОДКИ (проверено на plm_reader 02.10.2026) ==
* **CLI ≠ окно**: разные корни/исключения/пороги → «цифры консоли спорят с цифрами окна».
* **Проба пишет в боевые настройки** (`is_old` → `save_settings_file`).
* **Проба с несуществующим путём создаёт папку** на диске.
* **Ротация по имени файла**: файлы с чужими именами не убираются и копятся.
* **Устаревшие логи/legacy-файлы в папке программы** после переезда на домашние логи.
* **`ERROR ... No such file or directory`** при скане — живой склад, а не сбой программы.
