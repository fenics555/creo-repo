# SKILL: Превышение лимита редактора (Editor Too Large)

## Описание сбоя
Ошибка `Editor input too large` возникает, когда объем текста, передаваемый в инструменте `editor` через параметр `new_text`, превышает рекомендуемый лимит (около 6000 символов).

## Причины (Разбор)
1. **Монолитный перенос**: Попытка перенести функции целиком (например, `run_loop` или `ask` с их зависимостями) одним вызовом.
2. **Недостаточное дробление**: Игнорирование предупреждений IDE о размере блока.
3. **Сложные зависимости**: Когда функции тянут за собой много контекста, увеличивая итоговый размер `new_text`.

## Алгоритм действий при возникновении

### 1. Остановка и оценка (Diagnostics)
Если получен `Editor input too large`:
- **СТОП**. Не повторяй ту же самую операцию.
- Оцени размер `new_text`. Если он > 5000 символов — это гарантированный сбой.

### 2. Стратегия дробления (Mitigation: Chunking)
Вместо одного большого вызова используй серию мелких:
- **По функциям**: Если нужно перенести 5 функций, делай 5 отдельных вызовов `editor`.
- **По частям функции**: Если одна функция слишком велика (например, `ask` в `agent.py`), разбей её на логические блоки (начало, середина, конец) и используй `insert_line` или несколько вызовов `editor` с разными `old_text`.
- **Метод "Якорей"**: 
    1. Сначала создай файл или добавь кусок кода.
    2. Найди место вставки через `search_codebase` или `read_files`.
    3. Используй `insert_line` для добавления следующего куска.

### 3. Проверка (Validation)
После каждой "порции" правок:
- Проверь синтаксис: `py_compile <file>.py`.
- Если это часть большого рефакторинга, не жди конца всей задачи, чтобы убедиться, что файл всё еще "жив".

## Запрещенные действия
- Попытка повторного вызова `editor` с тем же объемом текста.
- Игнорирование ошибки и переход к следующему шагу без исправления текущего.
- Попытка использовать `write_file` для частичного обновления существующего файла (это создаст новый файл вместо правки).
