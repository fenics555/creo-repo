СИМПТОМ: search_codebase с массивом из нескольких regex-паттернов (4 и более)
возвращает маркер миграции вместо результатов поиска; исполнитель теряет результаты
и повторяет запрос по памяти или вслепую.
ПРИЧИНА:
1. Слишком много паттернов в одном вызове search_codebase — объём результата
превышает лимит (~48k per query по правилу 9.1), система мигрирует/обрезает
ответ, превращая его в маркер «missing».
2. Исполнитель не проверяет результат первого паттерна перед отправкой остальных —
пытается получить всё одним вызовом вместо серии точечных.
ЛЕЧЕНИЕ (проверено):
- search_codebase — только ОДИН паттерн за вызов.
- После каждого вызова проверять результат: если маркер миграции — не повторять
многопаттерновый запрос, а разбить на серию одиночных.
- Точечные запросы: сначала самый узкий паттерн (например, creo_get_params),
результат проверить, потом следующий.
ПРОФИЛАКТИКА:
1. Один regex — один вызов search_codebase.
2. Если результат маркер миграции — не умножать паттерны, а искать иначе
(например, через findstr или чтение конкретного файла).
3. Не отправлять 3+ паттерна в одном вызове, даже если они «независимы» —
лимит вывода всё равно обрывает.
