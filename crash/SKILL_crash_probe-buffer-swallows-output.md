ОШИБКА (дословно, для grep):
`Command failed: Command timed out after 30000ms` — при этом файл вывода ПУСТ (0 байт),
хотя до этого та же команда печатала строки. Процесс python оставался жив (видно в
`Get-Process python`).
СИМПТОМ: скрипт напечатал первые строки, потом завис, его убили по таймауту — и файл
оказался пустым целиком. Вывод «пропал», диагностика встала: неясно, завис ли импорт,
сборка окна или уже вывод.
ПРИЧИНА (факт): stdout питона буферизуется. При `> file` буфер не сбрасывается, пока процесс
жив; убий процесса — буфер теряется. Первые же `print()` без `flush` в файл не дошли.
ПРОФИЛАКТИКА:
1. **Фоновый прогон = `python -u`** (`start /b python -u -X utf8 file.py > out.txt 2>&1`),
   иначе при зависании или убийстве вывод потеряется целиком.
2. В диагностической пробе — `print(..., flush=True)` на КАЖДОМ шаге: замер с шагами обязан
   быть виден сразу, а не в конце.
3. Два опроса одного и того же файла запрещены (анти-петля) — поэтому запускать с `-u`
   сразу, а не «сначала посмотрим».
4. PowerShell и `> file` в одной строке переписывает файл при каждом запуске: после
   перезапуска пробы старый (полезный) вывод потерян. Если нужен архив — писать в файл
   с датой.
5. Диагностика по шагам в файле, который ПУСТ — это не «скрипт не печатал», а «буфер потерян».
   Прежде чем искать причину в коде, перезапустить с `-u`.
