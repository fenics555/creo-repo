ОШИБКА (дословно, для grep):
Editor input too large (повторные отказы при передаче блока сверх лимита одним вызовом)
СИМПТОМ: многократные отказы editor, потеря контекста, обсуждение причин в чате вместо записи краха; ложные выводы (сироты там, где их нет) из-за неполного чтения базы и кодировок.
ПРИЧИНА: 1) «экономия» из спеки прочитана как разрешение сокращать чтение скиллов и дробление; 2) нарушен закон двух отказов - метод не сменён после второго отказа; 3) нарушен протокол краха - запись в crash\ отложена в пользу разговора в чате.
ПРОФИЛАКТИКА:
1. Экономия не покрывает чтение обязательных скиллов и форматы данных (MANIFEST М18, правка 23.09): факт - только probe (SELECT LIMIT 5 / head / чтение с двумя кодировками).
2. Два отказа editor на блоке = мгновенный переход на дробление (create + дописывание у последней строки) или insert_line; третий блок тем же путём запрещён (MANIFEST М7).
3. Крах = запись в crash\ в том же ходе, не обсуждение в чате (см. SKILL_crash_protocol_omission).
ПОВТОРЫ: 1

ДОПИСАНО 02.10.2026 (ревизия orphan_scan, Cline) — ТОТ ЖЕ ПОДПИС, ТОТ ЖЕ ПОЧЕРК:
ОШИБКА (дословно, для grep): `Editor input too large: new_text was 7289 characters, exceeding the recommended limit of 6000` + `text not found` на якоря из памяти.
СИМПТОМ: отчёт на 7 КБ не пишется целиком (первая попытка), затем правка `run()` падает с «text not found», потому что якорь взят по памяти, а файл уже менялся; агент ищет правый блок ещё и не своим инструментом.
ПРИЧИНА: 1) большой отчёт писается одним блоком вместо create + дописывания; 2) `old_text` взят не из свежего чтения; 3) после первого отказа метод не сменён — тот же редактор с другим якорём.
ПРОФИЛАКТИКА:
1. Файл больше 6 КБ: `editor` без `old_text` (create) первым блоком ≤4 КБ, дальше — ТОЛЬКО `insert_line` перед последней строкой или добавление по свежему якорю из `read_files`/`Select-String`.
2. «text not found» = якорь устарел: сначала `read_files` диапазоном или `Select-String` (учесть: `search_codebase` ищет только по рабочей папке чата, а не по `D:\AI` — это тоже смена метода), и только потом вторая попытка правки.
3. Сообщение «ПОПЫТКА N:» с второго отказа — обязательно (MANIFEST М18, п.18).
