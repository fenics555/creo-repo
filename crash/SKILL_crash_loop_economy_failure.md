ОШИБКА (дословно, для grep):
Editor input too large (повторные отказы при передаче блока сверх лимита одним вызовом)
СИМПТОМ: многократные отказы editor, потеря контекста, обсуждение причин в чате вместо записи краха; ложные выводы (сироты там, где их нет) из-за неполного чтения базы и кодировок.
ПРИЧИНА: 1) «экономия» из спеки прочитана как разрешение сокращать чтение скиллов и дробление; 2) нарушен закон двух отказов - метод не сменён после второго отказа; 3) нарушен протокол краха - запись в crash\ отложена в пользу разговора в чате.
ПРОФИЛАКТИКА:
1. Экономия не покрывает чтение обязательных скиллов и форматы данных (MANIFEST М18, правка 23.09): факт - только probe (SELECT LIMIT 5 / head / чтение с двумя кодировками).
2. Два отказа editor на блоке = мгновенный переход на дробление (create + дописывание у последней строки) или insert_line; третий блок тем же путём запрещён (MANIFEST М7).
3. Крах = запись в crash\ в том же ходе, не обсуждение в чате (см. SKILL_crash_protocol_omission).
