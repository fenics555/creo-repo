ОШИБКА (дословно, для grep):
  File "hol_check\gui.py", line 94
IndentationError: unindent does not match any outer indentation level
СИМПТОМ: большой модуль (>10 КБ) не влезает в один вызов редактора, пишется блоками по
5–6 КБ. Первый блок заканчивается маркером вида `# === КАСТЬ N ===`, второй начинается с
`def метода(...)`. Метод оказывается на уровне модуля вместо уровня класса — Python видит
`def` с отступом 0 внутри тела класса и падает.
ПРИЧИНА (факт): разрыв вставлялся НЕ с отступом метода. Редактор вставлял текст как есть,
а отступ первой строки нового блока задавался автором — и при вставке он терялся.
ПРОФИЛАКТИКА:
1. **Разбивая файл, разбивать по границе МЕТОДА целиком.** Метод = его `def` + тело + пустая
   строка после; следующий блок начинается с нового метода, а не с `def` середины класса.
2. **После второй вставки — читать шов** (`read_files` с диапазоном вокруг маркера), пока
   в файле есть маркер `=== ЧАСТЬ N ===`.
3. Проверка синтаксиса ДО запуска: `python -c "import ast;ast.parse(open(f,encoding='utf-8').read())"`,
   либо просто запуск модуля — падение сразу видно.
4. Если `IndentationError` уже случился — искать в файле `def ` на нулевом отступе внутри класса
   (`Select-String -Pattern '^def '`), это и есть потерянный метод.
