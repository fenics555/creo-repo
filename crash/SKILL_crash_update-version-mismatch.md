# КРАХ: автообновление не гаснет — версия живёт в двух местах

## Подпись
`crash_update-version-mismatch` — «обновился, шапка новая, но программа вечно просит обновление и показывает старую версию».

## Что случилось (30.09.2026, PLM Reader)
1. Версия инструмента жила в ДВУХ константах: `APP_VERSION = "V32"` в `plm_reader.py` (шапка окна) и `VERSION = "V31"` в `engine.py`.
2. При выпуске V32 подняли только `APP_VERSION` → окно показало V32.
3. `check_updates()` возвращал «локальную» версию из `engine.VERSION` (= V31), а удалённую из `version.json` (= V32) → `available=True` вечно.
4. Пользователь видел: шапка V32, а окно «Доступна версия V32 (у вас V31)» — по кругу.
5. Вторая причина: `check_updates()` читал манифест по raw-URL, а CDN `raw.githubusercontent.com` кэширует надолго → удалённая версия «залипала»; скачивание файлов при этом шло через свежий API и упиралось в несовпадение SHA.

## Причина
Версия-двойник: любая копия `APP_VERSION` (движок, отчёт, манифест) со временем расходится с настоящей. Плюс манифест из кэшируемого источника.

## Урок
**Версия — ровно один источник** (`APP_VERSION`); все читают её, а не держат свою. **Манифест и файлы** тянуть из свежего источника (GitHub API), raw — только резерв.

## Профилактика
1. Версия берётся из одной константы; движок читает `APP_VERSION` (напр. разбором `plm_reader.py`), копий нет.
2. `make_version_json.py` читает ту же константу — манифест и шапка не разъедутся.
3. Манифест — через API (`Accept: application/vnd.github.raw`), raw как fallback.
4. Приёмка обновления: `check_updates()` даёт `local == remote` и `available=False`.
5. При выпуске версии поднимать ОДНУ константу; после пуша манифеста дать CDN/API ~минуту и сверить `local == remote`.
