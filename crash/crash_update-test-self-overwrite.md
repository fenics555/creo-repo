# КРАХ: тест автообновления затирает сам себя

## Подпись
`crash_update-test-self-overwrite` — «прогнал установку обновления на живом инструменте — потерял свежую правку».

## Что случилось (30.09.2026, PLM Reader V31)
1. В `engine.py` был добавлен источник обновления через GitHub **API** (`_fetch`, `UPDATE_API`) — потому что raw-CDN отдавал устаревшие файлы.
2. Для проверки запустил `sync_by_manifest()` **на живом инструменте** (`D:\AI\tools\agent\plm_reader`).
3. Механизм честно скачал из репозитория файлы и **заменил локальный `engine.py`** версией из репозитория — а там был ещё **старый** код (raw-only, без API).
4. Правка с API исчезла. Далее был закоммичен уже откаченный вариант.
5. Обнаружено только при сверке хешей и содержимого (`Select-String UPDATE_API` — «нет»).

## Причина
Механизм обновления по определению **перезаписывает файлы своей папки**. Если запустить его на рабочей копии, где идёт разработка, он заменит код на то, что уже лежит в репозитории (то есть на предыдущую версию). Тест разрушает предмет теста.

## Урок
**Тест установки обновления — только на КОПИИ инструмента, а не на живой.** Живая копия — это то, что обновляют, а не то, на чём проверяют.

## Профилактика
1. Перед тестом `sync_by_manifest` — скопировать инструмент в отдельную папку (`data\tmp` или урну) и гонять тест там.
2. Тест на живой копии допустим только когда локальный код **уже совпадает** с репозиторием (нечего терять) — и лучше всё равно на копии.
3. После теста — **сверить хеши** (`Get-FileHash` локально и в репозитории) и ключевые строки (`Select-String`), прежде чем коммитить.
4. Коммит после такого теста — только после проверки `git diff` на предмет откаченных правок.
5. Не путать: `check_updates()` безопасен (только читает), `sync_by_manifest()` — **пишущий** (заменяет файлы).

## Связи
*   Обновление инструментов — `Prog\SKILL_tool_template.md` (раздел автообновления).
*   Грабля raw-CDN: `raw.githubusercontent.com` кэширует надолго, cache-busting не помогает → источник — API.
*   CRLF/LF: SHA256 считать по нормализованному содержимому (`\r\n` → `\n`), иначе сверка ломается между локалью (CRLF) и репозиторием (LF).
