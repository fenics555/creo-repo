# crash_bat_no_dry_run_flag

**Подпись:** `Command failed: Command timed out after 30000ms` после запуска `.bat` «просто глянуть».

**Когда (02.10.2026, 11:47):** после правки шапки `RUN_p18_probe.bat` нога захотела
проверить, что файл рабочий, и выполнила `cmd /c RUN_p18_probe.bat --help`. **`.bat` не имеет
режима проверки** — он игнорирует любые аргументы и пошёл гонять батарею на 3 модели.

**Последствия:** команда истекла по таймауту 30 с, прогон убит (дерево процессов). Следы:
`log\ollama_checks\p20sm.log` создан (2504 байта), **новый `results_*.json` НЕ создан**,
маяк `p20sm_done.txt` не появился, правила не затронуты (прогон только читает их).
Ущерба нет, но потрачено время и сработала та же грабля, что в H2.

**Почему опасно:** архивный бат выглядит безобидно; запуск ради «проверки» воспроизводит
эксперимент, который может быть провальным или испортить состояние.

**Лечение:**
1. **Никогда не запускать `.bat` ради проверки синтаксиса.** Читать файл и проверять глазами.
2. Проверка синтаксиса bat — только на копии вне `data\tmp`, и то не запуском, а чтением.
3. Если `.bat` всё же надо проверить — сначала `Get-Content`, потом запуск через `Start-Process`
   (иначе таймаут команды убьёт прогон: `crash_command_timeout_kills_process_tree.md`).

**Профилактика в файле:** архивные баты получают шапку `АРХИВ. НЕ ЗАПУСКАТЬ ДЛЯ ПРИЁМКИ`
с указанием, что запускать вместо них. В `RUN_p18_probe.bat` такая шапка стоит с 11:47.
