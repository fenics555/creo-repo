# crash_command_timeout_kills_process_tree

ОШИБКА (дословно, для grep):
crash_command_timeout_kills_process_tree: Command failed: Command timed out after 30000ms — дерево процессов детача убито

**Подпись (дословно):** `Command failed: Command timed out after 30000ms`

**Когда (02.10.2026, 09:55, задача ночного оптимизатора, H2):** оптимизатор запущен так:
`cmd /c "python -X utf8 night_optimizer.py --run H2 --apply > out 2>&1"`. Оптимизатор отработал
правку (журнал: `09:55:05 ... правка применена`, `детач запущен: RUN_night_core.bat (PID 23436)`),
после чего перешёл в ожидание батареи. Команда ноги истекла по таймауту 30 с → **всё дерево
процессов cmd/python, включая батарею PID 23436, убито**. Правка осталась применённой, замера нет.

**Как обнаружено:** PID из лога оптимизатора (23436) не существует; `core.log` застыл на 14-й
строке; `core_done.txt` не появился. Ошибка инструмента при этом **не показывалась** — команда
просто вернула timeout.

**Почему это коварно:** агент видит «процесс идёт», опрашивает лог, а на деле опрашивает мёртвый
процесс. Три опроса подряд дали один и тот же счётчик строк (14) — выглядит как «медленная модель».

**Лечение (смена метода, работает):** детач запускать **отдельным** `Start-Process`, а не внутри
команды с ожиданием:
```powershell
Start-Process -FilePath 'cmd' -ArgumentList '/c','D:\AI\AGENT_SETTINGS\checks\RUN_night_core.bat' -WindowStyle Hidden -PassThru
```
Этот же приём спасён приёмку 9 моделей (PID 24116) — он отработал 19,5 минуты без убийства.

**Профилактика:**
1. Никогда не запускай детач (прогон > 60 с) через `run_commands` — только `Start-Process`.
2. PID ноги ≠ PID детача: уточняй `Get-CimInstance Win32_Process` по командной строке, а не
   по списку PID (в этом прогоне PID 6580 из моего опроса оказался `creo_pdf_gui.py`).
3. **Повторяющийся счётчик строк при «идущем» процессе — признак смерти, а не медлительности.**
   Проверяй живость PID, а не размер лога.
4. После таймаута команды проверяй журнал оптимизатора: если правка применена, а батарея мертва —
   перезапускай ТОЛЬКО батарею, повторный `--apply` не нужен (иначе правка применится дважды).
