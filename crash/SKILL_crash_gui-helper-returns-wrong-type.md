ОШИБКА (дословно, для grep):
`IndentationError` не была исходной ошибкой; исходная — окно не возвращалось:
`config_audit: проверка отработала в потоке` не печаталась, файл вывода ПУСТ, процесс python
не завершался (команда уходила в таймаут 30 с).
СИМПТОМ: `App()` зависает намертво, НО при этом `python ui_common.py` (selftest каркаса) проходит,
и простая проба `tk.Tk()` + `Frame` работает за 0.04 с. Окно «должно собираться», а не возвращается.
ПРИЧИНА (факт): помощник каркаса `ui_common.log_view()` возвращает кортеж
`(рамка, ФУНКЦИЯ log)`, а окно клало второй элемент в `self._log_widget` и вызывало
`self._log_widget.insert(...)`. Та же ошибка契约 в `ui_common.actions()`: возвращался список
результатов `pack()` (все `None`), а не сами кнопки, — падало
`AttributeError: 'NoneType' object has no attribute 'config'`.
Контракт помощника нигде не был записан — окно вызвало по смыслу, а не по сигнатуре.
ПРОФИЛАКТИКА:
1. **Подпись помощника — это контракт.** Прежде чем вызвать `ui_common.*`, прочитать `def`
   целиком и записать в комментарии окна, ЧТО ИМЕННО возвращается (виджет / функция / кортеж).
2. `.pack()` возвращает `None`. Если нужно отдать кнопку наружу — сначала `b = tk.Button(...)`,
   потом `b.pack(...)`, и в список класть `b`, а не результат `pack()`.
3. **Висяк ищется замером по шагам, а не чтением кода.** Проба с `print(..., flush=True)`
   после каждого виджета показывает шаг за шагом; запускать `python -u` (см. скилл про буфер).
4. `selftest()` каркаса проверяет ЛОГИКУ без окна. Он не ловит ошибку контракта — нужен
   ещё и живой `App()`.
5. Подозрение «окно зависло» проверять изоляцией: сначала каркас по кускам, потом `App()`.
