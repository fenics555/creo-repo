секретов, файл пользователей и память процесса.
ЛЕЧЕНИЕ (проверено 17.09.2026, цитаты в транскрипте):
1. Сбросить пароль из secrets.json при бегущем агенте:
   python -X utf8 -c "import json,users; pw=json.load(open('data/secrets.json',encoding='utf-8'))['admin_pw']; print(users.admin_reset_password('admin', pw))"
   Живой вывод: LOGINS: ['admin', '555', 'testadmin']; RESET ok: True; лог "admin password reset: admin".
   Список логинов пуст или ошибка — вернуть data\backup\pre_loginfix_users.json.bak в data\users.json и повторить.
2. Рестарт агента (память перечитает users.json, лок-аут обнулится). CREOSON и Ollama не трогать.
3. Проверка: POST /login {"login":"admin","pw":<секрет>} → ok=True + token; GET /status без токена → 200.
ПРОФИЛАКТИКА:
1. после любой смены пароля рестарт агента обязателен: диск и память процесса обязаны
   перечитаться вместе; без рестарта пароль живёт одновременно в двух мирах и не работает
   ни в одном.
2. учётка для входа — только из data\secrets.json (ключ admin_pw), одной попыткой;

3. при «нужен вход» не перебирать пароли: сверить логины (users.list_users) и сбросить
   пароль из secrets.json.
