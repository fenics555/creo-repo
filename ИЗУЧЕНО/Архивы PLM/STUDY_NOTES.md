## 1. КАК УСТРОЕН ЧИТАТЕЛЬ (выжимка изучения, 03.10.2026)

- `creo_read.py` — единый «лобовой» парсер: `parse_toc` (секции по `#UGC_TOC`),
  `real` (double big-endian по метке `e0 02 <имя> 00 ed`), `params` (NeuPrtSld + весь файл),
  `param/compose` (шаблоны `{ИМЯ}` `"текст"` `+`), `role`, `names` (входимость),
  `user_time`/`last_hist` (история: `f7 14 <user> 00 e2 <6 байт>` и `e1 f6 e1 <user> 00 e2 <6 байт>`,
  время в файле — UTC), `TAIL` (маркер ревизии `f7 ?? e3 <rev> 00 00 … Creo X.Y`).
- `engine.py` — движок: `collect_stat` (обход + size/mtime), `scan_item` (паспорт одного файла),
  `do_scan` (запись в базу), `scan_to_base` (замок → черновик в %TEMP% → публикация новой
  versioned-базы `plm_reader_ГГГГММДД_ЧЧММСС.db` + бэкап + зеркала).
- `plm_reader.py` — окно + два важных для нас разборара: `history()` (ревизия/дата/пользователь/
  компьютер/версия Creo) и `parse_changes()` (**что менялось**: размеры `dNNN` из
  `MTTyped_ModifyData`, параметры из `chg_param_arr`/`param_typed_data`), `changes_line()`.
- База PLM: `snapshots` (ключ — **путь** файла), `links`, `derived`, `changes`, `folders`, `meta`.
  Факт на 03.10.2026: 45 866 паспортов (из них 45 847 — файлы версий `.prt.N`), 70 028 записей
  `changes` (`new` 69 355 / `modify` 673), пути все `Z:\PTC\…`.

## 2. ГЛАВНАЯ НАХОДКА: ПОЧЕМУ АРХИВЫ НЕЛЬЗЯ ЛИТЬ В БОЕВУЮ БАЗУ

`engine.do_scan` при записи:

```sql
DELETE FROM links WHERE parent=? AND source='plm_tree'   -- связи по МОДЕЛИ
DELETE FROM derived WHERE child=? AND source='plm_tree'
```

Ключ `snapshots` — путь, но `links`/`derived` — по модели. Старый архивный срез, пройдя
движок, **перезаписал бы связи живой базы** своими (архивными) данными: изделие, которого
уже нет в `Z:\PTC\Work`, осталось бы с чужими связями, а переименованное — потеряло бы.
Значит архивы читаем ТОЛЬКО на чтение (`engine.scan_item`) и пишем в **отдельную** базу.

## 3. АРХИВЫ: ЧТО ЭТО ФИЗИЧЕСКИ

- 32 папки-даты (`29.03.2022` … `17.08.2026`), суммарно ~460 ГБ.
- Формат — **RAR5, многотомный** (part01…partNN; в 2022 — один `PTC.rar` на 22–29 ГБ,
  в 2023+ — `Work.partNN.rar` (13–18 томов) + `CREO-START.partNN.rar`).
- Скорость чтения шары `\\Backup` — **~10 МБ/с** ⇒ одна дата (13–29 ГБ) = 30–60 минут только
  на перекачку; все 32 даты = ориентировочно 15–30 часов.
- `7z` (21.07) RAR5 читает; `-sccUTF-8` влияет только на вывод в консоль (в списке имена
  «кракозябрами»), на диск пишет корректно — проверено пробой.

## 4. ГРАБЛИ (на них уже наступили)

1. `7z x … -i!Work\*.prt.*` и `e … *.prt.1` дали **«No files to process»** (маски не сработали
   на этом архиве). Помог `-ir!*.prt` (рекурсивное включение) — с ним извлечение пошло.
2. `7z l` на 13-томном архиве читает **все тома** — листинг одного `part01` занял ~3 минуты
   и 26 МБ вывода; нельзя ждать «быстрый список».
3. Многотомный архив нельзя читать том за томом вразрез: пока не прочитан заголовок следующего
   тома, 7z молчит (процесс жив, а вывода нет) — это норма, не зависание.
4. Правило `MANIFEST.md` №5: удаления вне `tmp`/`backup` — только словом хозяина. Инструмент
   удаляет **только то, что сам распаковал** в `D:\ARC_WORK\<дата>`; архивы и боевая база
   не трогаются ни при каких флагах.
