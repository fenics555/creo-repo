# УРОК: ОСИРОТЕВШИЕ РАННЕРЫ ЕДЯТ VRAM (14.10.2026)

## 1. Симптом (что видели живьём)
- Ночной прогон 16 правил пошёл **в 3 раза медленнее** (~1.5 ч/прогон вместо ~28 мин).
- `ollama ps`: **PROCESSOR = «24%/76% CPU/GPU»** (или 54/46) вместо **100% GPU**.
- Скорость **9.5 т/с** вместо **~90**.
- В прогонах — **18–19 ERROR из 79** (массовые падения/500).

## 2. Причина
- **Осиротевшие `llama-server.exe`** (раннеры) от **аварийно убитых** прогонов/сервера **не освободили VRAM**.
- Три процесса держали **~15 ГБ VRAM** → новым моделям не хватало → Ollama **оффлоадил слои на CPU** → медленно + ошибки.
- Спровоцировано **ручным `ollama serve`** (вместо штатного `ollama app.exe`) и `Stop-Process ollama` «на живую».

## 3. Диагностика (30 секунд)
```powershell
nvidia-smi --query-gpu=memory.used,memory.total --format=csv   # VRAM при простое должен быть ~0
nvidia-smi                                                      # в Processes ищи ЛИШНИЕ llama-server.exe
ollama ps                                                       # PROCESSOR должен быть 100% GPU
```

## 4. Лечение
1. Убить осиротевшие раннеры: `Get-Process llama-server -ErrorAction SilentlyContinue | Stop-Process -Force`.
2. Проверить VRAM: должно стать ~0.
3. Тест скорости: короткая генерация → ~90 т/с, `ollama ps` = **100% GPU**.

## 5. Профилактика (ЗАКОН)
- **НЕ поднимать сервер вручную** (`ollama serve`) — только штатное приложение **`ollama app.exe`**.
- **ПЕРЕД КАЖДЫМ прогоном/батчем** — проверка: `nvidia-smi` VRAM ~0 И `ollama ps` = 100% GPU.
- **Не убивать** прогоны/сервер `Stop-Process` без последующей зачистки `llama-server`.
- Батч стартовать ТОЛЬКО на чистой VRAM.

## 6. Цена ошибки
Потеряно **~7 часов** ночного прогона (v01–v03 признаны невалидными). Не повторять.
