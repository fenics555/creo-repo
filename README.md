# Дом агента Creo — база знаний, правила и скиллы

Структурированная база знаний, свод правил и библиотека скиллов для ИИ-агента, работающего с **PTC Creo Parametric** воспроизводимо и с опорой на живой факт: автоматизация CREOSON, прямое чтение бинарных моделей, переименование и копирование сборок, пары PDF↔чертёж, прецеденты крахов и протоколы выживания локальных моделей в IDE (Cline / VS Code).

## 🎯 Главные скиллы (корень репозитория)

Все базовые правила и навигация расположены непосредственно в корне `D:\AI\repo\`:

| # | Файл | Назначение |
|---|---|---|
| 1 | **`.clinerules`** | Живой закон среды Cline (зеркало `D:\AI\.clinerules`, синхронизируется через `sync_clinerules.bat`) |
| 2 | **`SKILL_index.md`** | Единая карта всех скиллов репозитория по доменам (вход навигации) |
| 3 | **`SKILL_local_agent_cline.md`** | Выживание локальной модели в Cline (контекст, транспорт, протокол `REVIVE`) |
| 4 | **`SKILL_edit_gotchas.md`** | Грабля-лист правки файлов и команд: BOM, кавычки, `;`, якоря, лимит 6 КБ, таймауты |
| 5 | **`SKILL_anti_hallucination.md`** | Защита от выдумок: уровни `ФАКТ / ПРЕДПОЛОЖЕНИЕ / НЕТ ДАННЫХ`, счет только с диска |
| 6 | **`SKILL_parallel_legs.md`** | Закон работы с Git в общем репозитории: коммит строго с pathspec, защита чужой работы |
| 7 | **`SKILL_noga_health.md`** | Контроль усталости модели (пороги вызовов 40/55/70, три признака деградации) |
| 8 | **`SKILL_handover.md`** | Протокол передачи эстафеты в `D:\AI\ЭСТАФЕТЫ\<ТЕМА>.md` |

*(Для автономного Python-агента используются `MANIFEST.md`, `AGENT_index.md` и `SKILL_agent_protocol.md`).*

## 🚀 Быстрый старт (Cline / VS Code)

1. Убедиться, что актуальный `.clinerules` скопирован в корень рабочей области `D:\AI\.clinerules` (при обновлении запускать `sync_clinerules.bat`).
2. Открыть новый чат в Cline — модель автоматически получает `.clinerules` в системный промпт и начинает ответ со строки-маяка `[START: dir=..., mode=...]`.
3. Для задач с правками или скриптами (`mode=FULL`) агент находит нужный скилл поиском (`Select-String`) по `SKILL_index.md`, читает его и выполняет задачу по правилам.

## 📐 Массовые свойства — ЧТЕНИЕ (проверено 04.10.2026)

Масса, объём и площадь поверхности хранятся в `.prt` и читаются прямо из сырых байт без запуска Creo.

**Раскладка записи:**
```text
PRO_MP_MASS   00  f8 01 f7 38 fb e3 f7 39 0e   e3 32  [тип]  [7 байт]  f1
PRO_MP_VOLUME ...                                   e3 32  2D    [7 байт] f1
PRO_MP_AREA   ...                                   e3 32  2D    [7 байт] f1
```
- `e3 32` — маркер «далее идёт значение».
- `[тип]` — `28` для `MASS`, `2D` для `VOLUME` и `AREA`.
- `7 байт` — big-endian IEEE-754 **double со срезанным ведущим байтом экспоненты**.
- `f1` — терминатор.

**Восстановление срезанного байта:**
1. `VOLUME` / `AREA` — ведущий байт восстанавливается из порядка величины (проверены `0x40` и `0x41`).
2. `MASS` — восстанавливается из плотности (`MASS / VOLUME` в диапазоне `6..9.5 г/см³`, сталь `7.85`). Проверено: `0x3F` → `0.21461530730689607` (`7.8500 г/см³`), `0x40` → `6.6861510413184719` (`7.9000 г/см³`).

**Эталонная проверка через JLINK:**
```bat
call .\mass_probe.bat Z:\PTC\Work\00080\00080-03.prt
-> 00080-03.prt  MASS=0,21461530730689607  VOLUME=27339,529593235176  AREA=13275,370841291067
```

## 🛡️ Базовые соглашения дома

- **Кириллица и кодировки:** verbatim-русский записывается в файлы только через редактор (`editor`) или скрипты в явной кодировке UTF-8; консоль кириллицу через инлайн-команды не несёт.
- **Безопасность данных:** сетевые диски (`Z:\PTC` и общие шары) открыты строго только для чтения; любые необратимые правки выполняются только после бэкапа.
- **Фиксация сбоев:** любой инфраструктурный сбой или петля диагностируется по протоколу `REVIVE` и фиксируется в `crash/` со счётчиком повторов.
