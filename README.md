# Дом агента Creo — база знаний, правила и скиллы

Структурированная база знаний, свод правил и библиотека скиллов для ИИ-агента, работающего с **PTC Creo Parametric** воспроизводимо и с опорой на живой факт: автоматизация CREOSON, прямое чтение бинарных моделей, переименование и копирование сборок, пары PDF↔чертёж, прецеденты крахов и протоколы выживания локальных моделей в IDE (Cline / VS Code).

## 🧠 Архитектура правил и скиллов v3.0 (Capacity-Based)

Дом переведён на принцип **«тонкого ядра»**: `.clinerules` несёт только законы и красные линии, детали — в скиллах. Ключевые идеи v3.0:

- **Контроль когнитивной ёмкости окна (`num_ctx`).** Цветовые зоны (`SKILL_noga_health.md` §2.1): 0–45% ЗЕЛЁНАЯ · 45–70% ЖЁЛТАЯ (принудительный `ДИСПЕТЧЕР`) · 70–80% ОРАНЖЕВАЯ (Downshift + подготовка эстафеты) · >80% или 1-е сжатие КРАСНАЯ (СТОП). Каждый ответ-остановка завершается диагностическим футером `[НОГА: ...]`.
- **Две независимые оси режимов (комбинируются).** **Темп** (`ПОШАГОВО` / `АВТОНОМНО`) × **Исполнитель** (главное окно / `ДИСПЕТЧЕР`). `АВТОНОМНО` идёт до конца без остановок (уточнения копятся и выдаются разом в конце); `ДИСПЕТЧЕР` может остановиться для уточнения. Диспетчер = 4 роли микро-субагентов (**Библиотекарь, Разведчик, Арбитр, Тестировщик**) с автоматической веткой **Solo-Chunked** для VS Code Cline без `spawn_agent`. Пример комбинации: `ДИСПЕТЧЕР АВТОНОМНО`.
- **Три команды-артефакта:** `ПЛАН` (`PLAN_<ТЕМА>.md`), `ЭСТАФЕТА` (`ESTAFETA_<ТЕМА>.md`) и новый `ПРОМПТ` — стартовый промпт для новой ноги по стандарту `SKILL_start_prompt.md` (7 блоков, обязательный обряд старта — «первым действием прочти `.clinerules`»).
- **Единый источник знаний:** Librarian-Guided Read (субагент-**Библиотекарь** → узкий диапазон `20–40` строк) или Solo-Chunked (`Select-String` + `≤ 80` строк).

Регламенты: `.clinerules` §2, `SKILL_local_agent_cline.md` §2, `SKILL_noga_health.md` §2.1, `SKILL_handover.md` §2–3, `SKILL_start_prompt.md`.

## 🛰 Сторож петель ноги (`loop_watch.py`)

**Что это:** внешняя программка — питон-скрипт `D:\AI\tools\agent\loop_watch.py`. Онлайн-детектор зацикливания ног Cline.

**Зачем:** модель **в моменте не видит свою петлю** (каждый ход для неё «первый»). Сторож смотрит её историю **сбоку** и сигналит.

**Схема работы:**
1. Находит сессию: `--session <id>` или **новейшую** папку в `%USERPROFILE%\.cline\data\sessions\` по `mtime` — с префиксом `session_` ИЛИ без него (папки `*__agent_*` пропускаются — они принадлежат субагентам). Если основного `<id>.messages.json` нет — читает путь из меты `<id>.json` (`messages_path`).
2. Разбирает историю как пары «вызов инструмента → результат».
3. **Петля №1 (tool-loop):** один и тот же `инструмент+аргументы` упал **≥2 раз** (`THRESHOLD`) — только в **окне последних `WINDOW` (=12) вызовов**, чтобы старые ошибки не давали вечный ALERT. Ошибкой считается результат ≤ `ERR_MAX_LEN` (=4000) с ключом из `ERR_KEYS`: **крупные чтения файлов** со словом «error» ложных срабатываний **не** дают.
4. **Петля №1b (cycle-loop):** качели `A-B-A-B` (`CYCLE_PAIRS`=2) в окне — ловит чередующийся цикл даже без текста ошибок.
5. **Петля №1c (error-loop):** ≥`ERR_SIG_THRESHOLD` (=3) результата в окне упали с **одинаковой подписью ошибки** (`err_signature`: цифры/пробелы нормализованы) → **ALERT** — ловит повтор одной падающей операции даже при разном `input` (когда hash tool-loop не срабатывает).
6. **Петля №1d (fail-loop):** ≥`FAIL_THRESHOLD` (=3) **любых** провала инструментов в окне (без требования одинаковой подписи) → **ALERT** — ловит «мятущийся» провал-цикл (напр. переписывание своего же тест-скрипта, где каждая ошибка своя).
7. **Петля №2 (text-loop):** в последних `TXT_WINDOW` (=6) ответах ассистента `TXT_REPEAT` (=3) раза повторяется одинаковый текст (≥20 символов) → **ALERT даже без `aborted`**.
8. **Петля №3 (fallback, aborted):** последний ход сессии в `%USERPROFILE%\.cline\data\logs\code.log` = `finishReason:"aborted"` → **ALERT**.
9. Пишет сигнал в `D:\AI\log\urn\cline\LOOP_ALERT.txt` (с пометкой `kind=tool-loop|cycle-loop|error-loop|fail-loop|text-loop|aborted`); в режиме-цикле — подпись события + `COOLDOWN_SEC` (=20 с) против спама.

**Запуск:**
```
python D:\AI\tools\agent\loop_watch.py [--session <id>]   # цикл ~4 с
python D:\AI\tools\agent\loop_watch.py --once             # разовая проверка (новейшая сессия)
```

**Дополнительные детекторы (по умолчанию ВЫКЛЮЧЕНЫ — включаются флагами):**
- `--stall` — **GENERATION_STALL**: файл сессии не растёт `STALL_SEC` (=110 с), но сессия была активна < `RECENT_SEC` (=300 с) и бэкенд отвечает → ALERT. Проба бэкендов: `llama.cpp:8080/health`, `vLLM:8000/health` (+ `/health/decode` 503 = застой), `Ollama:11434/api/ps`, `LM Studio:1234/v1/models`, `text-generation-webui:5000/v1/models`. Любой HTTP-ответ (даже 404/503) = бэкенд жив. Таймаут — `--probe-timeout`; форс без сети для тестов — `--probe-reachable yes|no`.
- `--spike` — **CONTEXT_SPIKE**: файл сессии вырос на `≥ SPIKE_BYTES` (=64 КБ) за один тик → ALERT. В `--once` предыдущий размер задаётся `--prev-size N`; порог — `--spike-bytes N`.

**Тестовые ключи** (прогоны на фикстурах, `D:\AI\tools\agent\loop_watch_test.py`): `--sess-dir <dir>`, `--log <file>`, `--alert <file>`, `--window N`, `--txt-window N`, `--txt-repeat N`, `--stall-sec N`, `--recent-sec N`, `--spike-bytes N`, `--prev-size N`, `--probe-reachable yes|no`, `--probe-timeout F`.

**Важно:** это чтение **локальных данных Cline** (не диск `Z:`) — разрешения владельца не требует. Пороги (`THRESHOLD/ERR_SIG_THRESHOLD/FAIL_THRESHOLD/WINDOW/TXT_WINDOW/TXT_REPEAT/CYCLE_PAIRS/ERR_MAX_LEN/COOLDOWN_SEC/STALL_SEC/RECENT_SEC/SPIKE_BYTES`) и ключи ошибок (`error/not found/too large/no replacement/не найден/ошибк`) — в начале скрипта.

## 🚀 Быстрый старт (Cline / VS Code)

1. Убедиться, что актуальный `.clinerules` скопирован в корень рабочей области `D:\AI\.clinerules` (при обновлении запускать `sync_clinerules.bat`).
2. Открыть новый чат в Cline — модель автоматически получает `.clinerules` в системный промпт и начинает ответ со строки-маяка `[START: dir=..., mode=...]`.
3. Режим задаётся словами (оси комбинируются): темп (`ПОШАГОВО` / `АВТОНОМНО`) × исполнитель (`ДИСПЕТЧЕР`), например `ДИСПЕТЧЕР АВТОНОМНО`. Для задач с правками агент находит нужный скилл через `SKILL_index.md`, читает и выполняет по правилам. Команды-артефакты: `ПЛАН`, `ЭСТАФЕТА`, `ПРОМПТ`.

## 📐 Массовые свойства — ЧТЕНИЕ (проверено 04.10.2026)

Масса, объём и площадь поверхности хранятся в `.prt` и читаются прямо из сырых байт без запуска Creo.

**Раскладка записи:**
```text
PRO_MP_MASS   00  f8 01 f7 38 fb e3 f7 39 0e   e3 32  [тип]  [7 байт]  f1
PRO_MP_VOLUME ...                                   e3 32  2D    [7 байт] f1
PRO_MP_AREA   ...                                   e3 32  2D    [7 байт] f1
```
- `e3 32` — маркер «далее идёт значение».
- `[тип]` — `28` для `MASS`, `2D` для `VOLUME` и `AREA`.
- `7 байт` — big-endian IEEE-754 **double со срезанным ведущим байтом экспоненты**.
- `f1` — терминатор.

**Восстановление срезанного байта:**
1. `VOLUME` / `AREA` — ведущий байт восстанавливается из порядка величины (проверены `0x40` и `0x41`).
2. `MASS` — восстанавливается из плотности (`MASS / VOLUME` в диапазоне `6..9.5 г/см³`, сталь `7.85`). Проверено: `0x3F` → `0.21461530730689607` (`7.8500 г/см³`), `0x40` → `6.6861510413184719` (`7.9000 г/см³`).

**Эталонная проверка через JLINK:**
```bat
call .\mass_probe.bat Z:\PTC\Work\00080\00080-03.prt
-> 00080-03.prt  MASS=0,21461530730689607  VOLUME=27339,529593235176  AREA=13275,370841291067
```

## 🛡️ Базовые соглашения дома

- **Кириллица и кодировки:** verbatim-русский записывается в файлы только через редактор (`editor`) или скрипты в явной кодировке UTF-8; консоль кириллицу через инлайн-команды не несёт.
- **Безопасность данных:** сетевые диски (`Z:\PTC` и общие шары) открыты строго только для чтения; любые необратимые правки выполняются только после бэкапа.
- **Фиксация сбоев:** любой инфраструктурный сбой или петля диагностируется по протоколу `REVIVE` и фиксируется в `crash/` со счётчиком повторов.
