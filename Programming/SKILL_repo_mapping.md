## СТАТУС: ЗАВЕРШЕНО (ЭТАП 2)

## КОНЦЕПЦИЯ
Создание "карты репозитория" (Repo Map) — это метод сжатого представления всей структуры проекта в ограниченном контекстном окне. Вмеме того чтобы загружать содержимое всех файлов, агент загружает только их "скелет" (иерархию важных идентификаторов).

Это позволяет агенту "видеть" проект целиком, понимать связи между модулями и быстро находить нужные места, не тратя токены на чтение всего кода.

## ПРИНЦИПЫ РЕПО-КАРТЫ (на базе Aider)

### 1. Иерархическое представление (Tags)
Карта — это не список файлов, а список **тегов** (идентификаторов):
- `filename: line_number: tag_name`
- Примеры тегов: имена классов, названия функций, методы, важные переменные.

### 2. Приоритезация (Ranking)
Когда проект слишком велик, карта должна выбирать только самое важное:
- **Active Files (Приоритет №1)**: Файлы, с которыми агент работает прямо сейчас (текущие файлы в контексте).
- **Important Identifiers (Приоритет №2)**: Самые часто используемые или структурно важные теги.
- **Contextual Density**: Чем выше плотность важных тегов в файле, тем выше шанс, что он попадет в карту.

### 3. Управление лимитами (Token Budgeting)
Карта должна иметь строго заданный лимит токенов (`max_map_tokens`).
- Если карта превышает лимит $\rightarrow$ применяем понижающий коэффициент (rank reduction) или отсекаем менее важные файлы.
- **Цель**: Получить максимально информативный "скелет" при минимальном расходе контекста.

## АЛГОРИТМ ПОСТРОЕНИЯ (для Агента)

Если тебе нужно "понять структуру проекта", не читай все файлы. Выполни следующий алгоритм:

1. **Scan**: Быстро пробегись по структуре директорий (через `ls` или `dir`).
2. **Identify Core**: Найди ключевые файлы (entry points, main modules, config).
3. **Extract Skeleton**: Для ключевых файлов извлеки только имена функций/классов (используй `tree-sitter` или `grep-ast` паттерны).
4. **Build Map**: Сформируй краткий список:
   ```
   src/main.py:
     class Engine:
       def start()
       def stop()
   src/utils.py:
     def helper()
   ```
5. **Verify**: Если при поиске что-то не найдено $\rightarrow$ только тогда расширяй карту (добавляй больше файлов).

## ПРАВИЛА ПРИМЕНЕНИЯ ДЛЯ АГЕНТА
- **Никогда не запрашивай "весь код проекта"**. Всегда запрашивай "карту проекта" или "скелет".
- **Используй карту как компас**. Если ты заблудился в проекте, начни с построения карты.
- **Обновляй карту**. Если ты создал новый файл или функцию $\rightarrow$ обнови свою внутреннюю карту (Core Memory).
