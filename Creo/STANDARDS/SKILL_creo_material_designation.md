## 6. 🔴 ГРАБЛИ ЭТОЙ ТЕМЫ (живые, 05.11.2026)

### 6.1. ДВА ПАРАМЕТРА-ДВОЙНИКА: `МАТЕРИАЛ` и `Материал`
В библиотеке исторически **две схемы именования**: часть файлов имеет `МАТЕРИАЛ` (заглавными),
часть — `Материал` (как слово). Замер: 68 файлов имели только заглавный, 495 — только строчный.

**⇒ ПРАВИЛО: заполнять ОБА параметра одинаковым значением.** Тогда любой шаблон
(`&material.param.МАТЕРИАЛ` или `&material.param.Материал`) выведет материал.

### 6.2. 🔴 PowerShell: `-eq` НЕ РАЗЛИЧАЕТ РЕГИСТР!
`"Name = МАТЕРИАЛ" -eq "Name = Материал"` → **True** (PowerShell игнорирует регистр!).
Из-за этого скрипт «видел» `МАТЕРИАЛ` там, где был только `Материал`, и **не добавлял** нужный.

**⇒ ПРАВИЛО: для сравнения строк/имён параметров — только `-ceq`** (case-sensitive).
То же для `-ne` → `-cne`, `-like` → `-clike`.

### 6.3. Поля-двойники у материала (карта)
| Имя | Смысл |
|---|---|
| `МАТЕРИАЛ` (заглавные) | **для чертежа** (старые файлы) |
| `Материал` (как слово) | **для чертежа** (другие файлы) |
| `МАТЕРИАЛ_МАРКА` | марка отдельно |
| `МАТЕРИАЛ_СТАНДАРТ` | ГОСТ отдельно |
| `PTC_MATERIAL_DESCRIPTION` | Описание (для инженера, НЕ для чертежа) |

### 6.4. Regex `Name\s*=\s*МАТЕРИАЛ\s*$` ловит `МАТЕРИАЛ_МАРКА`
Без границы слова `$` (или `\b`) поиск «МАТЕРИАЛ» находит и `МАТЕРИАЛ_МАРКА`, `МАТЕРИАЛ_СТАНДАРТ`.
Считать/менять — только точным сравнением строки (`-ceq`).

### 6.5. 🔴 ПОДПИСЬ ЕДИНИЦЫ ВРЁТ — ВЕРИТЬ ЧИСЛУ И ФИЗИКЕ (06.11.2026)

В `.mtl` поле `PTC_MASS_DENSITY` = `число + подпись`. **Подпись НЕ отражает реальную единицу:**

| Записано | Реально | Правильно |
|---|---|---|
| `2.710000e-09 tonne/mm^3` | тонна/мм³ | 2710 kg/m³ ×1e12 |
| `3.670000e-06 tonne/mm^3` | **kg/mm³** (подпись врёт) | 3670 kg/m³ ×1e9 |
| `7800.0 tonne / mm^3` | **kg/m³** (подпись врёт) | 7800 kg/m³ ×1 |
| `2.78 g / cm^3` | грамм/см³ | 2780 kg/m³ ×1000 |
| `0.00000285 g / cm^3` | **kg/mm³** (подпись врёт) | 2850 kg/m³ ×1e9 |

**ПРАВИЛО:** коэффициент перевода выбирать по **физическому диапазону 50..25000 kg/m³**.
Перебрать 1e12, 1e9, 1e6, 1e3, 1 — взять тот, что даёт осмысленную плотность.
Ни один материал не выходит за 50..25000 kg/m³ — это надёжный фильтр.
**Замер 06.11.2026:** 182 файла с `mmKS` но граммовой плотностью, 98 «битых» подписей — исправлены.

## 8. 🔴 ГРАБЛИ ВОССТАНОВЛЕНИЯ (06.11.2026, 2501 файл)

### 8.1. `Type = Real` — значение БЕЗ КАВЫЧЕК
**Эталон владельца** (`d_16.mtl` в бэкапе 05.11): `Default = 2.78 g / cm^3` — **без кавычек**.
Скрипт, который пишет `Default = '2.78e-06 kg/mm^3'` (в кавычках), даёт Creo **строку вместо числа** —
параметр не применяется в расчётах.
**Правило:** `Type = String` → в кавычках; `Type = Real` / `Type = Integer` → **БЕЗ кавычек**.

### 8.2. БЛОК `МАТЕРИАЛ_МАРКА` МОЖЕТ БЫТЬ РАЗОРВАН
Симптом в файле:
```
{
  $110х1'          ← обрывок Default, строки Name/Type/Default потеряны
  Access = Full
},
```
Причина — вставка нового блока **внутрь** существующего (между `{` и `Name = ...`).
**Лечение:** найти блоки с ПУСТЫМ `Name` и удалить их целиком (данные `МАТЕРИАЛ`/`Материал`
в файле целы отдельно), затем пересобрать `МАТЕРИАЛ_МАРКА` из `МАТЕРИАЛ` минус ГОСТ.

### 8.3. ЗАПЯТАЯ ПОСЛЕ `}` ОБЯЗАТЕЛЬНА
`}` без `,` перед следующим `{` — Creo может не прочитать файл. Скан:
```powershell
# "}" без запятой, а следующая непустая строка — "{"
```
Найдено 3 файла из 2501 (`08x18h10`, `chugun_chvg45`, `chugun_vch50`).

### 8.4. ГОСТ 380-2005 — ТОЛЬКО ДЛЯ СТАЛИ ОБЫКНОВЕННОГО КАЧЕСТВА
Массовая ошибка: `ГОСТ 380-2005` подставлен 50 файлам, из них 48 — неверно.

| `Ст0…Ст5` | **380-2005** ✅ единственный правильный случай |

### 8.5. ПОДПИСЬ ЕДИНИЦЫ ВРЁТ — ВЕРИТЬ ЧИСЛУ И ФИЗИКЕ
(см. §6.5) `tonne/mm^3` / `g/cm^3` в подписи не отражает реальную единицу.
Коэффициент определять подбором: найти k из {1e12, 1e9, 1e6, 1e3, 1} такой, что `v*k` попадает
в физический диапазон 50…25000 kg/m³.

### 8.6. ДВА ПАРАМЕТРА-ДВОЙНИКА `МАТЕРИАЛ` / `Материал`
`МАТЕРИАЛ` (заглавные) — строка для чертежа по ЕСКД.
`Материал` (строчные) — исторический дубль, встречается в 563 файлах.
**Правило:** значения должны совпадать. Синхронизировать `Материал := МАТЕРИАЛ`
(ЕСКД-запись главнее, она с ГОСТом).

### 8.7. ПРАВИЛО МАРКИ (извлечение из МАТЕРИАЛ)
`МАТЕРИАЛ` = `[сортамент] [тип] [марка] [ГОСТ]`. Для `МАТЕРИАЛ_МАРКА`:
1. Убрать стандарт (`ГОСТ`/`ТУ`/`ОСТ` + номер).
2. Снять префикс-тип (`Сталь`, `Чугун`, `Резина`, `Древесина`, `Сплав`, `Пластмасса`, `Прочие`) — повторять.
3. Снять прилагательное (`высоколегированная`, `оловянная`, `литейный`, `деформируемый`).
4. Убрать хвостовые `,` и `-`.

### 🔴 ВОПРОС: нужен ли `default_hatch_type pat` для ГОСТ-узоров? ОТВЕТ: НЕТ

**Проверено 06.11.2026 по первоисточникам.**

**1. Что делает опция** (дословно из `configoptions.pdf` Creo 13):
> «`xch` — устанавливает собственный формат Creo (`.xch`) в качестве типа для штриховки **по умолчанию,
> создаваемой в моделях и чертежах**; `pat` — устанавливает формат PAT»

⇒ Опция решает, **в каком формате Creo сохраняет НОВЫЕ штриховки, создаваемые пользователем**.
Она НЕ управляет связью материал→штриховка через `PTC_XHATCH_FILE`.

**2. Эталонный набор практика (Creo 8) — тоже `XCH`** при наличии полного `gost_patterns.pat`:
```
line 168: hatch_pattern_cfg_file $pro_stds\crosshatch\hatch_pattern_scale.cfg
line 170: default_hatch_type XCH
line 185: pro_crosshatch_dir $pro_stds\crosshatch
```

**3. `.pat` УЖЕ подключён и работает.** Наш `hatch_pattern_scale.cfg` содержит масштабы для
**108 узоров**: `GOST` 41 · `iso` 25 · `WOOD` 12 · `AEC` 11 · `JIS` 11 · `ansi` 8.
Примеры: `GOST,ГОСТ 2.306 бетон` · `GOST,ГОСТ 2.306 древесина (торец)` ·
`GOST,ГОСТ 2.306 металлы и твёрдые сплавы` · `ansi,ANSI31`.
⇒ 43 ГОСТ-узора доступны **с правильными масштабами**, без смены `default_hatch_type`.

**4. Почему `pat` как default — ОПАСНО:**
| Риск | Последствие |
|---|---|
| 2578 материалов ссылаются на `.xch` | новые штриховки пойдут в другом формате |
| Имена в `.pat` другие (`ГОСТ 2.306 металлы и твёрдые сплавы`) | связь по имени материала (`xch_gost_metally`) **сломается** |
| Справка: в PAT «**невозможно сохранить изменения**» | нельзя править узор |

### ✅ ИТОГ: оставляем `XCH`. `.pat` — библиотека узоров для ручного выбора.
**`.xch`** — автоматика (материал → штриховка), **`.pat`** — ручной выбор в Hatch Designer.
