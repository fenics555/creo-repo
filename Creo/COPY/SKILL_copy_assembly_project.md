# УМНАЯ КОПИЯ ПРОЕКТА (СБОРКИ) ЧЕРЕЗ CREOSON — рабочий алгоритм
Источник метода: `SKILL_copy_rename.md` (+ `SKILL_creoson_write_rules.md`,
`SKILL_creoson_rename_mechanism.md`, `SKILL_davydovka_creoson_map.md`).
Живая реализация: `D:\AI\PROBA\smartcopy.py` (прогон в полигоне 22.09.2026).

## Шаги (семь)
0. Корень открыть из рабочей папки; собрать состав: `bom:get_paths` (asm/prt рекурсивно;
   `children` приходит словарём ИЛИ списком — обрабатывать оба).
1. Добавить спутники: `<имя>.drw`, `<имя>_mfg.asm`, `<имя>_mfg.drw`, `<имя>_wp.prt` —
   только если реально лежат в папке (`creo:list_files`).
2. temp-папка → `file:backup` каждого файла, ГЛУБОКИЕ ПЕРВЫМИ. Ловушка: backup требует
   ОТКРЫТУЮ модель (`File '<name>' was not open.`) → сначала `file:open`.
3. Оригиналы выгрузить (`file:erase`) — иначе Creo подставит их вместо копий.
4. `creo:cd temp`; `file:open` копий (в temp они со СТАРЫМИ именами).
5. `file:rename {onlysession:true}` в порядке: экземпляры (глубокие первыми) → generic →
   сборки → ЧЕРТЕЖИ ПОСЛЕДНИМИ. `new_name` — С расширением (пример спеки `box_flat.prt`).
6. `file:save` снизу вверх (детали → сборки → чертежи).
7. `creo:cd` обратно; выгрузить копии. Старые имена в temp — уводить в backup, НЕ удалять.

## Семейства (многоуровневые/вложенные)
- Копия generic несёт таблицу семейств ЦЕЛИКОМ (копируется диск-файл). Экземпляры
  адресуются составным именем `ЭКЗЕМПЛЯР<GENERIC>.PRT`; для вложенной строки generic в имени —
  ПРОМЕЖУТОЧНЫЙ экземпляр, а файл на диске называется по верхнему generic (пробовать оба имени).
- Порядок: от САМЫХ ГЛУБОКИХ вложенных экземпляров к верхним → generic → чертежи.
- Состав/дерево: `familytable:list_tree`, `file:list_instances` (у не найденного в путях
  поиска файла `list_instances` → null), `file:has_instances`.
- Механика Давыдовки (`copyCreoFamilyModels`): `Copy()` generic → временные `t_`-имена членов
  в памяти (чтобы копия не подтянула оригиналы) → retrieve экземпляров копии → rename → save →
  вернуть оригиналы из `t_`. Fallback `copyFamilyTableStructure` — пересборка колонок/строк
  cell-by-cell, если таблица не поехала с файлом. CREOSON-аналог: `file:backup` generic
  (таблица едет с файлом) + onlysession-renames по порядку.

## Мануфактуринг (спутники)
- В CREOSON `mfg-*` функций НЕТ. Обработка — это сборка (*.asm); её заготовка и оснастка
  копируются вместе, ссылочные модели во временную папку обязаны попасть (иначе не соберётся).
- Файловый уровень: `<имя>_mfg.asm` (ЧПУ-обработка), `<имя>_mfg.drw` (карта наладки),
  `<имя>_wp.prt` (заготовка) — входят в план автоматически при наличии рядом.
- Признак обработки — назначение компонентов (есть заготовка/ссылочная модель), НЕ тип модели.

## Правило имён (шаблон)
Одна строка `A_old=A_new` — замена префикса во ВСЕХ именах плана (не пофайлово). Длина
префикса — на усмотрение пользователя. Имя копии обязано отличаться от исходного; уже
открытая модель с новым именем = отказ.

## Живые факты проб (22.09.2026, полигон `D:\AI\PROBA`)
- **Сборка + детали**: `amf75838.asm` + 6 деталей, правило `amf`→`amk`: все
  backup/open/rename/save = `error:false`; копия `amk75838.asm` ссылается на
  `AMK74096_1_R`, `AMK74096_6/3`, `AMK74419`, `AMK74872_2`, `AMK74146` (проверено `bom:get_paths`).
- **Деталь + одноимённый чертёж**: `23-1017gri-01r.prt/.drw` → `23-1017gri-k-01r.prt/.drw` — ОК.
- Ловушки: `file:backup` без открытой модели → `File '<name>' was not open.`; `file:rename`
  `new_name` — С расширением; `file:save` пишет НОВУЮ версию `name.ext.N`, старая версия имени
  остаётся в temp (уводить в backup); `file:open` отдаёт `dirname` с удвоенным диском (`D:D:\...`).
- **Кириллица**: пути/имена с кириллицей через PowerShell `Invoke-RestMethod` искажаются
  (`?` вместо букв: `Directory does not exist: Z:/PTC/CREO-START/?????????/???????`). Кириллицу
  гонять только из Python (JSON + UTF-8), как в `smartcopy.py`.
- **Семейство (generic с таблицей)** — `df-stp2-gdf.prt` → `df-stp2k-gdf.prt` (backup →
  `file:rename {onlysession:true}` → `file:save`): все `error:false`; копия СОХРАНИЛА таблицу —
  `has_instances=true`, `list_instances` = `DF-STP2-GDF-01/02/03`, `familytable:list_tree` total=3.
  Имена СТРОК (исполнений) при копии НЕ меняются: в CREOSON нет rename-instance, есть
  `familytable:add_inst` / `replace` / `set_cell` / `delete_inst` / `create_inst`.
- **mfg-набор** — `ст-чпу-2-mfg.asm` → `ст-чпу-к-2-mfg.asm`, правило `ст-чпу`→`ст-чпу-к`: 13 моделей
  (mfg-сборка + ссылочная сборка `ст-чпу-2.asm` + 5 деталей + 6 чертежей), ВСЕ `error:false`.
  Структура обработки: `bom:get_paths` даёт root → компонент `ст-чпу-2.ASM` (ссылочная сборка) →
  её детали; копия ссылается на новые имена. Пример на `Z:`:
  `Z:\PTC\Work\000_02 ST Стеклосфера\СТ-ЧПУ-02 Угловой стол многофункциональный\ст-чпу-2-mfg.asm`.
- **Кириллица**: имена моделей кириллические → гонять ТОЛЬКО из Python (UTF-8); в консоли
  PowerShell они видны как `?`, но JSON и файлы корректны.
- Дополнительно: backup чертежей тянет в temp форматы (`a3.frm`, `a4.frm`); старые имена копий
  остаются в temp — уводить в backup; у семейств рядом появляются ускорители `*.tph`/`*.xpr`.
- Итог: живьём проверены ВСЕ ветки — сборка+детали, деталь+чертёж, семейство (generic), mfg-набор.
- Размеры проверенных таблиц: `df-stp2-gdf` — 3 строки, `df-stp2-vz` — 5, `df-stp2-vp` — 13 (все
  ПЛОСКИЕ, `children[].total=0`); у `df-stp2-vdf/sh-01/sh-02` строк нет.
- **ВЛОЖЕННОЕ (многоуровневое) семейство** — `pin_split.prt` из библиотеки КБ
  `Z:\PTC\CREO-START\Libraries\Библиотека_стандартных_изделий` (папка `НЕ_ПОЛЬЗОВАТЬСЯ`): generic →
  промежуточное исполнение `PIN_SPLIT-DIN1481X10<PIN_SPLIT-DIN1481>` (у него `has_instances=TRUE`,
  т.е. это под-generic) → листья `…din1481x10x100`. Копия: `backup` → `rename onlysession` → `save`
  → `pin_splitk.prt`; таблица СОХРАНЕНА (`has_instances=true`, 3 верхних исполнения).
- ЛОВУШКА: `familytable:list_tree` на БОЛЬШИХ библиотечных семействах (сотни строк, `din912`,
  `pin_split`) — долго/висит; вложенность проверять через `file:has_instances` на промежуточном
  исполнении (составное имя `ИСПОЛНЕНИЕ<GENERIC>`).
- ЛОВУШКА: ПРЕРЫВАНИЕ долгого вызова CREOSON (kill своего скрипта) подвешивает JVM/Creo
  (порт слушает, `connect` таймаутит) → сброс creoson+Creo ПО PID и подъём заново.
