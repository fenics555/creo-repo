# ЧТЕНИЕ ФАЙЛОВ CREO «В ЛОБ» (файл напрямую, без Creo и CREOSON)

**Зачем:** не открывать Creo (тяжело, долго, занимает лицензию/железо), не мусорить в рабочих
папках (вариант «история → в файл» пишет HTML рядом с моделью), читать весь склад массово,
работать когда Creo закрыт. Приём проверен домом: таблицы семейств читались из файла ещё в Давыдовке.

## 1. История изменений («Инструменты → Исследовать → История файла»)
Данные лежат **внутри модели**, сервер не нужен. Найдены ДВА вида записи (Creo 12 и Creo 11):

**Раскладка A (Creo 12, `.asm` — проверено на `liteika_hts_mm.asm.1`):**
```
… <имя пользователя> \0  e2 | sec min hour_utc day (month-1) (year-1900) | f7 31 e3 | "РЕВИЗИЯ" \0\0
   <текст UTF-8> \0 … "Creo X.Y.Z.W" …
```
**Раскладка B (Creo 11, `.prt`):**
```
user_name \0 USER \0 … modif_time \0 (tm_sec tm_min tm_hour tm_mday tm_mon tm_year — по одному байту)
   … typed_data(MdlStored) \0 … rev_string \0 <номер> \0 … comment \0 <текст UTF-8> \0 …
```
**Формат времени:** однобайтовые `sec, min, hour, day, month-1, year-1900`; **время в файле — UTC**
(локальное КБ = UTC + 3). Проверка: LITEIKA `08:10:56 UTC` = `11:10:56` местного ✓.
**Тип операции:** `typed_data(MdlStored)` = «Модель сохранена» (в файле описан один раз в словаре типов).

**Проверено (эталон — отчёт Creo хозяина, совпало до минуты):** `LITEIKA_HTS_MM.ASM` →
ревизии **718 / 713 / 712 / 710 / 708**, пользователь `USER`, компьютер `frezer-4`,
05.08.2026 11:10:56 / 04.08 17:03:30 / 16:50:45 / 15:55:08 / 15:50:25 ✓
**Код-прототип (работает, раскладка A):** `D:\AI\log\urn\cline\creo_history_v2.py`
(аргумент — путь к модели; печатает ревизия · время · пользователь · комментарий · версия Creo).
Раскладку B в парсер ещё надо добавить (поля известны).

## 2. Таблицы семейств (проверено раньше, Давыдовка)
Секция `FamilyInf`, имена после тегов `e3`/`1f` — читается без сессии Creo и без загрузки исполнений
(`family_table_file.py`, 9 741 б). Годится для массовой проверки семейств на складе.

## 3. Грабли (дорого дались)
* **Текст — UTF-8, а строки интерфейса — cp1251.** Декодировать по факту, иначе «кракозябры».
* Имена полей — NUL-терминированный ASCII; между полями — бинарные метки и однобайтовые значения.
* **Ловушка:** в ASCII-дампе перед номером ревизии «видно `1\x00`» — на самом деле это часть бинарной
  метки `7e f7 31 e3`. Не искать ревизию по «тексту», искать по метке + ASCII-цифры + `00 00` + UTF-8 текст.
* Одно и то же имя поля встречается много раз (в файле `Наименование компьютера` — 198 раз, а реальных
  записей истории — 25). Фильтровать строго по метке записи.
* **История пишется не во все объекты** — зависит от настройки/обстоятельств сохранения. Пустая история
  не значит «файл битый». И отдельная ловушка: чертёж из `D:\AI\PROBA\23-1017GRI\test.drw` оказался
  **подделкой** — 19 байт текста `dummy drw content`; настоящие файлы опознаются по `#UGC:2`.

## 4. ЧТО ВООБЩЕ ЧИТАЕТСЯ — карта файла (25.09.2026)

**Контейнер один для всех типов:** каждый файл начинается `#UGC:2 PART | ASSEMBLY | DRAWING` и текстовым
заголовком `#- VERS / HOST / LINK / DBID / REVS / RELL / UOBJ_ID / MACH … #-END_OF_UGC_HEADER`; дальше
данные (`#P_OBJECT`, `@P_object`, `@depend`). Значит читатель — один на все типы (тип `.mfg` — проверить).

**Как смотреть (метод, 3 шага):** 1) опознать вид по `#UGC:2`; 2) снять инвентарь — частотный словарь
ASCII-идентификаторов плюс **все** кириллические UTF-8-строки; 3) пройтись по темам-ключам
(`param`, `PTC_`, `PRO_MP_`, `relation`, `material`, `FamilyInf`, `note`, `dimen`, `tol`, `view`, `table`,
`layer`, `unit`). Скрипты: `log\urn\cline\creo_file_map.py`, `file_kind_probe.py`, `param_pair_probe.py`.

**Уже подтверждено, что читается:**
* **параметры** — имя+значение, кириллицей (`ОБОЗНАЧЕНИЕ`=`MM_PART`, `ТИП`=`Деталь`, `ПРЕДПРИЯТИЕ`=`ООО "ПТО"`,
  `НАИМЕНОВАНИЕ`/`…1`/`…2`, `ФОРМАТ`, `РАЗРАБОТАЛ`, `ТИП2`);
* **системные параметры** `PTC_*` (`PTC_COMMON_NAME`, `PTC_MATERIAL_NAME/DESCRIPTION`) и `PRO_MP_*` (масса);
* **материал** — внутреннее имя `BiSTEEL_40X` + описание «Сталь 40Х ГОСТ4593-71»;
* **отношения** — код (`ceil`/`floor`/`pow`/`sqrt`/`IF`/`ELSE`/`ENDIF`) и тексты-комментарии;
* **имена элементов** (`Вращение 1`), заметки, **размеры/допуски** (`dimen`, `tol`);
* **чертёж**: `view_id`, `format_info`, `Dwg_Models`, `Dwg_MasterRep`, `model_name`, `sheet`;
* **сборка**: `@depend`, имена и пути компонентов;
* **таблицы и спецификация** (`TABLE`, `bom`), слои, единицы, **таблицы семейств** (`FamilyInf`);
* **история** (раскладки A/B), шапка `…Corporation / All Rights Reserved` + версия Creo.

**Проверочные файлы:** `sergei-v1-stp-p-150.prt.2` (`#UGC:2 PART`), `sergei-v1.asm.1` и `liteika_hts_mm.asm.1`
(`#UGC:2 ASSEMBLY`; 976 кириллических строк), `knockout_1.drw` (`#UGC:2 DRAWING`; 560 идентификаторов).

## 6. УСТРОЙСТВО ФАЙЛА И ЧТО ЧИТАЕТСЯ ДОКАЗАННО (второй заход, 25.09.2026)

**Устройство:** заголовок `#UGC:2 <ТИП>` → **оглавление `#UGC_TOC`** (строки
`Имя <offset_hex> <len_hex> <len-10> 2572`, цепочка продолжается через `NEXT_TOC_ENTRY <offset> <len>`)
→ секции. В детали Сергея — **47 секций**: `BasicData` 87 836 б, `LargeText` 27 390, `AllFeatur` 21 802,
`VisibGeom` 19 729, `THMB_IMG_MAIN` 18 179 (**миниатюра модели!**), `FeatDefs` 15 095, `FullMData` 7 998,
`Notes`, `FamilyInf`, `MdlStatus`… **Адреса и длины лежат прямо в файле** — слепой скан не нужен.
Модуль-читатель: `D:\AI\log\urn\cline\creo_sections.py` (плюс `creo_diff.py` — сравнение версий).

**Записи — типизированные поля** `e0 <тип> <имя>\0 <значение>`: `01`=1 байт, `02`=2 байта (uint16),
`0a`=строка до `\0` (UTF-8, иногда UTF-16LE), `00`=ссылка/пусто, `03/04/09`=сырые байты.

**Доказанно читается «в лоб»:**
* **Технические требования / заметки** — секция `Notes`: 9 строк («Общий_случай_без_ТО», «размеры для справок;»,
  «Предельные отклонения по H12; h12;», «Неуказанные фаски- 0.5х45», «радиусы- R0.5 мм.») ✓
* **История (раскладка B)**: `user_name` → `modif_time` (`tm_sec/min/hour/mday/mon/year`, **UTC**) →
  `typed_data(MdlStored)` → `rev_string` («1223», «1224») → `comment` («Наименование компьютера: 'frezer-4'») →
  `Proe_version` («Creo 11.0.2.0») — **кто, когда, на каком компьютере, какой версией** ✓
* **Элементы** — имя + `feat_id` (`Вращение 1`, feat_id=3; поля `feat_id/geom_id/revnum`);
* **Отношения** — код + русские пояснения («…1000 /* 1->0, ; 10->0,1; … количество знаков после ","»);
* **Таблицы имён/слоёв/аннотаций** — `LargeText` (`RIGHT/TOP/FRONT`, `PRT_CSYS_DEF`, `AXES/NOTES/SOLID`,
  `num_feat_regens`, `saved_operation`, `SHOWN_ANNOTATIONS`);
* **Геометрия** — выровненные массивы float32 (координаты) в `VisibGeom/NovisGeom`;
* **Сравнение версий** (демо `.prt.1` vs `.prt.2`): **добавлены 8 требований** (H12/H14, фаски 0.5х45, R0.5),
  изменились размеры секций (`LargeText` +1401, `MdlStatus` +2292, миниатюра +685, `AllFeatur` −1) ✓

**Правка «в лоб» — можно, но с оговорками** (проверено на копии, оригинал не тронут): контрольной суммы
в шапке **нет** (ни crc32, ни сумма байт не дали 8-значный hex — это счётчик/идентификатор); правка **текста
той же длины** файл не ломает (заметка `Общий_случай_с_ТО` → `_ТР`: 47 секций, оглавление цело).
**Менять длины нельзя** — поедут адреса секций. Правки только на копии, с бэкапом и проверкой в Creo.

**Открытый вопрос:** **размеры**. Значений (40/150) нет ни как float32/float64, ни как обычный текст.
Найдено, куда смотреть: в `BasicData` числа лежат **в UTF-16LE** — видно `34 00 30 00` = «40» рядом с кусками
отношений (`floor`, `!=`, `)*`, `)-`). Значит искать размеры/текст нужно и в UTF-16LE, а не только в UTF-8.

### 7.1. ПОЛНЫЙ ЧИТАТЕЛЬ ИСТОРИИ — как в отчёте Creo (готово, проверено)

Запись = отметка «кто+когда» + хвост:
* отметка логина/времени: `f7 14 <логин>\0 e2 <6 байт UTC>` (Creo 11–12, детали) **или**
  `<логин>\0 e2 <6 байт UTC> f7…` (раскладка A: шаблоны, сборки);
* хвост записи: **`f7 <?> e3 <номер ревизии>\0\0 <"Наименование компьютера: 'X'">\0 <"Creo a.b.c.d">\0`**;
* рядом — имя модели: `f7 28 e2 <ИМЯ>`.

Скрипт: `log\urn\cline\history_full.py <файл…>` → таблица «дата (UTC) · ревизия · пользователь · компьютер ·
версия Creo · модель».

## 8. ПРИВЯЗКИ, СБОРОЧНЫЕ ОПЕРАЦИИ, СЕМЕЙСТВА, ЗЕРКАЛА (разбор 25.09.2026)

### 8.1. Привязки сборки — что именно лежит в файле
Запись привязки называется **`place_instruction_ptrs`** (по числу компонентов; в проверенной сборке — 3).
Её поля (разобрано на `insert-stp-s1-iz-obrezkov-v4.asm.1`):
`local_sys`, `own_ref_id`, **`orient`**, **`type`**, **`offset`**, **`offset2`**, `dim_id`, **`ref_id`**,

### 8.8. ЧИСЛА/РАЗМЕРЫ — в UTF-16LE; инструмент и дифф «было→стало»
