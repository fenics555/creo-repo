# ИНСТРУМЕНТЫ: ОФЛАЙН-РАЗБОР ФАЙЛОВ CREO

Все скрипты **без Creo, без сети, только чтение**. Python 3, без внешних зависимостей.
Оригиналы копировались из `D:\AI\PROBA\ftype_probe\` (зона для проб).

⚠️ **Копии моделей в репозиторий НЕ кладутся** — скрипты работают с файлом, который
передаётся аргументом. Пути к моделям — только аргументы.

## ГЛАВНОЕ ПРАВИЛО РАБОТЫ С ЭТИМИ СКРИПТАМИ
**Сначала мерить, потом утверждать.** Любая гипотеза проверяется замером по N полям
и только потом пишется в скил. Прецедент: гипотеза «байт = длина имени» дала
14 совпадений из 2797 → опровергнута (`checklen.py`).

## СКРИПТЫ

| Скрипт | Что делает | Как запускать |
|---|---|---|
| **`checklen.py`** | Проверяет, что означает 2-й байт после `E0`: длина имени или код типа. **Дало 14/2797 → опровергнуто** | `python checklen.py <файл>` |
| **`codetype.py`** | Таблица «маркер+код → что за поля → форма значения». Дала устойчивое распределение на 3 моделях | `python codetype.py <файл>` |
| **`codewhat.py`** | Проверка «код == длина значения» (0 из 3779) и разброс первых байт по кодам | `python codewhat.py <файл>` |
| **`creoscan.py`** | **Универсальный поиск**: дамп байтов вокруг строки с раскладкой полей. Рабочая лошадка | `python creoscan.py <файл> <строка> [--before N] [--after N] [--max N]` |
| **`fields.py`** | Инвентаризация полей с частотой — по всему файлу или по одной секции | `python fields.py <файл> [Секция]` |
| **`fieldhunt.py`** | Перекрёстный поиск 19 целевых полей по many-файлам. Показал, что они по 1 разу = схема | `python fieldhunt.py <файл> [папка]` |
| **`schema.py`** | Кластеры редких полей (1–3 вхождения) = **блоки-схемы**. Нашёл `Sld_Features`, `Sld_MdlStatus` | `python schema.py <файл> [радиус]` |
| **`featdefs.py`** | Сырые дампы записей `feat_defs_<N>` из секции `FeatDefs` | `python featdefs.py <файл> [макс]` |
| **`featrec.py`** | Разбор записей `feat_defs_*` в поля + статистика `type` | `python featrec.py <файл> [макс]` |
| **`featall.py`** | Разбор секции `AllFeatur`, поиск постоянства хвостов записей | `python featall.py <файл> [макс]` |
| **`ftbyname.py`** | Тип операции по имени (признак «Отверстие»=HOLE и т.п.) | `python ftbyname.py <файл>` |
| **`ftprobe.py`** | Поиск записей `MTTyped_CreateData` | `python ftprobe.py <файл>` |

**Вывод пишется рядом со скриптом** в `out_*.txt` / `*_out.txt` (UTF-8).
⚠️ Надёжнее писать в файл, а не в `System.out`-подобный stdout — кириллица в консоли
PowerShell ломается (в Python вывод в файл надёжнее).

## ГРАБЛИ, ЗАРАБОТАННЫЕ ЭТИМИ СКРИПТАМИ
1. **`re.finditer(pattern, chunk, pos)`** — передача `pos` третьим аргументом ищет
   **за пределами среза** `chunk` и даёт 0 результатов. Считать смещение вручную.
2. **Маркер секции искать точно** `\n#Имя[\r\n]`, иначе `FeatDefs` цепляется к
   `FeatDefsIndex` → срез не из той секции.
3. **Поля с частотой 1 = схема, а не данные.** Не искать по ним значения фич.
4. **Значение поля ≠ число.** Часто это ссылка: `F6 F8 F7 FB C0 E1 E3` — указатели,
   `84 <б>` — ID. Правка такого = разрыв графа, CRC нет (`SKILL_creo_write_raw.md` §3а).
5. Кириллица в stdout PowerShell ломается → писать отчёт в файл UTF-8.
