# СБОРКА `.asm` — ЧТЕНИЕ «В ЛОБ»

Ядро формата — `SKILL_creo_read_core.md`.

## 1. ЖИВАЯ ПРИЁМКА (03.10.2026)
| Что | Факт |
|---|---|
| Объём | ✅ есть: `23-1017gri-01.asm.1` = 1 284 131; `23-1017gri_vzm.asm.1` = 6 010 826 |
| История | ✅ ревизия/дата/пользователь/Creo |
| Параметры (обозначение/наименование/материал) | ❌ **0 %** — лежат в другой секции, не читаются (**долг №2**) |
| Состав/наложение/пути/отсутствующие | ❌ не читаются (`SKILL_creo_file_reading.md` §5 п.5) |
| Ссылки на компоненты | ✅ внутри файла видны имена (`insert-stp-s1-iz-obrezkov-v4.asm.1`: `Скругление 1` ×158, `Отверстие 1` ×73) |

**Почему объём сборки = объёму детали** (`23-1017gri-01.asm.1` = `…-01.prt.1`): признак того, что сборка
хранит одну деталь/заготовку (MFG или оболочка). Не ошибка чтения.

## 2. ПРИЗНАКИ ТИПА СБОРКИ
| Тип | Маркер |
|---|---|
| Обычная | `#UGC:2 ASSEMBLY` |
| **Производственная (мануфакчуринг)** | `#UGC:2 ASSEMBLY/ASSEM_MFG` — деталь + заготовка (+ `INLBS_MFG_NC.ASM`, `T0010.PRT`, `HAAS_3X.ASM`) |
| Обычная сборка | деталь + её **отражение** (`*-1-01`) |

## 3. СБОРОЧНЫЕ ОПЕРАЦИИ (вырезы/слияния)
* `assem_merge_parts` + секция **`AssMrgPrt`** — слияние/пересечение компонентов (сборочные вырезы).
  Правило: есть `assem_merge_parts`/`AssMrgPrt` → в сборке есть сборочные вырезы.
  Служебные ключи: `merged_srfs`, `holes_arr`, `merge_info_ptr`, `slot_id`.
* Найденные коды типов привязки (`place_types.py`): **155, 148, 143, 133, 130, 5**; в простых сборках 2–3 привязки.
  Гипотезы (нужен контрольный опыт): `130` — базовое сопряжение детали/заготовки, `148` — совмещение СК.

## 3. ⚠️ ЧТО ОКАЗАЛОСЬ НЕ ТАК (проверено 03.10.2026, важно!)
Гипотеза «из файла сборки читается состав по записям `ID n (NAME.PRT)`» **не подтвердилась**:
* в `23-1017gri-01.asm.1` таких записей **0**;
* имена моделей внутри файла почти все — **ссылки на саму сборку**: `23-1017GRI-01.ASM` ×341
  (плюс варианты `g23-…`, `q23-…`, `k23-…` — это те же имена с разными байтами-префиксами!);
* ключи зависимостей есть, но по одному вхождению: `asm_comp_map`, `gen_comp`, `inst_comp`,
  `comp_id`, `ref_model`, `comp_pos` (счётчики 1–4) — это **указатели**, а не список.

**Вывод (меняет планы):** **состав сборки из файла не читается** — нужен Creo (`bom:get_paths`)
или таблица `links` в базе ПЛМ (`plm_reader`, `where`/`tree`), где входимость уже работает.
Прежняя запись «состав читается» в скилле была неверной — исправлено здесь.

**Что из состава всё-таки видно:** имена операций **компонентов** (`Вытягивание 2…20`, `Эскиз 1/2`,
`Скругление 3/6/7/8`, `Сопряж Границ 1`, `Сечение 1`) и названия переходов ЧПУ — т.е. сборка «прозрачна»
по содержимому моделей-компонентов, но **не по списку компонентов**.

⚠️ **Грабля имён моделей:** искомое `23-1017GRI-01.ASM` встречается с **мусорным байтом-префиксом**
(`g23-`, `q23-`, `k23-`, `s23-`, `C23-`, `Z23-`, `01123-`). Перед сравнением отбрасывать первый
не-`[A-Za-z0-9_]` символ, иначе посчитаются дубликаты (341 → десятки).

## 4. ПРОИЗВОДСТВЕННАЯ ЦЕПОЧКА (читается по содержимому)
```
деталь → отливка (*-otlivka) → мастер-модель (*-master_model / *-MASTER) → знаки/ящики/плиты → оснастка
```
Главный признак — снова `MERGE_BASE_PART` (наследование геометрии).
**Проверенная «физика»** (объёмы сошлись, припуски/усадка на месте):
деталь `23-1017gri-m2-01.prt.1` = **1 325 240** < отливка `…-otlivka` = **1 328 090** < мастер-модель = **1 567 190**.

## 5. ВХОДИМОСТЬ (кто во что входит) — через базу, не через чтение
`links(parent, child, qty)`, `qty` ≈ число упоминаний компонента в сборке.
Живо: `where DF-STP2-VDF` → **46 сборок** (03.10.2026; было 42 на 25.09 — входимость растёт).
Ключи запросов: `engine.plm_children`, `plm_parents`, `plm_up_data`, `plm_down_data`.

## 6. ГРАБЛИ
* Роль «производная» **нельзя ставить сборкам**: у сборки `ref_part_tab` = список её компонентов.
* Отливки бывают **около 6 МБ** — при малом лимите размера они выпадают из разбора.
* Родственные модели лежат в одной папке; поиск ссылки — **с границей имени** (иначе `GR4` путается с `GR4-1`),
  искать и в UTF-8, и в UTF-16LE.
* `parent_link_probe.clean_names` отдаёт имена **с расширением** (`.PRT`), а стемы без → `stem()` перед сравнением.
