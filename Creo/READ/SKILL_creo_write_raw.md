# ПРАВКА ФАЙЛОВ CREO «В ЛОБ» (без Creo, если возможно)

**Зоны:** править можно **только в `D:\AI\PROBA`**; `Z:\PTC` — **только чтение**.

## 0. СНАЧАЛА СПРОСИ СЕБЯ: НУЖЕН ЛИ CREO?
| Задача | Путь | Почему |
|---|---|---|
| Массовая замена **текста/параметра** во многих файлах | ✅ **в лоб** | дёшево, проверяемо |
| Переименование, регенерация, размеры, новые фичи | ❌ **только Creo** (CREOSON/JLINK) | `file:rename` дисковый мёртв, размеры в p-code |
| Правка **геометрии** | ❌ никогда в лоб | риск порчи без возможности отката |
**Правило дома:** сначала спросить «можно ли в лоб», и только если нет — поднимать Creo.
Creo нужен **только для записи**, читается всё без него.

## 1. ГЛАВНОЕ ПРАВИЛО ДЛИНЫ
* ✅ **Менять текст ТОЙ ЖЕ длины** — файл не ломается (проверено на копии: заметка
  `Общий_случай_с_ТО` → `Общий_случай_с_ТР`; 47 секций, оглавление цело).
* ❌ **Менять длины НЕЛЬЗЯ** — поедут адреса секций и всё оглавление `#UGC_TOC`.
* Контрольной суммы в шапке **нет** (ни crc32, ни сумма байт не дали 8-значный hex — это счётчик/идентификатор),
  поэтому **своей проверки целостности у файла нет** — приёмка только внешняя.

## 2. ГДЕ МЕНЯТЬ (безопасно)
| Что | Формат | Примечание |
|---|---|---|
| **Параметр** | `<имя> \0 e2 33 <значение> \0` | значение той же длины; ⚠️ за значением `\xf7 <байт>` — не затирать |
| **Заметка/ТТ** | секция `Notes` | текст той же длины |
| **Имя параметра** | то же | осторожно: нарушится матчинг по хвосту имени |
| **Размер** | упакованное число | ❌ длины плавают 1–3 байта, структура p-code → **не трогать** |

## 3. ГДЕ НЕ ТРОГАТЬ НИКОГДА
* секции построения `AllFeatur` / `FeatDefs` / `ActEntity` / `SolidPrimdata` — пересобираются целиком;
* `VisibGeom` / `NovisGeom` — геометрия;
* оглавление `#UGC_TOC`, шапку `#UGC:2 …`, маркер `#- … #-END_OF_UGC_HEADER`;
* историю (`f7 ?? e3 <ревизия> 00 00`) — счётчики и адреса внутри связаны;
* файлы на `Z:\PTC` — **вообще**.

### 3а. 🚫 ЖЕЛЕЗНЫЙ ЗАПРЕТ (03.10.2026) — правка полей-указателей

Разбор маркеров значения (см. `SKILL_creo_read_core.md` §2б) показал: **значение поля не
всегда число — часто это ссылка.** Запись такого поля выглядит «похоже на» число, но при
подмене разъезжает внутренние адреса, и **CRC/контрольной суммы у файла нет** — порча
выявляется только при открытии в Creo.

| Категория | Маркеры | Почему нельзя |
|---|---|---|
| **Указатели / ссылки** | `F6`, `F8`, `F7`, `FB`, `C0`, `E1`, `E3`, `F9`, `F4` | это адреса/ссылки на структуры; замена = разрыв графа |
| **ID объектов** | `84 <б>`, `85 <б>` и далее (**2 байта**) | на них завязаны ссылки геометрии и дерева |
| **Структурные коды** | `F8 <N>` (N = длина блока) | длина блока связывает его содержимое |
| **Коды типа поля** | байт после маркера `E0`/`E3` | изменение = смена типа поля, файл не распарсится |

✅ **РАЗРЕШЕНО:** менять **только строковые значения** с маркерами `F1`, `F2`, `0A`,
**строго той же длины, байт в байт**.

⚠️ **Особенно опасно** — правка «похожего на число» в поле типа `E0 01`:
```
"feat_type_ptr" 00 F6      ← НЕ число, а ссылка
"feattype_key"  00 E1      ← НЕ число, а ссылка
"table_id"      00 F6      ← НЕ число, а ссылка
```
Эти три поля уже ошибочно считались «типом операции» (`SKILL_creo_read_feat.md` §4в).
Если хочется «поправить число в файле» — сначала доказать, что это **не** `F6/F8/C0/E1`
и **не** `84 <б>`.

## 4. ПОРЯДОК РАБОТЫ (обязателен)
1. **Копия в `PROBA` под уникальным именем** (иначе Creo отдаст оригинал из сессии).
2. Бэкап копии; записать размер/mtime оригинала для сверки.
3. Правка **адресно**: найти точное смещение маркера, заменить байты, **не трогая длину**.
4. Проверка после правки: `#UGC_TOC` цел, число секций то же, размер файла не изменился (кроме записи),
   `py_compile`-аналог = повторный разбор всех секций без исключений.
5. **Открыть в Creo и посмотреть** (правило: правка «в лоб» — только с проверкой в Creo, оригинал не тронут).
6. Откат при любом подозрении — из копии.

### ⚠️ ГЛАВНОЕ: почему проверку в Creo сделать НЕ удалось
**CREOSON открывает не произвольный файл на диске, а только те, что доступны
рабочему каталогу `Z:\PTC\CREO-START\START-STD`.** Доказано контрольным опытом:
* нетронутый клон `din933` под новым именем (`clone.prt`, MD5 идентичен) — **не открывается**;
* нетронутый бэкап `wt_backup.prt` (MD5 идентичен рабочему файлу) — **не открывается**;
* оригинал `Z:\PTC\Work\00080\00080-03.prt` — **открывается**.

Значит ошибка «Could not open file …» **не означает порчу файла**.
⚠️ **Прежняя запись в скиле про «крепится только на Z:» неточна:** ограничение
не в букве диска, а в доступности пути для сессии Creo.

### ❌ Чего проба НЕ доказала
Приёмка в Creo (открыть изменённый файл и посмотреть заметку) **не выполнена** —
см. ограничение выше. Чтобы её провести, изменённый файл должен оказаться
в зоне, видимой сессии. `Z:\PTC\CREO-START\START-STD` писать **нельзя**
(запрет владельца). Значит запись подтверждена **структурно**, но не **в Creo**.
