## 🔴🔴 ЗАКОН: «НЕИЗВЕСТНОЕ» ≠ «МУСОР» (слово владельца, 30.10.2026)

> **Владелец:** «Твоя ошибка: при чтении файла ты находишь **"неизвестное"** и **отсекаешь
> под словом "мусор"**. А там **может самое важное**».

### ❌ ЗАПРЕЩЕНО
```
«это мусор» · «пустышка» · «служебное» · «не наше» · «схемное» · «отфильтровать» · «пропустить»
```
**Эти слова — МАСКИРОВКА НЕЗНАНИЯ.** Найдено непонятное → **значит НЕ ИЗУЧЕНО**, а не «мусор».

### ✅ ПРАВИЛЬНО
```
1. Неизвестное поле → ЗАПИСАТЬ (в базу, в скилл, в отчёт) — НЕ отбрасывать.
2. Пометить: «НЕ ИЗУЧЕНО» (честно), а не «мусор».
3. Изучить: что за поле, какой формат, к чему относится.
4. Только ПОСЛЕ изучения — решать, нужно ли (и почему).
```

### 🎯 ЧТО ДЕЛАТЬ С НЕИЗВЕСТНЫМ В СКАНЕРЕ
```
• Все поля — писать в базу (в таблицу `params` или отдельную `unknown_fields`).
• В отчёте — раздел «НЕ ИЗУЧЕНО» (список полей, которые встретились, но не разобраны).
• НЕ фильтровать по «похоже на служебное» — фильтр только по ДОКАЗАННОМУ признаку.
```

## 🔴 ГРАБЛИ ЧТЕНИЯ БАЙТОВ (мои, 30.10.2026 — 3 штуки за одну задачу)

| # | Симптом | Причина | Лечение |
|---|---|---|---|
| **R1** | Regex «не находит» поле, хотя оно есть | **`re.S` (DOTALL)** — `.` начинает «съедать» `\x0a`, и шаблон уезжает | **НЕ использовать `re.S`**, если в шаблоне есть `\xe0\x0a` |
| **R2** | `name` находится, а `description` — нет | класс `[\x20-\x7e\xc0-\xff]` **НЕ покрывает кириллицу**: `\xd0\x93` («Г») — байт **`\x93` < 0xC0** | класс **`[\x20-\x7e\x80-\xff]`** (весь UTF-8) |
| **R3** | Два формата имени поля в одном файле | `\xe0\x01name` и `\xe0\x0aname` — **оба** бывают | искать **оба** варианта |

**Урок:** при чтении байтов **класс символов должен покрывать UTF-8 полностью** (`\x80-\xff`), иначе кириллица рвёт regex.

## 🔴🔴 ЗАКОН: В ФАЙЛАХ **МУСОРА НЕТ** — И ЭТО КАСАЕТСЯ **КОДА** (30.10.2026)

> **Владелец:** «ты опять выбираешь что тебе нужно, **ОТБРАСЫВАЯ как ты думаешь МУСОР**.
> **НО В ФАЙЛАХ МУСОРА НЕТ!**»

### ❌ ЧТО Я ДЕЛАЛ (фильтры в СВОЁМ сканере — 22 штуки!)
| Фильтр в коде | Что терял |
|---|---|
| `if nm in seen: continue` | **повторы параметров** (343 вместо 1013!) |
| `[A-Z][A-Z_0-9]{3,40}` в `unknown_fields` | **строчные/короткие имена** (160 вместо 2107!) |
| `if lo <= abs(v) <= hi` в `_mp_field` | **все варианты `lead`, кроме «разумного»** |
| `if not mf: continue` в `dimensions` | **размеры без `feat_id`** |
| `break` после первого значения | **остальные значения поля** |

### ✅ ПРАВИЛО (обязательное)
```
1. НИЧЕГО не отбрасывать — ни в выводах, ни В КОДЕ.
2. Несколько вариантов (lead, формат, значение) → СОБРАТЬ ВСЕ.
3. Непонятное → в `unknown_fields` с пометкой, а НЕ `continue`.
4. «Разумное» → поставить ВПЕРЁД, но НЕ выбрасывать остальное.
5. `continue`/`break` в парсере = ПОДОЗРЕНИЕ на фильтр → проверить, что не теряется.
```

## 🔴 ГРАБЛЯ R4: ДЛИНА `f8 <N>` БЫВАЕТ МНОГОБАЙТНОЙ!

```
components  f8 80 90   ← это НЕ «1 байт длины», а СЧЁТЧИК 144 (многобайтное число!)
materials   f8 01      ← маленькое (1 байт)
tool_params f8 11      ← 17 (1 байт)
```
**⇒ Парсер `f8(.)` (один байт) ЛОМАЕТСЯ на больших массивах.**
**Правило:** `f8` + **читаемое многобайтное число** (как `f7 <N>` в других местах).

### 📋 СВОДКА ГРАБЛЕЙ ЧТЕНИЯ БАЙТОВ (R1–R4)
| # | Грабля | Лечение |
|---|---|---|
| **R1** | `re.S` ломает `\xe0\x0a` | не использовать `re.S` с `\x0a` |
| **R2** | класс `[\xc0-\xff]` не покрывает кириллицу (`\x93`) | `[\x80-\xff]` |
| **R3** | два формата имени поля (`\xe0\x01` / `\xe0\x0a`) | искать оба |
| **R4** | `f8 <N>` — **многобайтная длина** | читать число целиком, не 1 байт |

## 🎯 ПРАВИЛО ЧТЕНИЯ (закрепить в сканере)
```
1. Прочитать `#UGC_TOC` (СНАЧАЛА!).
2. Разобрать: имя секции → смещение → длина.
3. Читать ТОЛЬКО внутри нужной секции (не «по всему файлу»).
4. Если данных нет в ожидаемой секции — смотреть СОСЕДНЮЮ по карте.
```
**Польза:** точность (не «поймать» чужое значение), скорость (не сканировать весь файл), понимание структуры.

## ⚡ ОПТИМИЗАЦИЯ (30.10.2026): regex → быстрый find

**Проблема:** `re.finditer` с классом `[a-z_]{3,30}` по файлу 1 МБ = МЕДЛЕННО (9 мс).
**Решение:** быстрый `bytes.find(маркер)`, потом проверка ЛОКАЛЬНО.

| Функция | Было | Стало | Ускорение |
|---|---|---|---|
| `extract_matrices` | 9.26 мс | **0.61** | **15×** |
| `extract_drawing` | 5.90 мс | **0.01** | **590×** |
| `extract_links` | 5.40 мс | **0.00** | **∞** |
| `unknown_fields` | 3.48 мс | 3.43 | (предел: тысячи `\xe0`) |
| **`pack` всего** | **27.85 мс** | **~7.5** | **3.7×** |

**ПРАВИЛО:** для байтовых маркеров — `bytes.find()`, НЕ `re.finditer` с классами.
**Проверка области:** для `.drw`/`.asm` — сначала `b"DRAWING" in raw[:200]` (мгновенно).
