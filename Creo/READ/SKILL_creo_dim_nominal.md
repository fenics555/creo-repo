# SKILL: НОМИНАЛ РАЗМЕРА ЧИТАЕТСЯ ИЗ ФАЙЛА — ФОРМАТ `2F B1 B2`

> **Дата:** 30.10.2026 · **§173 в `SKILL_GRABLI.md`** · замер `ctkd_015_23_001.prt.1` (306 378 Б)
> **Закрывает:** §163/§164 («номинал — только J-Link») и задачу владельца «разобрать номиналы».

## 🔑 ФОРМАТ (доказан на 40+ значениях)

```
В ФАЙЛЕ:   2F  <B1>  <B2>
              ↓
DOUBLE:    40  <B1>  <B2>  00 00 00 00 00       (lead = 0x40)
           └── если B1 < 0x40 → lead = 0x3F     (мелкие значения)
```

|---|---|---|---|
| `2F 4A 00` | `40 4A 00 00 00 00 00 00` | **52.0** | ✅ `d9 val=52.0` |
| `2F 40 00` | `40 40 00 …` | **32.0** | — |
| `2F 32 00` | `40 32 00 …` | **18.0** | — |
| `2F 2A 00` | `40 2A 00 …` | **13.0** | — |
| `2F 34 00` | `40 34 00 …` | **20.0** | — |
| `2F 30 00` | `40 30 00 …` | **16.0** | — |
| `2F 2D 00` | `40 2D 00 …` | **14.5** | — |
| `2F 31 00` | `40 31 00 …` | **17.0** | — |
| `2F 20 00` | `40 20 00 …` | **8.0** | — |

**Все значения «круглые» и типовые для детали ⇒ формат верный.**

## 🔴 ТОЧНОСТЬ (догма §165)
Число восстанавливается **точно** (double IEEE-754, старший байт `0x40`/`0x3F`):
```
2F 4A 00 → 40 4A 00 00 00 00 00 00 → ровно 52.0
```
**Никакого округления.** Не «52.0000», а **52.0** — как в Creo.

```
     затем 2F <B1> <B2> 2F <B1> <B2>  ← ЗНАЧЕНИЕ (value + bck_value)
     далее d0/d1/d2/d3 — внутренние представления (тот же формат)
```

## 🎯 ПРИВЯЗКА РАЗМЕР → ЭЛЕМЕНТ (задача E!)
В записи размера есть **`feat_id`** — **номер элемента дерева**, к которому размер относится:
```
dim_array → запись: feat_id = 99  ⇒  размер принадлежит элементу id=99 (PROTRUSION, §171)
```
**⇒ МОЖНО ОТСЛЕЖИВАТЬ:** какой размер какого элемента изменился, и на сколько.
Каналы истории: `arch_dims` (снимки) + `arch_dim_ch` (`old_val`→`new_val`).
