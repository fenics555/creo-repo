# SKILL: СТРУКТУРНЫЙ РЕКОННАИСАНС ФАЙЛОВ CREO

**Назначение:** создание полной карты физических границ секций и идентификация типов данных на основе наблюдаемых паттернов в бинарных файлах.

## 1. КЛЮЧЕВЫЕ ПАТТЕРНЫ СЕКЦИЙ (По итогам Этапа 6)

| Тип файла | Ключевые маркеры / секции | Особенности |
|---|---|---|
| **Assembly (.asm)** | `#UGC_TOC`, `#SolidPersistTable`, `#LargeText`, `#MdlStatus` | Содержит метаданные о составе и зависимости. |
| **Part (.prt)** | `#NeuPrtSld`, `#FullMData`, `#LargeText`, `#ModelView` | Секция `#NeuPrtSld` критична для параметров. |
| **Drawing (.drw)** | `#B`, `#C` (repetitive), `#Dwg_Data`, `#Dwg_Models` | **Внимание:** секции `#C` могут повторяться массово (объекты/виды). Файл значительно тяжелее. |
| **Manufacturing (.mfg)** | `#UGC:2 ASSEMBLY/ASSEM_MFG` | Искать специфические `dat_ptr` для связи с инструментом. |

## 2. ПРАВИЛА МАРШРУТИЗАЦИИ (BOUNDARY RULES)

1. **ЗАПРЕТ на TOC:** Никогда не использовать `length` из `#UGC_TOC` для `seek()`. Смещение в TOC может быть корректным, но длина — нет.
2. **Метод "Следующий Маркер":** Реальная граница секции $S_i$ — это $Offset(S_{i+1}) - Offset(S_i)$.
3. **Поиск текстовых блоков:** Использовать `cp1251` для декодирования. Если встречаются `\xf6` или другие невалидные байты в текстовых секциях, использовать `latin-1` или декодировать побайтово.

## 3. МЕТОДЫ ИНСПЕКЦИИ

- **Structural Map:** Сначала собрать массив всех `#SectionName` с их реальными `size`.
- **Float Scan:** Если маркер секции (напр. `BoundingBox`) не дает результат, проводить сканирование по `float64` (8-байтовые блоки) в поисках реалистичных инженерных чисел.
- **String Recon:** Искать ASCII/CP1251 строки в `#LargeText` для идентификации параметров (например, `PRO_MP_*`).

## 4. ПРОВЕРКА (PROBE)
- Запустить `D:\AI\PROBA\recon_scanner.py <path>`.
- Проверить, что количество секций в отчете совпадает с количеством найденных `#` маркеров.
- Убедиться, что размеры секций в отчете не "накладываются" друг на друга.
