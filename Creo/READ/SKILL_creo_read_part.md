## 2б. ✅ ПАРАМЕТРЫ — ЗАКОН ВСКРЫТ И ПРОВЕРЕН (03.10.2026, глубинная разведка)

**Структура записи параметра (по байтам, секция `NeuPrtSld`):**
```
f6 02 e1 e1 00 e3  <ИМЯ>\0  e2 32  <упакованное число>     — ЧИСЛОВОЙ параметр
f6 02 e1 e1 00 e3  <ИМЯ>\0  e2 33  <строка>\0               — ТЕКСТОВЫЙ параметр
```
* Счётчики на `din933.prt.1`: **`e2 32` = 44** (числа), **`e2 33` = 473** (строки).
* Имя = байты **между двумя NUL** перед `e2`.
* ⚠️ **Главная грабля (был баг):** искать имя «назад по байтам ≥ 0x20» **нельзя** — кириллица UTF-8
  = байты `0xd0`/`0xd1`, они тоже ≥ 0x20 → захватывается **предыдущее** имя. **Граница — только NUL.**
* ⚠️ **Вторая:** между `e2 32` и числом бывает префикс (`f7 25`) → искать начало числа (`2f`/`48`)
  в первых 4 байтах хвоста.
* ⚠️ **Третья:** перед кириллицей лежит мусорный байт (`3Винт`, `1Вытягивание`) — отбрасывать.

## 2в. ✅ ОТНОШЕНИЯ (relations) — видны в файле
В `LargeText` на `din933.prt.1`: **`LOCAL_RESTR` ×24**, при них `if` ×14 · `else`/`endif` ×18 —
логика читается, `LOCAL_RESTR` = имя объекта-контейнера.

а не как строку) → **долг №15**.

## 3. ⚠️ ЛОВУШКА РОЛИ (главный дефект сейчас)
Обычная деталь даёт роль «наследование» с родителем **`MM_ASSY.prt` / `SBORKA_MM.prt` / `MM_PART.prt`** —
это **значение шаблона**, а не родитель. Настоящий родитель у производных (отливок, заготовок) другой
(`23-1017gri-m2-01-otlivka.prt.1` → `323-1017GRI-M2-01.prt`).
**Лечение (долг №1):** отбрасывать `MM_ASSY`/`MM_PART`/`SBORKA_MM` как шаблонные; роль ставить только
при родителе ≠ шаблонный.

## 4. ПРАВИЛА
* Пустой объём/история ≠ битый файл: это копия, ни разу не регенерированная (правило владельца).
* Объём детали и её ближайшей «однотелой» сборки может совпадать — признак MFG-сборки, не ошибка.
* Материал `PTC_SYSTEM_MTRL_PROPS` = материал не назначен (системная заглушка), а не «нет данных».
* Правки детали — только в `PROBA`, копия под уникальным именем (`SKILL_creo_write_raw.md`).
