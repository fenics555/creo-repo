# ЭТАЛОН ДЕРЕВА ПОСТРОЕНИЯ ЧЕРЕЗ J-LINK (TreeProbe)

**Зачем:** разбор байтов («что на что меняется», типы фич, размеры `dN`) проверяется ТОЛЬКО
сверкой с живым Creo. Creo — законодатель, файл — копия.

## Запуск (проверено 28.10.2026, Creo 13.4.1.0)

```powershell
cd D:\AI\tools\agent\creo_export
tree_probe.bat "путь\модель.prt.1"        # Creo поднимется сам, если не запущен
mass_probe.bat "путь\модель.prt.1"        # масса/объём/площадь (эталон чисел)
```

**Файлы:** `TreeProbe.java` + `tree_probe.bat` (ASCII-текст, без кириллицы!)

## Формат вывода (машиночитаемый)

```
#MODEL <имя файла>
#FEAT-COUNT <N>                       число элементов дерева
#DIM-COUNT <M>                        число размеров модели
#FEAT <индекс> <feat_id> TYPE_<код> <имя>
#DIM feat=<feat_id> sym=dN name=dN dimid=<id размера> val=<значение>
#PARAM <имя> <значение>
#ERR ...
```

## 🔴 ГРАБЛИ (обе пойманы живьём)

1. **`XToolkitNotFound`** — Creo не запущен. Поднять: `parametric.bat -g:no_graphics -i:rpc_input`
   (D:\PTC\CREO13\Creo 13.4.1.0\Parametric\bin), ждать процесс `xtop`, ~40 с.
2. **`XUnknownModelExtension`** — Creo не принимает имя с версией. Передавать `x.prt`,
   а не `x.prt.1` (номер версии отрезается в `TreeProbe.java`).
3. **`null` в имени / `no_name`** — норма: у элементов имя появляется только у именованных.
4. **`FeatureType` печатался как `com.ptc.pfc.pfcFeature.FeatureType@…`** — у enum нет `toString`;
   номер берётся через reflective `getValue()`/поле `__Value` → в выводе `TYPE_<номер>`.
5. **Импорт `pfcDimension.Dimension`** — классы лежат в `com/ptc/pfc/pfcDimension/`,
   а не в `pfcModelItem`; сверять по `all.txt` в каталоге инструмента, а не по памяти.
6. **У `Feature` НЕТ `ModelItemOwner`** (`ClassCastException`) — список элементов берётся у
   МОДЕЛИ: `ListItems(ModelItemType.ITEM_FEATURE)`; константы — `ITEM_*`, не `MODEL_ITEM_*`.
7. **Кириллица в `.bat` без BOM ломает парсер** — сообщения в bat писать ASCII.

## Связь с разбором БАЙТОВ (что даёт эталон)

- `dimid` из эталона = **id колонки таблицы семейства** в байтах (замер: колонки `14`, `103`
  ↔ `dimid=14`): этим и читается «что меняется в исполнении».
- `feat_id` из эталона ищется в файле как **2-байтовое LE-число** (1-байтовые — шум геометрии).
- Порядок `#FEAT 0..N` — **хронология создания**: её и искать в файле цепочкой id.
- `sym=dN` — **имя размера Creo** (`d10`), `val` — номинал; в байтах текстом `d10` НЕТ.

## 🔴 НОМИНАЛЫ РАЗМЕРОВ: ФОРМАТ НЕ РАЗГАДАН (уточнено замером 28.10.2026)

**Проверено на `g22033.prt.1`** (шпилька): живой Creo отдал 8 размеров с номиналами
(`d7=8.0`, `d8=8.0`, `d10=30.0`, `d13=0.625`, `d14=22.0`, `d15=6.75`, `d27=6.75`, `d28=8.0`).
**Что найдено в файле:**

- точных `double` (BE и LE) — **0**;
- точных `float32` — **0**;
- **дробных** `6.75` / `0.625` — **0** (ни с точкой, ни с запятой);
- числа `30\0`, `22\0`, `8\0` — **есть**, но это **имена исполнений** (`M3x30`, `M4x22`),
  а не значения размеров.

**Вывод (уточнён после замечания владельца «J-Link ничего не выдумывает»):**
Creo значение **показывает**, значит оно **в файле есть** — но **в неразгаданном формате**
(не IEEE-754, не текст). Ставить «не хранится» — **неверно**; правильная формулировка:
**формат хранения номинала не разгадан**.

**Практика до разгадки:**

- **квалитет и режим допуска — читаются из файла** (текстом, см. таблицу выше);
- **номинал** — брать **J-Link** (`tree_probe.bat` → `#DIM feat=… sym=d10 dimid=10 val=30.0`),
  а не выводить из имени исполнения;
- `dimid` и `feat_id` — в файле (2-байтовые LE), известны точно.


## 🔴 ЧТО ХРАНИТСЯ КАК: НОМИНАЛ / КВАЛИТЕТ / ID (замер 28.10.2026)

У размера в файле **несколько полей разной природы** — и это надо знать, чтобы не искать «число» там, где лежит «строка»:

| Поле размера | Как хранится | Читается? | Замер (`g22033.prt.1`) |
|---|---|---|---|
| `dimid` (номер `dN`) | 2-байтовое число (LE) | ✅ | `dimid=10`, `dimid=14` — совпало с Creo |
| `feat_id` (какой элемент) | 2-байтовое число (LE) | ✅ | 19/19 id из эталона найдены |
| **квалитет / посадка** (`H7`, `6g`, `f7`) | **ТЕКСТ** | ✅ **читается** | `6g` **8** · `f7` **6** · `h6` **3** · `H8` **2** · `g6` **2** · `Z6` **2** · `H7` **1** · `H9` **1** |
| режим допуска (`±`, лимиты) | ключ + значение | ✅ ключи есть | `def_tolerance_mode` · `def_tol_display_style` · `linear_dim_tolerance` · `angular_dim_tolerance` · `dim_tol` **6** · `tol_` **35** · `fit` **4** |
| **номинал** (`30.0`, `6.75`) | **ФОРМАТ НЕ РАЗГАДАН** | ❌ | точных `double`/`float32` — **0**; дробные `6.75` / `0.625` текстом — **0**; числа вида `30\0`, `22\0` — это **имена исполнений** (`M3x30`), не размер |
| значения (как числа) — только у Creo | вычисляются/распаковываются | ✅ через J-Link | `#DIM … val=30.0` |

**Правило:** номинал **не выдумывать из имени исполнения** (`M3x30` → «длина 30» — это догадка, а не чтение).
Если нужен точный номинал — **J-Link**. Квалитет и режим допуска — **из файла**.

## 📏 ТИПЫ РАЗМЕРОВ — РАСШИФРОВАНЫ (замер 28.10.2026)

Владелец: «размеры есть линейные, радиусные, диаметральные…» — **подтверждено замером**
на живом Creo (`ctkd_015_23_001.prt.1`, 40 размеров):

| `dtype` | Что это | Живые примеры | Допуск |
|---|---|---|---|
| **`TYPE_0`** | **линейный** | `d9=52.0` · `d10=32.0` · `d13=13.0` · `d17=8.475208614068027` | `DimTolISODIN` |
| **`TYPE_2`** | **радиус / диаметр** | `d11=18.0` · `d18=18.0` · `d24=16.0` · `d29=14.5` | `DimTolISODIN` |

**Правила:**

- **тип размера читается** (`DimensionType`, номер через reflective `getValue()` — у enum нет
  `toString`), и его кладём в базу рядом с `dimid`;
- **у углов допуска не бывает** — пустое `tol=` у `TYPE_3` это **норма**, а не пропуск;
- подтверждено **двумя независимыми признаками**: три разных класса объектов

**Канал номинала (не разгадан до конца):** рядом с размером лежат `symbol`, `text(i_val)`,
`parent_dim_id`, `symbol_key` — то есть Creo хранит **символьное выражение и ссылки**,
а число получает вычислением (отсюда «некруглое» `8.475208614068027`).
Ключ дерева — `feat_defs_<ID>` (этот маркер из скилла `feat_defs_deep_dive` **подтверждён**;
ложным был только паттерн-делимитер `FB E3 F7 80`).

## 🧩 НОМИНАЛЫ ИСПОЛНЕНИЙ: ЧИТАЮТСЯ ИЗ ИМЕНИ + ПАСПОРТА ГЕНЕРИКА (замер 28.10.2026)

**Факт (два разных семейства):** чисел-номиналов в файле НЕТ — они **закодированы в имени исполнения**.

| Семейство | Исполнений | Разобрано маской | Диаметры в именах | Длины в именах |
|---|---:|---:|---|---|
| Шпильки `g22033` | **344** | **331 (96 %)** | 3, 4, 5, 6, 8, 10, 12, 16, 20, 24, 30, 36 | **12 … 240** (31 значение) |
| Винты `din912` | 1 375 записей / 106 имён | **102 (96 %)** | 2.5, 4, 5 … | **4 … 250** (51 значение) |

Маски: `M(\d+)_?(\d*)X(\d+)_` (шпильки) и `DIN912-M(\d+)_?(\d*)X(\d+)` (винты).
Примеры: `M3X12_G22033` → ⌀3.0 / L=12.0 · `DIN912-M2_5X4` → ⌀2.5 / L=4.0.

**Проверка сходимости с Creo:** базовые значения генерика `g22033` — `d10=30.0`, `d7=8.0`,
`d14=22.0`; длины из имён (12…240) содержат `30.0` внутри диапазона ✅; колонки таблицы
в файле (`id` 14, 128) совпали с `dimid=14` из Creo ✅.

**Правила:**

- **4 % неразобранных имён — НЕ дефект**: это родительские типоразмеры без длины
  (`DIN912-M2_5`, `M4_G22033`): диаметр известен, длина = базовая;
- **привязка «токен → dimid»** делается по паспорту генерика (тип `TYPE_0` линейный + диапазон значений),
  но **по каждому исполнению с Creo пока не сверена** — это следующий шаг;
- **квалитеты** (`6g`, `H8`) читаются из файла текстом, привязка к конкретному размеру не проверена.

## §104. РАЗДЕЛЕНИЕ СИСТЕМНЫХ И ЧЕЛОВЕЧЕСКИХ ДАННЫХ (ЗАКОН АВТОРА, 29.10.2026)

**Грань между «Creo-именованием» и «человеческим именем» — АБСОЛЮТНА.** Не по форме строки,
а **по автору**: имена `dN`, `TYPE_*`, `PROP_*` назначает **Creo** (цифровой базис, ему можно верить),
любые другие имена назначает **человек** (свободный текст, чисел в нём нет).

| № | Что нащупано бинарно (ФАКТ) | Чем является НА САМОМ ДЕЛЕ | Правило |
|---|---|---|---|
| 1 | `\xe3\x02 <ИМЯ> \x00 \xe1×5 \xe3\x1f\xe3\x02 <РОДИТЕЛЬ> \x00` | **реляционный узел таблицы семейства** | **Брать как есть** — иерархия Instance ↔ Generic (344 / 1 375 проверено) |
| 2 | строки `M3X12_G22033`, `DIN912-M2_5X4` | **человеческое ИМЯ исполнения** | 🔴 **ЗАПРЕЩЕНО резать на номиналы** — это свободный текст |
| 3 | тег `0x000F` перед `\xe3\x1f\xe3\x02` | **служебный код поля** («далее имя родителя») | 🔴 **ЗАПРЕЩЕНО** читать как `dimid=15` |
| 4 | счётчик `\xe2\x15<N>`, N = 15..40, 15 002 записи, **все пустые** | **разреженная адресная сетка**, не данные | **Не парсить** — номиналов там нет |
| 5 | `d7`, `d10`, `d27` + `TYPE_0/2/3` | **Creo-размеры и их виды** (линейный/радиус/угол) | **Цифровой базис базы** — брать |
| 6 | `6g`, `f7`, `h6`, `H8`, `Z6` текстом | **КД-квалитеты** (поля допуска) | **Писать как КД-свойство**, привязку к размеру не додумывать |
| 7 | `ВЫТЯГИВАНИЕ 9`, `СКРУГЛЕНИЕ 4`, `ВРАЩЕНИЕ 1` | **локализованные имена операций** | **Выводить в дерево** (совпало с Creo 13: 9 = 9) |
| 8 | `symbol`, `text(i_val)`, `parent_dim_id`, `feat_defs_<ID>` | **граф математических ссылок Creo** | **Канал не вскрыт** — Creo считает геометрию сам |
| 9 | номиналы: `double` 0 · `float32` 0 · текст 0 (весь файл, два семейства) | **номинал не хранится числовым полем** | 🔴 **ЗАПРЕЩЕНО искать числа размеров в байтах** |
| 10 | суффиксы `1P25`, `M2_5` | **произвольный текст человека** | 🔴 **ЗАПРЕЩЕНО** выводить из них шаг/диаметр |

## 📐 ТРИ КАНАЛА РАЗМЕРОВ И ПРАВИЛО ЗАМЫКАНИЯ `dN ↔ dimid` (замер 29.10.2026)

**ГЛАВНОЕ ОТКРЫТИЕ:** значения размеров **ЧИТАЮТСЯ** — и не из байтов, а **из базы/архива**.
Имя размера `dN` — это **`d` + `dimid`** (символьный ключ Creo), поэтому связь строится **индексом**:

```
dimid (из описания колонок/фичеров в файле)  ->  ключ "d<dimid>"  ->  значение из arch_dims
     26                                      ->      "d26"        ->         27.19
```

**Замер боевой базы** (`Z:\PTC\CREO-START\plm_reader\db\plm_reader_20261028_184536.db`, чтение):

| Канал | Что считывает | Первоисточник | Записей | Роль |
|---|---|---|---:|---|
| **`arch_dims`** | JSON `{"d26": 27.19, "d0": 63800.0}` | архивные срезы | **248 572** | **основной**: готовые вычисленные номиналы |
| **`arch_dim_ch`** | `dim`, `old_val`, `new_val`, `kind='размер'` | история изменений | **224 845** | история «было → стало» |
| **`params`** | имя + тип + значение | новый скан файлов | **1 078 484** | КД-атрибуты штампа (ГОСТ, материал) |
| `tree_probe.bat` (J-Link) | `#DIM sym=dN dimid=N val=V` | **живое ядро Creo** | — | **эталон/сверка** горячих правок |
| 🔴 **байты файла** | только `feat_id` + `TYPE_*` | UGC-контейнер | — | **номиналов НЕТ** (§104 п.9) |

**Живые примеры (факт из базы):**
```
ЯЩ-200-236-658-886  dims = {"d0": 63800.0, "d3": 57424.0, "d9": 13.8477, "d4": 28840.0}
ЮКЛЯ_743275_001     dims = {"d100": 10.5977, "d43": 2.3604, "d55": 114208.0, ...}
arch_dim_ch: MV2400S-STOL d26  27.1953 -> 27.1953  (kind='размер')
```
**Проверка сходимости имени:** Creo отдал `sym=d10 dimid=10`, `sym=d26 dimid=26` — в архиве ключи
`d10`, `d26` → **правило `d<dimid>` подтверждено**.

**Код в доме:** `engine.model_params()` (`engine.py:1541`) читает **оба** источника —
сначала `arch_dims` по ИМЕНИ модели (JSON), затем `params` по пути/имени; `plm_history.py:32`
берёт `arch_dims`/`arch_dim_ch`; `plm_graph.py:207` — параметры графа из тех же таблиц.

**Правило:** чтобы показать «размеры основного построения», берём `dimid` (цифровой базис) и
ищем `d<dimid>` в `arch_dims`; J-Link — для сверки свежих значений. **В байтах не искать** (§104).

## 🔴 МАССА/ОБЪЁМ/ПЛОЩАДЬ — РАЗГАДАНО ПО СКРИНШОТАМ ВЛАДЕЛЬЦА (29.10.2026)

**Слово владельца:** «в модель выводится в пострегенерации масса через уравнение `MASS=pro_mp_mass`,
где `pro_mp_mass` — внутренний параметр массы Creo, посчитанный на **ОБЪЁМ × ПЛОТНОСТЬ**».

**Факты со скриншотов живого Creo (модель `DIN912`):**

| Поле (окно «Параметры») | Значение | Что значит |
|---|---|---|
| `PRO_MP_SOURCE` | **`GEOMETRY`** | масса **ВЫЧИСЛЕНА из геометрии** (потому и нет числа) |
| `PRO_MP_ALT_DENSITY` | **`0.000008`** | **плотность ЕСТЬ числом** (8e-6 kg/mm³) |
| `PRO_MP_ALT_MASS`, `_VOLUME`, `_AREA` | пусто/альтернативные | поля заведены, заполняются по режиму |
| `PRO_MP_ALT_COGX…COGZ`, `_IXX…_IYZ`, `_CSYS` | есть | ЦМ, моменты инерции, СК |
| `PTC_UNITS_LENGTH/MASS/FORCE/TIME/TEMPERATURE` | `mm`,`kg`,`mm kg/s²`,`sec`,`C` | **единицы модели** |
| `PTC_UNITS_SYSTEM_TYPE` | `Mass length time (MLT)` | система величин |

**Нить в файле (замер байт `g22033.prt.1`):**
```
PRO_MP_MASS    567 вхождений | PRO_MP_VOLUME 567 | MASS 575
@55822:  ... \xe3 PRO_MP_MASS \x00 = <8 байт> ... (значение ДВАЖДЫ: значение + backup)
числа 0.014921140138664956 как double/float32 — НЕТ (упаковано)
```
**Отношения (читаются ТЕКСТОМ):** `MP_DENSITY=DENSITY` · `MP_DENSITY=DENSITY*1.085` · `MP_DENSITY=DENSITY*0.356`.

**ИТОГ (три канала, как и у размеров):**

| Канал | Что даёт | Читается |
|---|---|---|

**⇒ `\xe0\n` и `\xe0\x0a` — ОДНО И ТО ЖЕ (0x0a = 10 = LF = «длина 10»), по-разному читается в тексте!**
