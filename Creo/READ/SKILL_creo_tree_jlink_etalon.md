# ЭТАЛОН ДЕРЕВА ПОСТРОЕНИЯ ЧЕРЕЗ J-LINK (TreeProbe)

**Зачем:** разбор байтов («что на что меняется», типы фич, размеры `dN`) проверяется ТОЛЬКО
сверкой с живым Creo. Creo — законодатель, файл — копия.

## Запуск (проверено 28.10.2026, Creo 13.4.1.0)

```powershell
cd D:\AI\tools\agent\creo_export
tree_probe.bat "путь\модель.prt.1"        # Creo поднимется сам, если не запущен
mass_probe.bat "путь\модель.prt.1"        # масса/объём/площадь (эталон чисел)
```

**Файлы:** `TreeProbe.java` + `tree_probe.bat` (ASCII-текст, без кириллицы!)

## Формат вывода (машиночитаемый)

```
#MODEL <имя файла>
#FEAT-COUNT <N>                       число элементов дерева
#DIM-COUNT <M>                        число размеров модели
#FEAT <индекс> <feat_id> TYPE_<код> <имя>
#DIM feat=<feat_id> sym=dN name=dN dimid=<id размера> val=<значение>
#PARAM <имя> <значение>
#ERR ...
```

## 🔴 ГРАБЛИ (обе пойманы живьём)

1. **`XToolkitNotFound`** — Creo не запущен. Поднять: `parametric.bat -g:no_graphics -i:rpc_input`
   (D:\PTC\CREO13\Creo 13.4.1.0\Parametric\bin), ждать процесс `xtop`, ~40 с.
2. **`XUnknownModelExtension`** — Creo не принимает имя с версией. Передавать `x.prt`,
   а не `x.prt.1` (номер версии отрезается в `TreeProbe.java`).
3. **`null` в имени / `no_name`** — норма: у элементов имя появляется только у именованных.
4. **`FeatureType` печатался как `com.ptc.pfc.pfcFeature.FeatureType@…`** — у enum нет `toString`;
   номер берётся через reflective `getValue()`/поле `__Value` → в выводе `TYPE_<номер>`.
5. **Импорт `pfcDimension.Dimension`** — классы лежат в `com/ptc/pfc/pfcDimension/`,
   а не в `pfcModelItem`; сверять по `all.txt` в каталоге инструмента, а не по памяти.
6. **У `Feature` НЕТ `ModelItemOwner`** (`ClassCastException`) — список элементов берётся у
   МОДЕЛИ: `ListItems(ModelItemType.ITEM_FEATURE)`; константы — `ITEM_*`, не `MODEL_ITEM_*`.
7. **Кириллица в `.bat` без BOM ломает парсер** — сообщения в bat писать ASCII.

## Связь с разбором БАЙТОВ (что даёт эталон)

- `dimid` из эталона = **id колонки таблицы семейства** в байтах (замер: колонки `14`, `103`
  ↔ `dimid=14`): этим и читается «что меняется в исполнении».
- `feat_id` из эталона ищется в файле как **2-байтовое LE-число** (1-байтовые — шум геометрии).
- Порядок `#FEAT 0..N` — **хронология создания**: её и искать в файле цепочкой id.
- `sym=dN` — **имя размера Creo** (`d10`), `val` — номинал; в байтах текстом `d10` НЕТ.

## 🔴 НОМИНАЛЫ РАЗМЕРОВ: ФОРМАТ НЕ РАЗГАДАН (уточнено замером 28.10.2026)

**Проверено на `g22033.prt.1`** (шпилька): живой Creo отдал 8 размеров с номиналами
(`d7=8.0`, `d8=8.0`, `d10=30.0`, `d13=0.625`, `d14=22.0`, `d15=6.75`, `d27=6.75`, `d28=8.0`).
**Что найдено в файле:**

- точных `double` (BE и LE) — **0**;
- точных `float32` — **0**;
- **дробных** `6.75` / `0.625` — **0** (ни с точкой, ни с запятой);
- числа `30\0`, `22\0`, `8\0` — **есть**, но это **имена исполнений** (`M3x30`, `M4x22`),
  а не значения размеров.

**Вывод (уточнён после замечания владельца «J-Link ничего не выдумывает»):**
Creo значение **показывает**, значит оно **в файле есть** — но **в неразгаданном формате**
(не IEEE-754, не текст). Ставить «не хранится» — **неверно**; правильная формулировка:
**формат хранения номинала не разгадан**.

**Практика до разгадки:**

- **квалитет и режим допуска — читаются из файла** (текстом, см. таблицу выше);
- **номинал** — брать **J-Link** (`tree_probe.bat` → `#DIM feat=… sym=d10 dimid=10 val=30.0`),
  а не выводить из имени исполнения;
- `dimid` и `feat_id` — в файле (2-байтовые LE), известны точно.


## 🔴 ЧТО ХРАНИТСЯ КАК: НОМИНАЛ / КВАЛИТЕТ / ID (замер 28.10.2026)

У размера в файле **несколько полей разной природы** — и это надо знать, чтобы не искать «число» там, где лежит «строка»:

| Поле размера | Как хранится | Читается? | Замер (`g22033.prt.1`) |
|---|---|---|---|
| `dimid` (номер `dN`) | 2-байтовое число (LE) | ✅ | `dimid=10`, `dimid=14` — совпало с Creo |
| `feat_id` (какой элемент) | 2-байтовое число (LE) | ✅ | 19/19 id из эталона найдены |
| **квалитет / посадка** (`H7`, `6g`, `f7`) | **ТЕКСТ** | ✅ **читается** | `6g` **8** · `f7` **6** · `h6` **3** · `H8` **2** · `g6` **2** · `Z6` **2** · `H7` **1** · `H9` **1** |
| режим допуска (`±`, лимиты) | ключ + значение | ✅ ключи есть | `def_tolerance_mode` · `def_tol_display_style` · `linear_dim_tolerance` · `angular_dim_tolerance` · `dim_tol` **6** · `tol_` **35** · `fit` **4** |
| **номинал** (`30.0`, `6.75`) | **ФОРМАТ НЕ РАЗГАДАН** | ❌ | точных `double`/`float32` — **0**; дробные `6.75` / `0.625` текстом — **0**; числа вида `30\0`, `22\0` — это **имена исполнений** (`M3x30`), не размер |
| значения (как числа) — только у Creo | вычисляются/распаковываются | ✅ через J-Link | `#DIM … val=30.0` |

**Правило:** номинал **не выдумывать из имени исполнения** (`M3x30` → «длина 30» — это догадка, а не чтение).
Если нужен точный номинал — **J-Link**. Квалитет и режим допуска — **из файла**.

## 📏 ТИПЫ РАЗМЕРОВ — РАСШИФРОВАНЫ (замер 28.10.2026)

Владелец: «размеры есть линейные, радиусные, диаметральные…» — **подтверждено замером**
на живом Creo (`ctkd_015_23_001.prt.1`, 40 размеров):

| `dtype` | Что это | Живые примеры | Допуск |
|---|---|---|---|
| **`TYPE_0`** | **линейный** | `d9=52.0` · `d10=32.0` · `d13=13.0` · `d17=8.475208614068027` | `DimTolISODIN` |
| **`TYPE_2`** | **радиус / диаметр** | `d11=18.0` · `d18=18.0` · `d24=16.0` · `d29=14.5` | `DimTolISODIN` |
| **`TYPE_3`** | **угол** | `d15=360.0` · `d21=360.0` · `d30=118.0` | **пусто** — у углов квалитета НЕТ |

**Правила:**

- **тип размера читается** (`DimensionType`, номер через reflective `getValue()` — у enum нет
  `toString`), и его кладём в базу рядом с `dimid`;
- **у углов допуска не бывает** — пустое `tol=` у `TYPE_3` это **норма**, а не пропуск;
- подтверждено **двумя независимыми признаками**: три разных класса объектов
  (`@27d6c5e0` / `@5b480cf9` / `@6f496d9f`) и смысл значений (`360.0` = углы, парные = радиусы).

**Канал номинала (не разгадан до конца):** рядом с размером лежат `symbol`, `text(i_val)`,
`parent_dim_id`, `symbol_key` — то есть Creo хранит **символьное выражение и ссылки**,
а число получает вычислением (отсюда «некруглое» `8.475208614068027`).
Ключ дерева — `feat_defs_<ID>` (этот маркер из скилла `feat_defs_deep_dive` **подтверждён**;
ложным был только паттерн-делимитер `FB E3 F7 80`).
