# 🛠️ SKILL: Creo Protocol Decoder (Deep Binary Forensics)

**Назначение:** Низкоуровневое декодирование проприетарного бинарного протокола `e0`, используемого в секциях `GeomDepen`, `Geomlists` и `FeatDefs`.

## 🧬 Структура протокола `e0`
В отличие от простых типов данных, протокол `e0` в контексте зависимостей использует именованные поля:

`[e0] [type_byte] [name]\0 [value]`

### 🔍 Компоненты:
1. **`e0` (0xE0)**: Маркер начала блока/поля.
2. **`type_byte`**: Тип данных, следующий сразу за `e0`.
   - `0x00`: **HEADER/NAME-ONLY**. Поле содержит только имя (например, заголовок секции).
   - `0x01`: **INT** (4 байта, Little or Big Endian).
   - `0x02`: **STRING** (до первого `\x00`).
   - `0x03`: **DOUBLE** (8 байт, Big Endian).
3. **`name\0`**: Строковое имя поля, завершающееся нулевым байтом.
4. **`value`**: Значение, соответствующее типу.

## 🛠️ Методика работы (Forensics)
1. **Поиск маркера**: Используйте `data.find(b'\xe0', offset)`.
2. **Извлечение имени**: Считывайте байты после `type_byte` до первого `\x00`.
3. **Валидация значения**: 
   - Для `INT`: Проверяйте разумные границы (например, `0 < val < 10^7`), чтобы избежать чтения случайных данных как чисел.
   - Для `DOUBLE`: Проверяйте `abs(val) > 1e-12`.
4. **Смещение**: Следующее поле начинается сразу после байтов значения.

## ⚠️ Ошибки и ловушки
- **Пропуск имени**: Попытка прочитать `value` сразу после `e0` приведет к тому, что имя будет интерпретировано как значение (ошибка в `creo_model_parser.py` v0.1).
- **Кодировка**: Имена всегда в `utf-8` или `latin-1`. При ошибках используйте `errors='ignore'`.
- **Не-e0 блоки**: Внутри секций могут встречаться сырые данные без маркера `e0` (например, массив `double` в `Geomlists`).
