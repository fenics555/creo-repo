# СЕМЕЙСТВА И ИСПОЛНЕНИЯ — ЧТЕНИЕ ИЗ ФАЙЛА (без Creo, без загрузки исполнений)

**Зона:** библиотека `Z:\PTC\CREO-START\Libraries` — **ТОЛЬКО ЧТЕНИЕ** (см. `_INDEX.md`).

## 1. ГДЕ СЕКЦИЯ — 🔴 УТОЧНЕНО ЗАМЕРОМ 28.10.2026 (было неверно)

**Было написано:** «признак семейства — размер секции `FamilyInf`». **Это неверно.**
Замер `gost18829-73.prt.1` (35 МБ): `FamilyInf` — **шапка 567 байт** (одинаковая у всех четырёх
проверенных файлов), а **таблица лежит отдельным блоком** рядом:

```
FamilyInf → Sld_FamilyInfo                     ← шапка (567 Б)
  instances_data → user_instances
      user_visible_name → <ИМЯ ИСПОЛНЕНИЯ>     ← имя
      ptc_common_name   → <ИМЯ ОБОЕ>           ← общее имя
  dim_tab_file → info_items (ОПИСАНИЕ КОЛОНОК)
      values_xar → attr · gval · sym_val · type
          value(s_val) · objname · param_val · value(l_val) · value(d_val)
  attributes → gen_mass_prop → mass_prop        ← масса/плотность/объём/ЦМ/инерция
```

**Оглавление файла (`creo_read.parse_toc`) подтверждает координаты** (замер `din912.prt.1`, 5 875 597 Б):
`FamilyInf` @123 177 len **4 476 250** · `instances_data` @124 001 · `user_visible_name` @124 042 ·
`dim_tab_file` @124 244 · `values_xar` @124 785.

**Признак семейства ищи НЕ по размеру, а по МАРКЕРАМ:** `instances_data`, `Sld_FamilyInfo`,
`user_visible_name`, `dim_tab_file`, `values_xar`.

**Для моделей без `FamilyInf`** (`cycloid.SLDPRT` — импорт) пустая таблица **законна**.

## 2. ИНСТРУМЕНТ (готов, проверен)
```
python "D:\AI\ИЗУЧИТЬ\ДАВЫДОВКА\creoJS\creo_bom_js\family_table_file.py" <файл.prt.1> [--json]
```
Восстанавливает **дерево целиком** по двум устойчивым тегам:
* имя **исполнения** — после байта `e3` (между могут стоять тип модели `01`/`02` или `f6`);
* имя **непосредственного generic** — после байта `1f`.
Схема записи пишется один раз в первой записи, дальше идут значения — полный разбор не нужен.
⚠️ Индексные `<папка>.idx` **не годятся**: там у каждого исполнения верхний generic, а не непосредственный.

## 4. СВЯЗКА «ИСПОЛНЕНИЕ → ЗНАЧЕНИЯ ЯЧЕЕК»
Значения лежат текстом **`value(s_val)` ПЕРЕД именем исполнения**; `drv_tbl_ptr` → верхний generic,
рядом `dim_tab_file`, `generic_revnum`, `user_visible_name`.
Проверено на `insert-stp-v1.prt.1` (30 исполнений):
```
INSERT-STP-V1-01 → 24x15,4     INSERT-STP-V1-16 → 28x20
INSERT-STP-V1-02 → 19,05x20,2  INSERT-STP-V1-17 → 28x18
```
В файле **десятичная запятая** (`19,05`).
**Живой пример параметров семейства** (из `din933.prt.1`): `ДЛИНА_ВИНТА`, `ДИАМЕТР_РЕЗЬБЫ`, `ШАГ_РЕЗЬБЫ`,
`ОБОЗНАЧЕНИЕ_РЕЗЬБЫ`, `ВИД_РЕЗЬБЫ`, `ДЛИНА_РЕЗЬБЫ`, `КЛАСС_ТОЧНОСТИ`, `ИСПОЛНЕНИЕ`, `ГЛУБИНА_ШЕСТИГРАННИКА`,

## 5а. 🔴 ИСПОЛНЕНИЕ — ЭТО НЕ ТОЛЬКО ИМЯ (слово владельца, 28.10.2026)

> «В самих файлах родителей уже есть параметры, а в таблицах исполнений — их **иные варианты**
> (не ельты). Не только параметра: есть и разные построения, и можно через таблицу изменить
> параметр, **подавить/заменить элемент**, **поменять размеры в элементах построения**.»
> «Есть сборки, у которых через таблицу семейства + сборку **взаимозамены** меняются разные
> компоненты сборки в исполнениях.»

**Четыре РАЗНЫХ класса того, чем исполнение отличается от родителя:**

| # | Что меняется | Где в Creo (имя поля) | В файле — маркеры |
|---|---|---|---|
| 1 | **Значение параметра** (`ДЛИНА_ВИНТА`, `DIAM`) | колонка типа `param` | `dim_tab_file → values_xar → param_val`, `value(s_val/l_val/d_val)` |
| 2 | **Размер элемента построения** (`d12` → иное значение) | колонка типа `dim` | `objname` + `d_val`, имена `dN` в элементах |
| 3 | **Подавление элемента** (feature suppressed) | колонка типа `suppress` | метки `suppress` / `comp_disp` (в файле при заполненной таблице) |
| 4 | **Замена компонента (взаимозамены)** у СБОРКИ | колонка типа `replace` / `alt` | `values_xar` + `asm_comp` в `.asm` |

**🔴 ЖИВОЙ ПРИМЕР СБОРКИ С ТАБЛИЦЕЙ (турновер, замер 28.10.2026):**
`Z:\PTC\Work\000_14 MP Механизм переворота\000_2 MP-T Турноверы\ПТР-401-МТ-01 Турновер`
- `птр-401-мт-01r-00-t01.asm.1` (7 037 249 Б): `instances_data` 3 · `user_visible_name` 3 ·
  `dim_tab_file` 3 · `values_xar` 3 · **`param_val` 3** · `asm_comp` 5 · `family` 4;
  **исполнение `R-00-T01_ISP-AL`** (родитель `R-00-T01`);
- `птр-401-мт-01-00-t01.asm.1` (4 345 099 Б): те же 3+3+3+3, **исполнение `T01_ISP-AL`**;
- `птр-401-мт-01-12_bdf-v1.asm.1`: таблицы нет (`instances_data` отсутствует) — норма.

**🔴 ГРАБЛЯ, найденная здесь же:** `engine.family_of()` начинается с `if not is_part_file(path): return []`
— то есть **таблицу семейства СБОРКИ он запрещает кодом**, и на обоих файлах турновера вернул
**0 записей**, хотя таблица в файле есть. Это класс отказа **E** (отказ чтения) — исправляется
в коде, не в скилле.

**Правило для сети проверки:** `din912` для этих классов **не годится** — там только имена
(`suppress`/`replace` = **0** вхождений, `param_val` = 1). Эталон классов 2–4 — **турновер**.

## 6. РОЛЬ/РОДИТЕЛЬ У ЧЛЕНОВ СЕМЕЙСТВА
У членов семейства роль «наследование» и **настоящий** родитель — generic
(`din933.prt.1` → `SCREWS_VZ.prt`, `g10341.prt.1` → `SCREWS_SWITCH.prt`).
⚠️ У **не-членов** роль = `MM_ASSY.prt`/`SBORKA_MM.prt` — это шаблон, а не родитель (см. `_core` §6, долг №1).

## 7. ГРАБЛИ
* `familytable:list_tree` в CREOSON на больших семействах **долго/висит** → читать из файла.
* Прерывание долгого вызова CREOSON подвешивает JVM/Creo → сброс **по PID**.
* Имена строк при копии семейства **не меняются**: rename-instance в CREOSON нет
  (`familytable:add_inst` / `replace` / `set_cell` / `delete_inst` / `create_inst`).
* Результат чтения из файла **сверять с сессией** (`ListRows()`): расхождение = файл на диске старее модели
  в сессии, или формат не распознан — тогда дерево из файла не использовать.
