# РОЛИ МОДЕЛЕЙ: ЗЕРКАЛО · НАСЛЕДОВАНИЕ · ЗАГОТОВКА (формат вскрыт по байтам)

## 1. ЗАКОН 1 — ЗЕРКАЛО (ОТРАЖЕНИЕ) = `MERGE_BASE_PART`
Байты из `191-9050-gr4-1-01.prt.1`, секция **`LargeText`** (`@0xf36e`):
```
e0 00 "MERGE_BASE_PART" 00 | 00 27 eb 02 7a d8 00 | e3 33 | f7 1c | "191-9050-GR4-1" 00
                                                       ^ИМЯ РОДИТЕЛЯ
                                             | f7 1d e3 33 "191-9050-GR4-1" 00   (дубль)
```
* **Признак зеркала — только `MERGE_BASE_PART`.** Проверено на трёх файлах одной детали:

| Файл | `MERGE_BASE_PART` | `ref_part_tab` | Вывод |
|---|---|---|---|
| `191-9050-gr4-1.prt.1` (база) | **0** | 2 | обычная деталь |
| `191-9050-gr4-1-01.prt.1` (**зеркало**) | **2** | 1 | **наследование геометрии** |
| `191-9050-gr4-1_z.prt.1` (заготовка) | **0** | 2 | заготовка |

Значит **зеркало — единственная роль с `MERGE_BASE_PART`**; заготовка его не имеет вовсе.
* Родитель читается **дважды подряд** (`f7 1c …` и `f7 1d e3 33 …`) — брать любое из двух.
* Счётчик `flip`: база **19**, зеркало **7**, заготовка **12** — зеркало «перевёрнуто», но
  как признак **не годится** (значения перекрываются).

## 2. ЗАКОН 2 — ЗАГОТОВКА = `ref_part_tabs` → `ref_part_tab` → `name`
Байты из `191-9050-gr4-1_z.prt.1`, секция **`BasBasData`** (`@0x2137`):
```
e0 00 "ref_part_tabs" 00 | e3 | e0 00 "ref_part_tab" 00 | f8 03 f7 18 fb e3
   | e0 00 "objname" 00 | e2 | e0 01 "object_type" 00 | 01 | e0 0a "name" 00 | "191-9050-GR4-1" 00
   | e0 00 "simple_rep" 00 | e1 | e0 00 "inherit_rep" 00 | e1 | e0 00 "p_foreign_source" 00
```
* **Имя родителя = значение поля `name` (тип `0a`) внутри `ref_part_tab`.**
* Рядом всегда идут `inherit_rep`, `p_foreign_source`, `simple_rep`, `gr_creo_src_ver`, `max_part_size`.

⚠️ **У сборок `ref_part_tab` = СПИСОК КОМПОНЕНТОВ, а не родитель** — роль по нему определять
только для `.prt` (проверено: `191-9050-gr4-1.asm.1` даёт `name = 191-9050-GR4-1`, но это компонент).

## 3. ⚠️ ОТСЕВ МУСОРА: ШАБЛОН — НЕ РОДИТЕЛЬ
У обычных деталей `ref_part_tab.name` = **`MM_ASSY` / `MM_PART` / `SBORKA_MM`** — это значение
**шаблона**, а не производная модель. Такой файл — **ни заготовка, ни зеркало**.
Примеры: `191-9050-gr4-1.prt.1`, `insert-stp-s3.prt.1`, `insert-stp-s4.prt.1` → `MM_ASSY`.

**Именно отсюда растёт дефект долга №1 в `plm_reader`:** половина деталей в базе показывается
как «наследование» с родителем `MM_ASSY.prt`, хотя это шаблон. Лечение проверено:
фильтровать префиксы `MM_ASSY` / `MM_PART` / `SBORKA_MM`.

## 5. ПРАВИЛА РАЗБОРА (грабли, оплаченные временем)
1. **НЕ использовать регулярки с `.` или `[\x00-\xff]{N}`** для этих полей — они не срабатывают
   из-за непечатных байт между тегами (проверено: `.{6}e3\x33\xf7\x1c` даёт ложь).
   Только **прямой поиск по индексам** (`bytes.find`) — на них работает `deep_roles.py`.
2. Ядро записи: `e3 33 f7 1c` (родитель зеркала) и `e0 0a name\0` (родитель заготовки).
3. Перед значением лежит **мусорный байт** — отбрасывать (тот же приём, что в параметрах).
4. Имя файла признаком роли **не является**: встречались `_z`, `-Z`, `-01`, `-02`, `-STEP`,
   `-ZERKALO`, `_WRK_01` и даже «заготовка отражения» (`NO221762-11-ZERKALO_WRK_01 ← …-ZERKALO`).

## 6. ПРОИЗВОДСТВЕННАЯ ЦЕПОЧКА (роли по содержимому, проверено)
```
деталь (родитель = шаблон) → заготовка [ref_part_tab] → отливка [ref_part_tab] →
мастер-модель [MERGE_BASE_PART / ref_part_tab] → знаки/ящики/плиты → оснастка (MFG)
```
Зеркало (`MERGE_BASE_PART`) — **побочная ветвь**: геометрия наследуется с переворотом, родитель —
обычная деталь или заготовка.
