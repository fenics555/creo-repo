### Формула для движка

```python
import re
PAT_COMP = re.compile("компонент id (\\d+) \\(([^)]{1,64}\\.(?:PRT|ASM))\\)".encode("utf-8"))

def used_models(raw, own_stem):
    """Что использует .asm-обработка: [(id, имя, роль)]. Роль — по СТРУКТУРЕ, не по имени."""
    out = []
    for cid, nm in PAT_COMP.findall(raw):
        nm = nm.decode("utf-8", "replace"); up = nm.upper()
        role = ("деталь"     if own_stem.upper() in up and "_Z." not in up else
                "заготовка"  if "_Z." in up else
                "инструмент" if up.startswith("T00") else
                "оснастка")   # ← приспособление / оправка / центровка
        out.append((int(cid), nm, role))
    return out
```

### 🔴 ГЛАВНАЯ ГРАБЛЯ: TOC-офсет `DwgData` НЕ ведёт к картинке

Первая версия кода брала смещение из TOC-строки:
```
DwgData 7e7b2 16b     ← offset=0x7e7b2, size=0x16b (363 байта!)
```
**363 байта — это не картинка.** Итог такого подхода: **6 превью из 300 файлов** вместо ~290.
Реальный JPEG лежал совсем в другом месте (напр. @596631 при size из TOC 363 байта).

**ПРАВИЛЬНО — искать по сигнатуре, а TOC-офсет использовать лишь как подсказку:**
```python
def jpeg_size(d):                       # валидация: без SOF это мусор
    i, n = 2, len(d)
    SOF = [bytes([0xFF, c]) for c in (0xC0,0xC1,0xC2,0xC3,0xC5,0xC6,0xC7,
                                      0xC9,0xCA,0xCB,0xCD,0xCE,0xCF)]
    while i < n - 9:
        if d[i] != 0xFF: i += 1; continue
        mk = d[i:i+2]
        if mk in SOF:
            return int.from_bytes(d[i+7:i+9],"big"), int.from_bytes(d[i+5:i+7],"big")
        if mk == b"\xff\xd8" or 0xD0 <= d[i+1] <= 0xD9: i += 2; continue
        ln = int.from_bytes(d[i+2:i+4],"big")
        if ln < 2: return 0, 0
        i += 2 + ln
    return 0, 0

def cut_preview(raw):                   # перебор ВСЕХ FF D8 FF до первого валидного
    j = -1
    while True:
        j = raw.find(b"\xff\xd8\xff", j+1)
        if j < 0: break
        e = raw.find(b"\xff\xd9", j+3)
        if e <= 0: continue
        cand = raw[j:e+2]
        if len(cand) < 2048: continue   # настоящие превью — 9–40 КБ
        w, h = jpeg_size(cand)
        if w and h and 16 <= w <= 4096 and 16 <= h <= 4096:
            return cand, "jpg"
    # BMP: проверять размер и WxH из заголовка (иначе ловятся случайные 'BM')
    b = -1
    while True:
        b = raw.find(b"BM", b+1)
        if b < 0 or b+26 > len(raw): break
        size = int.from_bytes(raw[b+2:b+6], "little")
        w = int.from_bytes(raw[b+18:b+22], "little", signed=True)
        h = int.from_bytes(raw[b+22:b+26], "little", signed=True)
        if 1024 <= size <= len(raw)-b and 16 <= abs(w) <= 4096 and 16 <= abs(h) <= 4096:
            return raw[b:b+size], "bmp"
    return b"", ""
```

### ГРАБЛИ (каждая ловилась живьём)
1. **TOC-офсет `DwgData` ≠ картинка** (см. выше) — 6 превью вместо 290.
2. **JPEG без SOF** — `FF D8 FF` встречается в служебных данных; без проверки маркера SOF
   в медиа попадал мусор 134 КБ–2,5 МБ «без размеров».
3. **Обрыв по лимиту** — если резать «до 200 КБ», JPEG не закрывается (`FF D9` не найден).
   Лечится: искать **конец** `FF D9`, а не ограничивать длину.
4. **Случайные `BM`** давали «BMP 292 байта, размер -566381503×403120695» — обязательна
   проверка `size` из заголовка и разумных WxH.
5. **Дедупликация обязательна:** 6 087 ссылок → 5 494 уникальных (**10%** экономии сразу);
   при повторных сохранениях детали превью не меняется — ссылка на тот же блоб по SHA-256.

### ГРАБЛЯ №2: ДУБЛЬ CSS-ПРАВИЛА МОЛЧА СЪЕДАЕТ ПРАВКУ
В CSS выигрывает **последнее** правило. Если новое добавить **выше** старого — работает **старое**.
Симптом владельца: «картинки большие, как в первый раз», «окно не делится», «правки не применяются».
**Проверка после правки CSS:** каждое ключевое правило (`#side{`, `.row img{`, `#main{`, `#card{`,
`#graph{`) должно встречаться в собранном HTML **ровно 1 раз**:
```powershell
python -c "h=open('CREO_GRAPH.html',encoding='utf-8').read(); import re; [print(n, len(re.findall(re.escape(n),h))) for n in ['#side{','.row img{','#main{','#card{','#graph{']]"
```

### ГРАБЛЯ №3: FLЕX-СКРОЛЛ НЕ РАБОТАЕТ БЕЗ `min-height:0`
Симптом: «в окне нет скролла, содержимое растягивает окно».
Причина: у flex-элемента с `overflow:auto` размер по умолчанию `min-height:auto` —
он растёт под содержимое. **Лечение:**
```css
#main{flex:1 1 auto;display:flex;flex-direction:column;overflow:hidden;min-width:0;min-height:0;height:100%}
#graph{flex:1 1 auto;overflow:auto;min-height:0}
#card {flex:0 0 auto;height:230px;overflow:auto}   /* фикс. высота верхнего окна */
```

### МИНИАТЮРЫ В СПИСКЕ — фиксировать ЖЁСТКО со всех сторон
Симптом: «картинки в левом окне большие, в первый раз было норм».
Причина: `flex:0 0 42px` + `object-fit` без ограничения ширины/высоты — при широком окне картинка
тянется. **Лечение:**
```css
.row img{width:40px;height:40px;min-width:40px;max-width:40px;object-fit:contain;flex:0 0 40px;display:block}
.row .nm{flex:1 1 auto;min-width:0;overflow:hidden}
```

## 5. ГРАБЛИ
* Тип `.mfg` по JLINK **не определяется**: `Model::GetSubtype()` в нашем `pfcasync.jar` НЕТ,
  `instanceof pfcMFG.MFG` даёт **false даже для `.mfg`**, `ModelType` отдаёт 1 (как у детали).
  Опираться на **расширение** и C-API `ProMdlSubtypeGet`.
* Роль компонента (`ComponentFeat.GetCompType()`): `0` заготовка, `1` ссылочная модель, `2` оснастка,
  `10` стержень, `11` результат литья; оснастка ещё ищется по `FEATTYPE_FIXTURE_SETUP = 91`.
* В CREOSON **нет ни одной `mfg-*` функции** — мануфактуринг читается только из файла или через Creo native.
* `familytable`/сборочные вызовы не смешивать с долгими MFG-операциями в одной сессии.
