# МАНУФАКТУРИНГ `ASSEM_MFG` И `.tph` — ЧТЕНИЕ «В ЛОБ»

**Закон владельца: CL-данные (траектории) в ПЛМ НЕ собираем.** Берём **операции / переходы / инструмент**.

## 1. ПРИЗНАК
`#UGC:2 ASSEMBLY/ASSEM_MFG` (отличается от обычной `#UGC:2 ASSEMBLY`).
Состав мануфакчуринг-сборки (проверено на `191-9050-gr4-1.asm.1`): деталь + заготовка +
`INLBS_MFG_NC.ASM` (**оснастка/приспособление**) + `SBORKA_MFG.ASM` + `T0010.PRT` (**инструмент**) +
`HAAS_3X.ASM` (**станок**).
⚠️ Природу модели доказывают **факты Creo** (расширение `.mfg`, `ProMdlSubtypeGet`), **не** параметры
(`ТИП = Производство`, `ПАРТИЯ` — только подсказка) — см. `..\STANDARDS\SKILL_creo_model_nature.md`.

## 2г. ✅ ПРИСПОСОБЛЕНИЕ (ОСНАСТКА) — МЕХАНИЗМ СВЯЗИ ОТКРЫТ (23.10.2026, Cline)

**Задача владельца:** в обработке есть приспособление, которое лежит в отдельной папке
(`…\CTKD-PSB Приспособления`); приспособление может быть **сборкой ИЛИ деталью**, с **любым именем**,
в **любой папке**. У мануфактуринга «встроенного знания» о нём нет — надо найти связь в байтах.

**Проверено** на `Z:\PTC\Work\001_15 ЦТКД Электон\…` (66 папок ЦТКД, только чтение), пробы
`D:\AI\PROBA\work\probe_fixture*.py`. Файл-эталон: `ctkd_738_01_001-01.asm.49` (4,29 МБ, `ASSEM_MFG`).

### Два канала связи

**Канал 1 — структурный (запись компонента), цитата из файла @2250510:**
```
…merge_info_ptr […] dat_ptr(comp_data) […] type […] model_ptr […] object_type […] name.CTKD-PSB-02-01_ […] simpl_rep […] inherit_rep […] p_foreign_source […] ext […] long_name
```
Приспособление — **обычный компонент** сборки-обработки (та же запись, что у деталей).

**Канал 2 — текстовый (Creo сам пишет пояснение), цитаты @3861458 и @3862383:**
```
…компонент id 98931 (CTKD-PSB-04-01.PRT)…ГАБАРИТ…
…компонент id 98931 (CTKD-PSB-04-01.PRT)…MACH01…FSETP3…CTKD_738_01_001-01-4X…
```
Формат: **`компонент id <N> (<ИМЯ>.<PRT|ASM>)`**, текст **в UTF-8**.

### Роли моделей в одном файле (живые данные)

| Роль | Имя | id |
| :--- | :--- | :--- |
| деталь (КД) | `CTKD_738_01_001-01.PRT` | 15 |
| заготовка | `CTKD_738_01_001-01_Z.PRT` | 3313 |
| **приспособление** | `CTKD-PSB-04-01.PRT` | 98931 |
| инструменты | `T0025.PRT`, `T0027.PRT` | 101984 |

### Формула для движка

```python
import re
PAT_COMP = re.compile("компонент id (\\d+) \\(([^)]{1,64}\\.(?:PRT|ASM))\\)".encode("utf-8"))

def used_models(raw, own_stem):
    """Что использует .asm-обработка: [(id, имя, роль)]. Роль — по СТРУКТУРЕ, не по имени."""
    out = []
    for cid, nm in PAT_COMP.findall(raw):
        nm = nm.decode("utf-8", "replace"); up = nm.upper()
        role = ("деталь"     if own_stem.upper() in up and "_Z." not in up else
                "заготовка"  if "_Z." in up else
                "инструмент" if up.startswith("T00") else
                "оснастка")   # ← приспособление / оправка / центровка
        out.append((int(cid), nm, role))
    return out
```

## 5. ГРАБЛИ
* Тип `.mfg` по JLINK **не определяется**: `Model::GetSubtype()` в нашем `pfcasync.jar` НЕТ,
  `instanceof pfcMFG.MFG` даёт **false даже для `.mfg`**, `ModelType` отдаёт 1 (как у детали).
  Опираться на **расширение** и C-API `ProMdlSubtypeGet`.
* Роль компонента (`ComponentFeat.GetCompType()`): `0` заготовка, `1` ссылочная модель, `2` оснастка,
  `10` стержень, `11` результат литья; оснастка ещё ищется по `FEATTYPE_FIXTURE_SETUP = 91`.
* В CREOSON **нет ни одной `mfg-*` функции** — мануфактуринг читается только из файла или через Creo native.
* `familytable`/сборочные вызовы не смешивать с долгими MFG-операциями в одной сессии.
