# SKILL: СХЕМА СКАНЕРА — ДВА ХОДА (RAM → БАЗА) + РЫЧАГ ОТЛАДКИ

> **§184 в `SKILL_GRABLI.md`** · слово владельца (30.10.2026)
> **Владелец:** «читаем всё в **RAM** — из рама нужное пишем в базу. **Два хода, всё просто
> как валенки**. Единственное, для тестов предусмотреть **рычаг для записи RAM в файл** для
> разбора (вдруг читает неправильно)».

## 🔴 СХЕМА (окончательная, ПРОСТАЯ)

```
① ЧИТАЕМ ВСЁ В RAM:   файл (диск Z:) → байты в ПАМЯТЬ (bytes)
② ИЗ RAM → В БАЗУ:    разбор (ящики) → запись (одна транзакция)
③ ФАЙЛ БОЛЬШЕ НЕ НУЖЕН: RAM освобождается (GC)

⇒ ДВА ХОДА. Никакого дискового кеша!
```

## ❌ ЧТО ЗАПРЕЩЕНО (и почему)
| Запрещено | Почему |
|---|---|
| **Кеш на диске (сырьё)** | = **скопировать файлы ещё раз** (70 000 × 600 КБ = **42 ГБ!**) — **БЕСПОЛЕЗНО** |
| **Кеш структуры на диске** | лишний слой (RAM и так есть) |
| **Два прохода по диску** | медленнее в 1.5–2× |

**⇒ RAM = КЕШ. Дисковый кеш НЕ НУЖЕН.**

## 🎚️ РЫЧАГ ОТЛАДКИ: запись RAM в файл (для тестов!)

**Назначение:** если сканер «читает неправильно» — **сохранить байты** и разобрать вручную.

```
НАСТРОЙКА (settings.json):
   dump_raw_dir     — папка для дампов (пусто = ВЫКЛ)
   dump_raw_limit   — сколько файлов сохранить (напр. 10)
   dump_raw_filter  — маска имён (напр. "*.prt.1")

ЧТО ДЕЛАЕТ:
   при сканe — сохраняет СЫРЫЕ БАЙТЫ файла в dump_raw_dir
   (для отладки: открыть, разобрать, понять ошибку чтения)
```

**⚠️ ВКЛЮЧАТЬ ТОЛЬКО ДЛЯ ТЕСТОВ** (иначе 42 ГБ!).

## 🔴 ПРОПУСК НЕИЗМЕНИВШИХСЯ — ПО УМОЛЧАНИЮ

```
ПО УМОЛЧАНИЮ:  не читать файл, если size + mtime совпадают с базой
ОБРАТНАЯ НАСТРОЙКА: «перечитать всё» (full = true) — игнорировать кэш
```
**⇒ Настройка `full` (уже есть в `settings.json`!) — «перечитать всё».**

## 📌 ИТОГ
```
1. RAM = кеш (дисковый кеш ЗАПРЕЩЁН — это копия файлов!)
2. Два хода: чтение → запись
3. Рычаг отладки: дамп RAM в файл (только для тестов)
4. Пропуск неизменившихся — по умолчанию; «перечитать всё» — обратная настройка
```
