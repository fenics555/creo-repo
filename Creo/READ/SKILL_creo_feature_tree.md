# ВОССТАНОВЛЕНИЕ ДЕРЕВА ПРИЗНАКОВ (FEATURE TREE)

Для построения дерева признаков необходимо извлекать зависимости между записями в секции `FeatDefs`.

## 1. Основные механизмы связей

Связи определяются внутри записей признаков через специальные ключевые слова, после которых следует ID связанного объекта.

### 1.1. Типы связей
- **Sub-feature (Child)**: Ключевое слово `sub_feat_id`. Указывает на дочерний признак, который является частью текущего.
- **Parent Link**: Ключевое слово `parent_id`. Указывает на родительский признак.
- **Reference**: Ключевое слово `ref_id`. Указывает на связь с внешним объектом или компонентом.

## 2. Алгоритм построения

1. **Загрузка признаков**: 
   - Найти все записи, начинающиеся с паттерна `feat_[a-zA-Z0-9_]+`.
   - Сохранить их в словарь `features = { id: {offset, data} }`.
2. **Поиск зависимостей**:
   - Для каждого признака просканировать окно (порядка 100 байт) после ключевых слов (`sub_feat_id`, `parent_id`, `ref_id`).
   - Извлечь 4-байтовый integer (пробовать Little Endian и Big Endian).
   - Если найдено валидное число, добавить ребро в граф: `adj[parent].append(child)`.
3. **Построение графа**:
   - Использовать список смежности (`adj`) для обхода дерева.
   - Корни дерева — это признаки, которые не являются "детьми" ни одного другого признака.

## 3. Инструментарий

- `creo_tree_builder.py`: Основной модуль для построения дерева.
- `creo_toc_parser.py`: Для получения начального смещения `FeatDefsIndex`.

## 4. Важные замечания
- **Циклы**: При обходе дерева обязательно отслеживать посещенные узлы (`visited`), так как бинарные данные могут содержать циклические ссылки.
- **Валидация ID**: При извлечении ID всегда проверяйте, что он находится в разумном диапазоне (не 0, не отрицательный, не слишком большой).
