# ОПЕРАЦИИ ПОСТРОЕНИЯ — ЧТО УЖЕ ЧИТАЕТСЯ «В ЛОБ»

**Статус (03.10.2026, после глубинной разведки): имена — ✅ читаются, `feat_id`/тип — ✅ ЧАСТИЧНО,
дерево (порядок/вложенность) — ❌ нет.** Разделено, чтобы не выдавать желаемое за сделанное.

## 0. ВСКРЫТЫЙ ЗАКОН ПОЛЯ (это база всего разбора)
```
<tag e0…ff> <тип> <имя_поля>\0 <значение…>
```
* `тип 01` → 1 байт (id/флаги) · `тип 0a` → **строка** (имя!) · `тип 02` → число/упакованное · `тип 00` → ссылка.
* **Имя операции = строковое поле `name` / `feat_name` / `object_name` / `long_name` с типом `0a`.**
  Это и есть причина прежних «0 операций»: искали ASCII-маркеры `Extrude`/`Sketch` — их в файле **нет вовсе**,
  тип операции хранится **не текстом**.
* Парсер: `re.finditer(rb"[\xe0-\xff][\x00-\x0f]([A-Za-z][A-Za-z0-9_/\.]{1,60})\x00", chunk)`.
* ⚠️ **Баг проб, стоивший времени:** `section("FeatDefs")` матчится с `#FeatDefsIndex` → срез секции неверный.
  Искать маркер **точно**: `\n#Имя[\r\n]`. Плюс база отсчёта = маркер + `len(имя)` + 1.

## 1. ✅ ИМЕНА ОПЕРАЦИЙ — читаются (проверено на 2 моделях)
`23-1017gri-01.prt.1` → **29 уникальных**: `Вытягивание 1…21`, `Эскиз 1`, `Отверстие 1…3`,
`Скругление 1, 8`, `Сечение 1`.
`23-1017gri-01.asm.1` (MFG-сборка) → `Вытягивание 2…20`, `Эскиз 1/2`, `Скругление 3/6/7/8`, `Сечение 1`,
**`Сопряж Границ 1`** (операция сопряжения — тоже распознаётся).

⚠️ **Грабля (у всех):** перед именем лежит **1 мусорный байт-префикс** — `1Вытягивание 4`, `fВытягивание 10`,
`^Вытягивание 5`, `vГабарит`, `Sзаметки`, `3Сталь 45`. Лечение: отбрасывать первый не-кириллический символ.

## 2. ✅ ГДЕ ЛЕЖАТ ИМЕНА (три секции — не одна!)
| Секция | Что там | Признак |
|---|---|---|
| **`MdlStatus`** | имена операций + история правок | `feat_id\0 … f7 29 e2 <ИМЯ>`, рядом `USER\0 e2`, `SER\0 e2` |
| **`FeatDefs`** | `Сечение 1`, `Эскиз 1` + `type` | `e0 0a name\0 <ИМЯ>`, рядом `e0 01 type\0` |
| **`MdlRefInfo`** | `feat_name`, `object_name`, геометрия | `f7 49 <ID> <тип> <смещение> <ИМЯ> 00 <ID> 00` |

**Закон записи операции (по байтам):**
```
f7 49 | 84 8a | 05 84 80 | "Вытягивание 1" 00 | 84 8a | 84 8a | 00
        ^ID?      ^смещ.      ^ИМЯ (UTF-8)          ^ID повторён
```
ID объекта (`84 8a` = 138, `84 ab` = 171 у «Вытягивание 2») **повторяется до и после имени** — это
и есть устойчивый идентификатор записи, по нему можно связать фичи между секциями.

## 3. ✅ `type` — ЧИТАЕТСЯ рядом с именем (частично)
`Сечение 1` → рядом поле `e0 01 type\0` со значением `5`.
Надёжных значений пока мало — **словаря типов нет** (долг №7). Гипотеза: числа кодируют класс операции
(5 = сечение/эскиз-подобная), но **не проверена на 10+ значениях** — не считать законом.

## 4. ❌ ЧЕГО НЕТ
* **Дерева построения** (вложенность, родитель-ребёнок) — не найдено: нет поля «родитель операции»;
* **порядка пересчёта** как отдельного поля — косвенно даёт порядок байтов в файле;
* **ASCII-типов операций** (`Extrude`, `Revolve`, `Sketch`, `Hole`, `Pattern`) — **0 вхождений**;
* библиотеки материалов/плотности из этих секций.

## 6. ПРАВИЛА
* Имена искать **UTF-8 по всему файлу** (кириллица лежит и в `MdlStatus`, и в `FeatDefs`, и в `MdlRefInfo`).
* В `BasicData` числа лежат **UTF-16LE** — для чисел искать и там.
* Запись потока ≈ **10–12 байт**, разделитель `e3`; «шаг 64 байта» — ширина окна диффа, не размер записи.
* При правке параметра секции **пересобираются целиком** → структурный разбор, не побайтовый дифф.
