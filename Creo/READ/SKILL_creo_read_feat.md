# ОПЕРАЦИИ ПОСТРОЕНИЯ — ЧТО УЖЕ ЧИТАЕТСЯ «В ЛОБ»

**Статус: имена — читаются, тип и `feat_id` — нет.** Разделено, чтобы не выдавать желаемое за сделанное.

## 1. ✅ ЧИТАЕТСЯ: ИМЕНА ОПЕРАЦИЙ
Прогон 03.10.2026 на `din933.prt.1` (болт М10×25 DIN 933) — кириллические строки **по всему файлу**:
```
x5  Вытягивание 1      x3  Сечение 1
x4  Вытягивание 2      x1  Винт M10x25 DIN 933
```
То есть **русские имена фичер (Вытягивание/Сечение/Отверстие/Эскиз/Массив/Скругление) лежат в файле**
и находятся поиском кириллических NUL-строк по **всему файлу** (не в одной секции!).

⚠️ Грабля: у многих строк **первый символ — мусорный байт** (в отчёте видно `3Винт`, `3Сталь 45 ГОСТ 1050-88`):
перед значением лежит служебный байт — отбрасывать (то же, что `\xf7` в параметрах).

## 2. ❌ НЕ ЧИТАЕТСЯ: ТИП ОПЕРАЦИИ И `feat_id`
Прогон той же пробы: пары «имя + `feat_id`» — **0 уникальных**; ASCII-маркеры операций
(`Extrude`, `Revolve`, `Sketch`, `Hole`, `Pattern`, `Round`, `CopyGeom`, `Merge`, `Shell`, `Draft`) — **0 вхождений**.

**Где искать дальше (гипотезы, не проверено):**
* `AllFeatur` (24 369 б на `din933`) — поток p-code фичеров; ASCII-имена в нём только `SpecTopolRefs`/`ActiveTopolRefs`;
* `FeatDefs` (14 100 б) — `Medium`, `Defaults`, `INCH`, `NONE`, `THICK`, `STEEL` (похоже, свойства элемента);
* `ActEntity` (1 758 б) — только `DEFAULT`;
* вероятно, тип фичи лежит **числовым кодом** рядом с `feat_id`/в `MdlStatus`, а не текстом.
→ **Долг №7** (см. `SKILL_creo_write_raw.md` §5 и `_INDEX`): снять числовой тип операции.

## 3. СЕКЦИИ, ОТНОСЯЩИЕСЯ К ПОСТРОЕНИЮ
`AllFeatur` · `FeatDefs` · `FeatDefsIndex` · `ActEntity` · `SolidPrimdata` · `VisibGeom` / `NovisGeom` ·
`Xsections` · `GeomDepen` · `BasBasData` / `BasFullData` · `FullMData` (габарит `outline`).

## 4. ИЗВЕСТНОЕ (из прежних проб дома)
* Имена + `feat_id` читались на деталях с русскими именами: `Вращение 1`, `feat_id=3`; поля `feat_id`/`geom_id`/`revnum`.
* Ссылки на элементы компонентов видны **в сборочном** файле: `Скругление 1` ×158, `Отверстие 1` ×73, `Эскиз 2` ×16.
* `assеm_merge_parts` + `AssMrgPrt` → в сборке есть **сборочные** вырезы/слияния (`SKILL_creo_read_asm.md` §3).

## 5. ПРОБА (инструмент сессии)
```
python D:\AI\PROBA\feat_probe\feat_read.py <файл> [отчёт.txt]
```
Печатает: список секций, все кириллические строки файла, ASCII-имена по секциям,
попытки «имя + feat_id», счётчики маркеров типов операций.
⚠️ Второй аргумент обязателен: **отчёт писать в `PROBA`**, не рядом с моделью на `Z:` (зона только чтение).

## 6. ПРАВИЛА
* Имена искать **UTF-8 по всему файлу**; в `BasicData` числа лежат **UTF-16LE** — для чисел искать и там.
* Длина записи потока ≈ **10–12 байт**, разделитель `e3`; шаг 64 байта — это ширина окна диффа, не записи.
* При правке параметра секции **пересобираются целиком** → структурный разбор, не побайтовый дифф.
