# SKILL: Creo Drawing (.drw) Binary Parsing
## Description
Method for extracting model references, sheet information, and drawing attributes from .drw binary files.

## Findings (Stage 5)
- Section Dwg_Models: Contains model name references. Pattern: model_names<MODEL_NAME>.PRT
- Section Dwg_Objects: Contains drawing entities and links.
- Section Dwg_MasterRep: Contains format and master representation data.
- Attribute Records: Key-value pairs. Pattern: [Name]Value@<metadata>

## Integration
- Node: .drw node with role: DRAWING
- Edge: represents -> .prt/.asm node
- Edge: uses_format -> Format node
- Edge: has_sheet -> Sheet node

## 10. БАЙТНЫЕ ПРАВИЛА РАЗМЕТКИ
На основе анализа реальных файлов `00080-03.prt` и `sample.drw` проверены следующие байтовые контракты для .drw файлов:

1. **Счётчики длины секций**
   - Длина каждой секции (включая заголовок) хранится как 16‑битное беззнаковое целое (`uint16`) в big‑endian порядке непосредственно перед маркером секции `#SectionName`.
   - Пример (смещение 0x658f): `0x00 0x65` → длина 165 байт для блока `FamilyInf`.
   - Тот же шаблон встречается для `drv_tbl_ptr` (длина 0x00 0x4b) и `table_name` (длина 0x00 0x4b).

2. **Выравнивание**
   - После счётчика длина выравнивается до 4‑байтовой границы, когда следующий элемент – 32‑битное целое.
   - Паддинг‑байты `0x00` не считаются «мусором», они гарантируют выравнивание следующего `type_code` (`e0…ff`) на 4‑байтовую границу.
   - Для 64‑битных полей (например, `e0 02` double) выравнивание до 8 байт; скрипт выравнивает до ближайшей 8‑байтовой границы.

3. **Коды типов**
   - Байт после счётчика (`e0…ff`) кодирует тип поля:
     - `e0` – 64‑битное число с плавающей запятой (IEEE‑754, big‑endian)
     - `e1` – начало мета‑записи (`e1 f1 … e3` разделитель)
     - `e2` – 32‑битное целое (знаковое, big‑endian)
     - `e3` – завершитель строки или маркер секции.
   - Код **не** является длиной имени; это фиксированный идентификатор.

4. **Имя поля**
   - Имя поля следует за кодом типа как NUL‑терминированная ASCII‑строка (максимум 64 байта). Пример: `drv_tbl_ptr\0`.
   - Имя чувствительно к регистру и может содержать подчеркивания.

5. **Значение**
   - Значение занимает количество байтов, указанных типом:
     - Для `e0` (double) – 8 байт.
     - Для `e2` (int32) – 4 байта.
     - Для мета‑записи (`e1 f1`) – переменная длина, завершающаяся `0x00` или следующим маркером секции.
   - Байты значения интерпретируются согласно типу; они никогда не являются «мусором».

6. **Начало секции (`#SectionName`)**
   - Маркер `#SectionName` появляется после значения предыдущего поля, предшествующего счётчику длины (uint16) и коду типа `e0` (или `e2` для целочисленных секций).
   - Имя секции – ASCII, NUL‑терминированная, может начинаться с префикса `Sld_` для твердых секций.

Эти правила заменяют прежнюю гипотезу «любой байт, не являющийся печатным, – мусор». Каждый байт имеет определённую роль, как показано в hex‑дампe `00080-03.prt` (см. вывод скрипта). Скрипт `byte_map.py` выводит точную разметку полей `drv_tbl_ptr`, `table_name`, `description` и `#FamilyInf`.
