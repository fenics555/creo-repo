### Структура записи
```
PRO_MP_MASS   \x00 f8 01 f7 38 fb e3 f7 39 0e  e3 32 [тип] [7 байт] f1
PRO_MP_VOLUME \x00 f8 01 f7 38 fb e3 f7 39 0e  e3 32 2D   [7 байт] f1
PRO_MP_AREA   \x00 f8 01 f7 38 fb e3 f7 39 0e  e3 32 2D   [7 байт] f1
```
- `e3 32` — маркер значения
- далее **ровно 7 байт** — это IEEE-754 double **БЕЗ старшего байта экспоненты**
- терминатор `f1` / `f7`
- байт типа бывает `0x28` **и** `0x2D` — не искать конкретный байт, а брать
  позицию, где через 7 байт стоит терминатор

### Восстановление старшего байта
В файле его **нет**. Восстанавливаем детерминированно:
1. пара `(mass, volume)` — по плотности: `6…9.5 г/см³` (сталь 7.85)
2. `area` — **тот же** старший байт, что у `volume`

## Прочие схемы DOUBLE (остаются в силе)

| схема | правило | проверено |
|---|---|---|
| тег `0xED` | полные 8 байт BE | `DEFAULT2` = 590903076.7953686 |
| тег `0x2F` | `0x40` + `be[1:3]` + нули | 45.0 / 135.0 / 2.0 / 3.0 |

Для **параметров** lead=2 (`be[2:8]`, теряются `be[0]` и `be[1]`) остаётся
недекодируемым — это другое поле, не `PRO_MP_*`.

## Реестр опровергнутых гипотез (не повторять)

| # | гипотеза | чем опровергнута |
|---|---|---|
| 1 | ведущий байт всегда `0x40` | `double_rule.py` — бывает `0x3F`, `0x41` |
| 2 | ведущий байт `0x3F`/`0x40` | `DEFAULT2` = `0x41` |
| 3 | нулевое усечение хвоста | ни одного префикса BE |
| 4 | в 7-байтовом хвосте 4 бита экспоненты | `tail == orig[1:8]` побайтово |
| 5 | универсальный 7-байтовый формат | длины 2/6/7/8 у ПАРАМЕТРОВ |
| 6 | тег = старший байт экспоненты | `be[0]=40` при разных тегах |
| 7 | заголовок `27 88` хранит экспоненту | контрпример |
| 8 | `mass` в файле отсутствует | **эталон JLINK совпал 6/6** |
| 9 | правило `2D + be[1:8]` не универсально | **моя проверка читала последнее вхождение вместо первого** |
| 10 | CREOSON годится для эталонов | не отдаёт `PRO_MP_*`, нужен JLINK |
| 8 | хардкод `40 06` для семейства `0x55..0x9F` | `test_decoder2.py` — 15 верных / 27 ошибок |
| 9 | подстановка ведущего байта по диапазону | 32 кандидата → 4 разумных, не 1 |

**Контрпример №7** (самый показательный):
```
be[0:2] = 3F C9, тег 0x56  →  41 53 53 00 27 88 20 E3 32 F7 2A 56
be[0:2] = 3F C9, тег 0x56  →  41 53 53 00 27 88 20 E3 32 F7 20 56
```
Одинаковое истинное значение и одинаковый тег — разные пред-теговые байты (`2A` / `20`).
Значит заголовок параметра **не кодирует порядок числа**.

Скрипты-проверки лежат в `Creo/TOOLS/ftype_probe/`: `double_rule.py`, `double_context.py`,
`double_ctx2.py`, `double_payload_diff.py`, `param_header_audit.py`, `test_decoder2.py`.

## Таблица системных свойств PRO_MP_*

В каждой модели есть служебные свойства. Байт **перед** каждым `PRO_MP_*` — последовательный ID:

```
PRO_MP_MASS     3D   → E3 32 F7 20 6F 02 82 F5 94 11 CB      (тег 0x6F, lead=2)
PRO_MP_VOLUME   3E   → E3 32 2D F3 72 8E 3D A3 87 87         (тег 0x2D, lead=1)
PRO_MP_AREA     40   → E3 32 2D CF 09 8C 57 13 7F 5D         (тег 0x2D, lead=1)
PRO_MP_COGX     41   → E3 32 7F 6C B7 AF BA 27 31            (тег 0x7F, lead=2)
PRO_MP_IXY      49   → E3 32 18                                   (нулевой хвост)
```
Это **ID свойства**, а НЕ байт экспоненты. Переключение `0x2D`/`0x6F` внутри одной таблицы
причина не установлена.

**`MASS` — не самостоятельное число**, а бинарная ссылка на `PRO_MP_MASS`:
запись содержит `E0 02 value(d_val)\0` и **те же 6 байт**, что `PRO_MP_MASS`.

## ⚠️ ГЛАВНОЕ ОГРАНИЧЕНИЕ: PRO_MP_* не выгружаются

`parameter:list` через CREOSON возвращает для них **пустоту**. На `137_011_0041`:
```
всего параметров: 28
имена с PRO_MP:  []
все не-STRING:   [('MASS', 'DOUBLE', 6.686151041318472)]
```
При этом в байтах файла лежат **43** записи `PRO_MP_*`.

Следствие: **эталон массовых свойств (VOLUME, AREA) добыть неоткуда** — не через CREOSON.
Значит проверить формулу для `0x2D` нечем. Это не «сложная задача», а «нет источника правды».

## Правило для PLM

`mass_properties.volume` и `mass_properties.area` — **всегда `null`**, пока нет доказанной формулы.
Фантомные числа опаснее отсутствующих: неверная масса попадёт в учёт как достоверная.

> Где в файле есть тег `ED`, объём и площадь читаются **просто и точно**:
> `\xe0\x02 volume \x00\xed` + 8 байт BE double (то же для `surfarea`).

>
> ⚠️ **То есть схемы ДОПОЛНЯЮТ друг друга:** там, где тег `ED` есть — достаточно простого

> Отсюда и рекомендация `null`: она верна не всегда, а только для второй половины файлов.
