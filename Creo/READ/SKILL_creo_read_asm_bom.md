# СОСТАВ ИЗДЕЛИЯ (BOM) ИЗ ФАЙЛА `.asm` — БЕЗ CREO

## ГЛАВНОЕ: заголовок UGC — это ОТКРЫТЫЙ ТЕКСТ

```#UGC:2 ASSEMBLY 142 1 780 804 1 1 15 2900 2008230 00000c9d \
#- VERS 0 0
#- CMNM 00c00080-03.asm
#-END_OF_UGC_HEADER
```
Формат строк: `@тег <номер> <длина>` → следующая строка `<объект> <номер> <ЗНАЧЕНИЕ>`.
**В .asm найдено 91 уникальный `@`-тег.** Никакого бинарного кодека не нужно.

## ШАГ 0. Классификация: 220 из 245 сборок — ЧПУ

| `#UGC:2` | количество | BOM |
|---|---|---|
| `ASSEMBLY/ASSEM_MFG` | **220** | ❌ спецификации нет в принципе |
| `ASSEMBLY` | 25 | ✅ разбирается |

```python
if b'ASSEM_MFG' in data[:2000]:
    return []   # производственная модель, состава нет
```
Это отсекает 90% базы. **Не пытаться вытащить BOM из ASSEM_MFG.**

## ШАГ 1. Схема «поколение 2» — прямые ссылки

Формат: `d <длина> (имя.файла)` — длина открытым текстом.
```python
rb'd \d+ \(([A-Za-z0-9_\-\.]{2,48}\.(?:[Pp][Rr][Tt]|[Aa][Ss][Mm]))\)'
```
Проверено на `most-75.asm` → 5 реальных компонентов:
```
MOST-75-001.PRT   MOST-75-002-SB.ASM   MOST-75-003-SB.ASM
MOST-75-003.PRT   MOST-75-004.PRT
```

## ШАГ 2. Схема «поколение 1» — обёртки

В файлах с `@comp_ids` второй `@model_name` = компонент:
```python
# nut_m12-sl.asm -> ['NUT_M12-SL', 'NUT_M16-SL']
```
Но у 9 из 11 обёрток второй тег **дублирует первый** — это обёртки ЧПУ-сессий, а не сборки.

## ШАГ 3. Поле `to_name` — универсальная запись компонента

```
E0 <len> name\0        <len> MM_ASSY\0
E1 E0 <len> to_name\0  <len> SBORKA_MM\0
E0 <len> user_vis_name\0
E0 <len> d_obj\0   E0 <len> id\0   E0 <len> type\0   E0 <len> p_sf_data\0
```
`name` = тип узла, **`to_name` = имя компонента**.
```python
rb'E0 [\dA-Fa-f]{1,3} to_name\x00(?:[\dA-Fa-f]{1,3} )?([^\x00]{2,48})[\x00\n]'
```

## ⚠️ ЛОВУШКИ (проверены на практике)

1. **`os.path.basename(path).split('.')[0]` ломается** — в путях есть точки
   (`001_10 AGV`). Стемить надо от последнего расширения.
2. **Самоссылки.** `most-75.asm` содержит `MOST-75.ASM`, `MOST-75-001.PRT` и
   `200080-03.ASM` — мусор с префиксами цифр. Отсекать по стему файла.
3. **`@comp_ids` — НЕ счётчик деталей.** Во всех 11 файлах `= 3`, это размер
   структуры. Число компонентов — длина списка `to_name`/`d N (...)`.
4. **Префиксы цифр в именах** (`ESBORKA_MM`, `FMOST-75-001`) — это НЕ отдельные
   детали, а повторяющиеся записи одних узлов с разными полями.
