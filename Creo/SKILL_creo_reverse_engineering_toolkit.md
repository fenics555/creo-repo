# 🛠️ SKILL: Комплект инструментов для реверс-инжиниринга Creo (CR-Toolkit)

**Паспорт:**
- **Назначение:** Хирургическое бинарное извлечение деревьев признаков и параметров из моделей PTC Creo.
- **Домен:** Creo / Реверс-инжиниринг.
- **Приоритет:** `ВЫСОКИЙ` (Специализированный инженерный инструмент).
- **Когда использовать:** Когда требуется анализ модели Creo без запущенного экземпляра Creo, при массовом извлечении признаков из больших наборов данных или при реконструкции дерева признаков напрямую из бинарных файлов.

---

## 🧬 Логика домена
Данный инструментарий работает путем обхода прикладного уровня и взаимодействия напрямую с внутренней структурой форматов файлов. Он полагается на обнаружение специфических сигнатур заголовков типов (протокол `e0`) и смещений TOC (таблицы содержимого) для навигации по бинарному потоку.

## 🛠️ Инструменты и методы

### 1. Основной рабочий процесс (`creo_orchestrator.py`)
- **Метод:** Выполнение одной командой.
- **Сценарий использования:** "Выполнить полный реверс-инжиниринг этого файла".
- **Команда:** `python creo_orchestrator.py <путь_к_файлу>`

### 2. Модульные компоненты
- **`creo_geom_extractor.py`**: Используйте для поиска всех определений признаков и их связанных параметров.
- **`creo_tree_builder.py`**: Используйте для реконструкции отношений родитель-потомок для построения структурного дерева признаков.
- **`creo_feature_classifier.py`**: Используйте для идентификации семантического типа признака (например, Extrude, Sketch).
- **`creo_protocol_decoder.py`**: Низкоуровневый инструмент для декодирования проприетарного бинарного протокола `e0`.

## 🛡️ Методология "Атомарного Инженера" (Atomic Engineer Method)

**ВАЖНО:** Чтобы избежать "петель" (бесконечных повторений ошибок импорта и синтаксиса), используйте этот метод вместо попыток запуска сложных интеграционных тестов.

1.  **Микро-скрипты вместо однострочников**: Никогда не используйте `python -c "long command"` в терминале. Это приводит к ошибкам кавычек и таймаутам. Вместо этого создайте файл `check.py` (5-10 строк), наполните его через `editor` и запустите.
2.  **Атомарная проверка импортов**: Первым делом проверяйте работоспособность импортов в микро-скрипте. Если `import module` не работает — исправляйте `sys.path`, а не код модуля.
3.  **Метод "Малых Шагов"**: Разделяйте задачу на этапы:
    *   Шаг 1: Импорт и чтение TOC.
    *   Шаг 2: Парсинг одного (первого) ID.
    *   Шаг 3: Связка ID с параметрами.
4.  **Только `editor` для правок**: Любое изменение в коде должно быть сделано через `editor`, чтобы гарантировать чистоту символов и отсутствие ошибок интерпретации.

## 📜 Привычки и правила

1.  **Всегда используйте Оркестратор первым**, чтобы получить базовый отчет, прежде чем переходить к точечной работе с отдельными модулями.
2.  **Проверяйте смещения TOC**: Если сканирование не находит признаков, первым шагом должна быть проверка смещения `FeatDefs` в TOC с помощью `creo_read`.
3.  **Проверяйте сигнатуру**: Если извлечение параметров нестабильно, убедитесь, что `creo_protocol_decoder` правильно распознает сигнатуру `0xe0` в бинарном потоке.
4.  **Внимательность к путям**: При импорте модулей всегда добавляйте `D:\\AI\\tools\\agent\\creo_reverse_engineering\\src` в `sys.path`.
5.  **Обработка кодировок**: Файлы могут содержать не-ASCII символы; убедитесь, что все операции чтения/записи используют соответствующие кодировки (UTF-8/Windows-1251).

## 💥 Протокол аварийных ситуаций (Crash-Protocol)

| Симптом ошибки | Диагноз | Действие по восстановлению |
| :--- | :--- | :--- |
| `TOC Parsing Failed` | Поврежден TOC или неподдерживаемая версия файла. | Проверьте целостность файла; проверьте структуру TOC через `creo_read`. |
| `No features found` | Маркеры `feat_defs_` отсутствуют или ошибка смещения. | Проверьте смещение `FeatDefs` в TOC. |
| `Parameter mismatch` | Рассинхронизация сигнатуры протокола (`e0`). | Перезапустите сканирование; проверьте, пропускает ли парсер лишние байты. |
| `ImportError` | Проблемы с путями в `sys.path`. | Проверьте `sys.path` и расположение модулей. |
| **Петля (Looping)** | Попытки запуска сложных тестов через терминал. | **Перейдите на Атомарный Метод (микро-скрипты + editor).** |

## ⚠️ Уроки (Lessons Learned)
* **Опасность интеграции**: Попытки запустить "весь проект сразу" через `run_commands` приводят к краху инструментов (PowerShell/Python/Cline).
* **Приоритет атомарности**: Одна функция $\to$ один микро-скрипт $\to$ один успешный запуск. Только так можно двигаться вперед.

## 🧪 Проверка (Probe)

- **Unit-тест:** Проверьте `creo_protocol_decoder.py` на известной последовательности байтов, содержащей `0xe0`.
- **Интеграционный тест:** Запустите `creo_orchestrator.py` на известном файле `.prt.1` и убедитесь, что количество признаков совпадает с ожидаемым.
- **Тест дерева:** Проверьте, соответствует ли реконструированная иерархия в отчете оркестратора логической ожидаемой структуре родитель-потомок.
