## 1. САМАЯ ЧАСТАЯ: `text not found` ПРИ ТОЧНО СУЩЕСТВУЮЩЕМ ТЕКСТЕ

**Живой факт (16.10.2026, 3 попытки подряд):** правлю обряд в `law_H15.md`. Текст прочитан построчно, скопирован «дословно» — `editor` трижды вернул `text not found`. Файл при этом **в LF, без BOM**.

**Причины (все три сразу):**
1. **Файлы дома — в LF, не CRLF.** Вывод `read_files` показывает `\n`; при копировании блока из **многострочного** фрагмента переносы/склейка могут не совпасть → промах.
2. **Якорь ВЗЯТ ИЗ ОТОБРАЖЕНИЯ, а не из свежего чтения** (номера строк, «…», обрезка) → в тексте его нет.
3. **Якорь многострочный и длинный** — растёт вероятность одного отличия (лишний пробел, «ё»/«е»).

**ОБХОД (жёсткий порядок):**
1. `old_text` — **ОДНА строка**, короткая (≤ 120 символов), скопирована из **свежего** `read_files`.
2. **Никогда** не брать `old_text` из вывода `run_commands` (там склейка, табы, ANSI).
3. **Две неудачи подряд = СТОП.** НЕ повторять тот же якорь. Варианты по порядку:
   - сузить до **одной строки** (или до её уникального куска);
   - правка **через `run_commands`** (`-replace` по regex с `[regex]::Escape`) — для больших блоков;
   - **пересоздать файл целиком** через `editor` (когда правок много).
4. Проверка после правки: `Select-String -Pattern '<маркер>'` — правка применилась.

**Правило дома:** `editor` — для **коротких однострочных** якорей. Всё крупнее — `-replace` или пересоздание.

## 2. `editor` СОЗДАЁТ ФАЙЛ БЕЗ BOM → КИРИЛЛИЦА В `.ps1` ЛОМАЕТ ПАРСЕР

**Симптом:** после создания/правки `.ps1` через `editor`: `Непредвиденная лексема "<кириллица>"`.
**Причина:** PowerShell 5.1 без BOM читает файл как ANSI → русские буквы в мусор → парсер валится.

**Обход (всегда после создания русского `.ps1`):**
```powershell
$f='<файл.ps1>'; $t=$null;$e=$null
[void][System.Management.Automation.Language.Parser]::ParseFile($f,[ref]$t,[ref]$e)
if($e.Count -or ([IO.File]::ReadAllBytes($f))[0] -ne 0xEF){
    $txt=[IO.File]::ReadAllText($f,[Text.Encoding]::UTF8)
    [IO.File]::WriteAllText($f,$txt,(New-Object Text.UTF8Encoding($true)))   # $true = С BOM
}
```
**Правило:** русские `.ps1` после `editor` — **всегда** проверка `ParseFile` + BOM. Массовые замены — только `UTF8Encoding($true)`.

## 3. `editor` МОЖЕТ СХЛОПНУТЬ ФАЙЛ В ОДНУ СТРОКУ

**Симптом:** перезапись через `editor` (создание существующего файла заново) → весь код **в одну строку**, `\n` потеряны, `$переменные` съедены.
**Обход:** для **многострочных** файлов использовать `[IO.File]::WriteAllLines($путь, $массивСтрок, (New-Object Text.UTF8Encoding($true)))` — каждая строка отдельным элементом массива.
**Проверка:** `(Get-Content $f).Count` — если 1 при ожидаемых 40 — файл схлопнут.

## 4. КАВЫЧКИ В `-Command` / `cmd /c` → ОБРЫВ ВЫЗОВА

**Симптом:** `Непредвиденная лексема "сколько"`, `Отсутствует выражение после ","`, `Missing closing '}'`.
**Причина:** вложенные кавычки (`"..."` внутри `'...'` внутри `\"...\"`) не переживают двойную обработку PowerShell+cmd.

**Обход (по приоритету):**
1. **Файл-скрипт** вместо inline: записать `.ps1`/`.py` и запустить `-File`/путь.
2. Кириллицу и сложные строки — **не передавать через `-Command`**, только через файл.
3. Если перевод строки: `[Environment]::NewLine` или `` `n `` внутри `"..."` (double-quoted), НЕ внутри `'...'`.

## 5. `;` В POWERSHELL: ЦЕПОЧКА ПРЕРЫВАЕТСЯ НА ПЕРВОЙ ОШИБКЕ

**Симптом:** вторая команда не выполнилась (`A; B` — B не сработала).
**Причина:** `powershell.exe` возвращает код ошибки при `2>&1` от native-команды, и Cline видит «Command exited with code 1», хотя цепочка продолжается, но вывод теряется.
**Обход:** **разделять команды на отдельные вызовы**; если нужна цепочка — `try { A } catch {}` + `B`; для native: `cmd /c "A 2>&1 & B"`.

## 6. `old_text` НЕ СОВПАЛ (`text not found`)

**Симптом:** правка не прошла, хотя «текст точно есть».
**Причины (по частоте):** (а) опечатка при копировании `old_text`; (б) взял из **устаревшего** чтения; (в) `\r\n` vs `\n`.
**Обход:** `old_text` — **только из свежего `read_files`**; при провале — **укоротить** якорь (1–2 строки), не угадывать; проверить опечатки посимвольно.
**Границы:** `insert_line` по номерам строк **ЗАПРЕЩЁН** законом — только якорь.

## 7. РЕГУЛЯРКИ: lookbehind ПЕРЕМЕННОЙ ДЛИНЫ НЕ ПОДДЕРЖАН

**Симптом:** `Недопустимый шаблон регулярного выражения (?<!A|B)`.
**Причина:** .NET (PS 5.1) не умеет lookbehind переменной длины.
**Обход:** два последовательных `-replace` вместо одного сложного; или позитивный lookbehind фиксированной ширины `(?<=\d)` (один символ — можно).

## 8. ЯКОРЬ «ЗАГОЛОВОК» СЪЕДАЕТ РАЗДЕЛ

**Симптом:** после правки число разделов уменьшилось.
**Причина:** `old_text` = строка заголовка → она заменяется вместе с блоком, содержимое «осиротело».
**Обход:** `old_text` — **минимум две строки ПОСЛЕ заголовка** (заголовок входит в `new_text`).
**Проверка сразу:** `(Select-String -Path $f -Pattern '^## ' | Measure-Object).Count` — должно совпасть с ожидаемым.

## 9. БОЛЬШОЙ `new_text` (> 5–6 КБ) → ТАЙМАУТ `editor` И ПЕТЛЯ В `Thinking`

**Симптом:** `Editor input too large` (> 6 000 символов), таймаут, порча кириллицы при обходе через PowerShell `Set-Content` или **бесконечная петля в `Thinking`**, когда модель пытается завернуть длинный Markdown-текст в Python-скрипт с тройными кавычками `'''...'''`.
**Обход (единственный правильный):**
- Никогда не генерируй `.py`-скрипт ради записи обычного `.md`-текста и не пиши кириллицу через PowerShell `Set-Content`.
- Создай целевой `.md`-файл через `editor` с коротким каркасом (шапка + пустые заголовки разделов на 15–20 строк), а затем заполни каждый раздел отдельным коротким вызовом `editor` (по 2–3 КБ за раз).
**Лимит дома:** один блок `editor` ≤ 4–5 КБ.

## 10. НЕОПРЕДЕЛЁННАЯ ПЕРЕМЕННАЯ = БЕЗЗВУЧНЫЙ ДЕФЕКТ (дорогой!)

**Симптом:** код работает, но результат неверный; в отчётах «пусто», флаги не срабатывают.
**Причина:** в PowerShell обращение к **неопределённой** переменной даёт `$null` **без ошибки** → условие тихо ложно, вывод тихо пуст.
**Живой факт (16.10.2026):** в `check_3_skills_avail.ps1` переменная `$ans` **использовалась в 3 местах** и **нигде не задавалась** → все отчёты печатали «(пусто)».

**Правило:** после **любой** правки скрипта — проверка, что все используемые переменные определены:
```powershell
$uses = @(Select-String -Path $f -Pattern '\$var[^a-zA-Z]').Count
$defs = @(Select-String -Path $f -Pattern '\$var\s*=').Count
if ($uses -gt 0 -and $defs -eq 0) { "ДЕФЕКТ: $var не определена" }
```
**Общий приём:** `Set-StrictMode -Version Latest` в начале скрипта → PowerShell начнёт ругаться на неопределённые переменные.

## 11. ФАЙЛЫ БОЛЬШОГО РАЗМЕРА И КИРИЛЛИЦА В `print()`

1. **Большой размер файла:** не читать целиком (таймаут инструмента, окно переполнено). Читать **диапазонами строк** (`start_line`/`end_line`) по якорю; искать через `Select-String` и читать только совпавшие участки. Файлы > 40 КБ целиком — только по частям.
2. **Кириллица в `print()` (encoding crash):** при выводе кириллических строк через `print()` в Windows-консоль (PowerShell/CMD) вместо текста отображаются `` (консоль использует ANSI/OEM, а Python выводит UTF-8).
   - Выводите результат в файл `> out.txt 2>&1` и читайте через `Get-Content -Encoding utf8`.
   - Для визуального контроля в консоли используйте английский (ASCII) в ключевых `print()`.

## 12. РЕГИСТР: PowerShell НЕ РАЗЛИЧАЕТ, PYTHON РАЗЛИЧАЕТ (живой факт 16.10.2026)

**Симптом:** строка «есть в файле» (найдена `Select-String`), но Python-код её **не находит** → чекер падает вхолостую, хотя правило на диске присутствует.
**Живой факт:** пункт `RULES_REQUIRED` содержал `"ПРЕДПОЛОЖЕНИЕ"` (все заглавные), в законе написано `"Предположение"`. `Select-String` по умолчанию регистронезависим и находил совпадение, а Python `k in HOUSE_SYSTEM` чувствителен к регистру и возвращал `False`.

**Правило (при переносе строк PS → Python):**
1. `Select-String` в PS 5.1 по умолчанию **регистронезависим**. Нужна точная форма → запрашивать **регистрозависимо**:
   ```powershell
   Select-String -Path '<файл>' -Pattern '<строка>' -CaseSensitive
   ```
   либо брать форму из живой цитаты `read_files`.
2. Python: `in`, `==`, `str.find()` — **регистрозависимы**; если нужна устойчивость — `.lower()` с обеих сторон.
3. Кириллица усугубляет: «е»/«ё», «и»/«й» — визуально похожи, а в байтах разные.

## 13. `python -c` ИЗ POWERSHELL ЛОМАЕТСЯ НА КАВЫЧКАХ (живой факт 16.10.2026)

**Симптом:** `Исключение при вызове "Create" с "1" аргументами`, `Отсутствует имя типа после знака "["`, `Непредвиденная лексема ")"` — хотя команда выглядит верной.
**Причина:** PowerShell сам разбирает строку ДО передачи в `cmd /c`. Любые кавычки и скобки внутри конфликтуют с экранированием PS.

**Правило дома:** инлайн `python -c` **ЗАПРЕЩЁН**. Питон — только файлом:
```powershell
# 1) создать .py через editor (кириллица — только editor/write_file)
# 2) запустить с редиректом, чтобы PS не глушил traceback
cmd /c "python -X utf8 <путь>.py > <путь>_out.txt 2>&1"
# 3) прочитать результат read_files
```
**Уборка:** временный `.py` в урне (`D:\AI\log\urn\<исполнитель>\`) — удалить сразу после исполнения.

## 14. КИРИЛЛИЦА В `old_text` НЕ МАТЧИТСЯ, ЕСЛИ ВЗЯТА ИЗ ОТОБРАЖЕНИЯ (23.10.2026, 3 промаха)

**Симптом:** `editor` → `No replacement performed: text not found` — при том, что строка ВИДНА в файле. В отображении: `РџРћР”РЎР§` (мохибейк), а файл при этом **UTF-8/BOM или без**.

**Живой факт (23.10.2026):** правил карту `SKILL_index.md` — якорь с «ПОДСЧЁТ» не матчился 3 раза. Причина в том, что **текст якоря был взят из усечённого вывода** `run_commands`, где кириллица шла мохибейком. В файле — нормальные UTF-8 байты.

**ОБХОД (порядок жёсткий):**
1. `old_text` — **только из свежего `read_files`**, НЕ из `run_commands` и НЕ из «я вижу в выводе».
2. Якорь с кириллицей не матчится 1 раз → **сразу перейти на ЛАТИНСКИЙ якорь** (имя файла, `SKILL_`, бэктики, `Prog\`, цифры).
3. Проверить уникальность якоря **до** правки:
   ```powershell
   $t=[IO.File]::ReadAllLines($p,[Text.Encoding]::UTF8); ($t|Select-String -SimpleMatch '<якорь>'|Measure-Object).Count
   ```
   Нужно ровно `1`.
4. 2 промаха подряд → **смена метода**: Python-скрипт с `io.open(..., encoding="utf-8-sig")`, правка строки **по индексу** в массиве строк, а не по подстроке.

**ГРАБЛЯ ВНУТРИ ГРАБЛИ:** правка ФРАГМЕНТА строки через `editor` **не удаляет** остаток строки — получается обрубок. Якорь обязан либо покрывать ВСЮ строку, либо быть точным фрагментом, а остаток удалять отдельно.

## 15. СКРИПТ-ПИСАТЕЛЬ РОНЯЕТ CRLF → ВЕСЬ ФАЙЛ «ИЗМЕНЁН» (23.10.2026)

**Симптом:** `git diff --numstat` показывает `253 253` (весь файл), хотя правил **6 строк**. История засоряется «переписыванием» файла.
**Причина:** `io.open(P, "w", encoding="utf-8-sig", newline="")` + `"\n".join(lines)` — пишет **только LF**, а файл дома был **CRLF**.

**Пример правильного замера EOL (читать байты напрямую ИЗ ФАЙЛА):**
```powershell
# ПРАВИЛЬНО: читать байты напрямую ИЗ ФАЙЛА
$p='D:\AI\repo\Creo\SKILL_creo_index.md'; $b=[IO.File]::ReadAllBytes($p)
$s=[IO.File]::ReadAllText($p)
"BOM=$(($b[0] -eq 239)) CRLF=$([regex]::Matches($s,\"`r`n\").Count) LF0=$([regex]::Matches($s,\"(?<!`r)`n\").Count)"
# НЕВЕРНО: git show ... | Out-File — Out-File ДОБАВЛЯЕТ CRLF → ложный 'регресс EOL'
```

**ОБХОД:**
1. Перед правкой — замерить EOL: `$b=[IO.File]::ReadAllBytes($p); ($b|?{$_ -eq 13}|Measure-Object).Count`.
2. Писать **тем же** EOL, что был: читать с `newline=""`, **не** нормализовать, либо явно `data.replace("\r\n","\n").replace("\n","\r\n")` перед записью.
3. **После правки — проверить счётчик CR** и `git diff --numstat` **до** `git add`.
4. Поймал регресс после коммита → вернуть CRLF и `git commit --amend --no-edit -- <paths>`.

## 16. «TEXT NOT FOUND» ПОСЛЕ УДАЧНОЙ ПРАВКИ = ПРАВКА УЖЕ ПРИМЕНЕНА (23.10.2026)

**Симптом:** второй `editor` с тем же `old_text` возвращает `text not found`, хотя файл только что правился именно так.
**Причина:** первая правка УЖЕ заменила якорь. Повтор ищет то, чего больше нет → это **не** промах, а сигнал «готово».
**Правило:** прежде чем менять метод — **прочитать файл** и убедиться, какая форма сейчас на диске.

## 17. ФУНКЦИЯ «ЧТЕНИЕ» МОЖЕТ ПИСАТЬ — ПРОБА ИСПОРТИЛА ЖИВЫЕ НАСТРОЙКИ (23.10.2026)

**Симптом:** после «безопасной» пробы настройки приложения изменились сами.
**Живой факт (PLM Reader):** проба звала `plm_settings.load_settings_file(path=<копия в песочнице>)`. Функция **кроме чтения** делает подчистку и перенос старых файлов, поэтому **живой `settings\settings.json` был перезаписан тестовыми данными**.

**ПРАВИЛО (жёсткое):**
1. Перед вызовом чужой функции — **прочитать её тело** (не имя!) и найти `open(...,"w")`, `os.replace`, `shutil.move`, `os.remove`, `_archive_*`, `save_*`. Есть — это **пишущая** функция.
2. Для проб проверки: **не запускать программу в рабочем каталоге**. Копия каталога в песочницу (`%TEMP%` или `log\urn\<исполнитель>\sandbox\<метка>\`) — и работать там.
3. Перед пишущей пробой — **снимок живого файла** (`Copy-Item <файл> <урна>\<файл>_before`), чтобы откат был мгновенным.

## 18. ТРИ ПРИЗРАКА СВЯЗЕЙ: связи «есть», а их НЕТ (23.10.2026, PLM Reader)

**Симптом:** узел показывает «состав 0 · входит 0», в графе — одинокая вершина. Пользователь говорит «связи не работают», хотя в базе связи **лежат**.

**ТРИ ПРИЗРАКА (проверять всегда):**
1. **Связь-в-шаблон.** `parent`/`child` = `SBORKA_MM`, `SBORKA_MFG`, `MM_PART`, `MFG_NC` → это **не связь изделия**, а шаблон. Если фильтр шаблонов включён — узел останется одиноким.
2. **Связь не собрана движком.** «Нет в `links`» ≠ «нет в файле». Тип связи может просто **не читаться** (мастер-модель по `Base_Part`/`_Z`, сознание ЧПУ по `T0xxx`/операциям).
3. **Обрезка лимитом.** `total > 120` / `slice(0,25)` в обходе **съедают** связи ещё до показа.

**Как проверять (SQL, живым счётом):**
```sql
SELECT parent, child, qty FROM links WHERE parent=? OR child=?;
SELECT child, base, kind  FROM derived WHERE child=? OR base=?;
SELECT COUNT(*), COUNT(DISTINCT parent), COUNT(DISTINCT child) FROM links;
```

## 20. POWERSHELL `-eq` НЕ РАЗЛИЧАЕТ РЕГИСТР → ПРАВКА ПРОПУСКАЕТСЯ (05.11.2026, материалы Creo)

**Симптом:** скрипт должен добавить параметр `МАТЕРИАЛ`, но **не добавляет** (0 изменений), хотя параметра в файле нет (в файле был строчный `Материал`).
**Причина:** PowerShell сравнивает строки **регистронезависимо**: `-eq`, `-ne`, `-like`, `-match` — все **игнорируют регистр** по умолчанию.

**ЛЕЧЕНИЕ — операторы с `c` (case-sensitive):**

| Регистронезависимо (ПЛОХО) | Регистрозависимо (ПРАВИЛЬНО) |
|---|---|
| `-eq` | **`-ceq`** |
| `-ne` | `-cne` |
| `-like` | `-clike` |
| `-match` | **`-cmatch`** |
| `-in` | `-cin` |
| `-contains` | `-ccontains` |

## 21. ЛОКАЛЬ ru-RU СТАВИТ ЗАПЯТУЮ В ДРОБНЫХ ЧИСЛАХ → ФАЙЛ ИСПОРЧЕН (06.11.2026, материалы Creo)

**Симптом:** скрипт пишет плотность `2.780000e-06 kg/mm^3`, а в файле оказывается `2,780000e-06`. Creo читает **точку** как десятичный разделитель.

**ЛЕЧЕНИЕ — только InvariantCulture для чисел, идущих в файлы:**
```powershell
$inv=[Globalization.CultureInfo]::InvariantCulture
$s = $v.ToString('0.000000e-00',$inv)    # -> "2.780000e-06"  (ТОЧКА)
```
Тот же капкан — в `[double]::Parse()`: без `$inv` строка `2.78` разберётся как `278`.

## 22. `[string[]]` НЕ ИМЕЕТ `InsertRange` (06.11.2026, материалы Creo)

**Симптом:** `Method invocation failed because [System.String] does not contain a method named 'InsertRange'.`
**Причина:** `$arr = $t -split "`r`n"` даёт **`string[]`** (фиксированный массив). `InsertRange`, `.Add()`, `.RemoveAt()`, `.Insert()` есть только у **`ArrayList`**.

**ЛЕЧЕНИЕ:**
```powershell
$lines=$t -split "`r?`n"
$arr=New-Object System.Collections.ArrayList
foreach($ln in $lines){ [void]$arr.Add($ln) }
$arr.InsertRange($end+1,$ins)
```

## 23. БИНАРНЫЕ ФАЙЛЫ Creo НЕЛЬЗЯ ПРАВИТЬ ТЕКСТОМ (06.11.2026, форматы .frm.1)

```powershell
$b=[IO.File]::ReadAllBytes($p)
$isBinary = ($b[0..199] -contains 0)
```

## 24. БЭКАП ВНУТРИ РАБОЧЕЙ ПАПКИ ЗАРАЖАЕТ СЧЁТЧИКИ (06.11.2026, материалы Creo)

**Симптом:** счётчик показал 3286 файлов вместо 2501 — разница 785 = бэкап внутри дерева.
**ПРАВИЛО:** в любом замере/правке исключать папки, начинающиеся с `_`:
```powershell
Get-ChildItem -LiteralPath $p -Recurse -Filter '*.mtl' -File |
  Where-Object { $_.FullName -notmatch '\\_[^\\]*\\' }
```
**Бэкап делать ВНЕ рабочего дерева**, не внутри рабочей папки.
