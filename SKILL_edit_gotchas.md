# ГРАБЛИ ПРАВКИ ФАЙЛОВ И КОМАНД (живые, с обходами)

> Каждая грабля стоила ходов. Читать нужный раздел ПЕРЕД правкой. Разведка — `SKILL_recon.md` §0–§2.

**Навигация:** редактор §1–§16 · консоль §4–§13 · кодировки/EOL §2/§15/§21 · Creo/БД/JS §18/§23/§27.

---

## 0. МАРШРУТ ПЕРЕД ПРАВКОЙ (разведка → выбор метода)

Правка — основная работа ноги и главный источник падений. Закон: **сначала метрики файла, потом инструмент** (`SKILL_recon.md` §0–§2). Перед правкой проверить: существует? размер/строки? BOM/EOL? бинарник (§23)? уникален ли якорь (`Select-String`, ровно 1)? После правки — `Select-String` по маркеру.

| Ситуация (разведка) | Инструмент / метод |
|---|---|
| Файла НЕТ (новый) | `editor` с `new_text`, БЕЗ `old_text` |
| Есть; точечная правка; unique-якорь | `editor`, `old_text` = **одна** короткая строка из свежего `read_files` (§1) |
| Есть; много правок; блок ≤ 5 КБ | несколько `editor`-вызовов по ≤ 5 КБ (§9) |
| Есть; блок > 5 КБ | `run_commands` (`-replace` с `[regex]::Escape`; `Set-Content`/`WriteAllLines` UTF-8) + проверка чтением (§9/§15) |
| Вставить/удалить по номеру строки | `insert_line` **ЗАПРЕЩЁН** (`.clinerules` §4.3) → якорь или пересоздание |
| Кириллица в `.ps1` | UTF-8 **с BOM** (§2) |
| Дробные числа | `InvariantCulture` — точка, не запятая (§21) |
| Бинарник Creo | текстовая правка запрещена (§23) → объектный слой/скрипт |

**Анти-петля:** 2 промаха `text not found` подряд = СТОП и смена метода (§1, `.clinerules` §4.7). Никогда не `delete→recreate` для «обновить содержимое» — править `editor` с якорем.

## 1. САМАЯ ЧАСТАЯ: `text not found` ПРИ ТОЧНО СУЩЕСТВУЮЩЕМ ТЕКСТЕ

**Причины:** (а) файлы дома в LF — при копировании многострочного фрагмента переносы/склейка не совпали; (б) якорь взят из отображения (номера строк, «…», обрезка), а не из свежего `read_files`; (в) якорь длинный/многострочный — растёт вероятность одного отличия (пробел, «ё»/«е»); (г) опечатка; (д) `\r\n` vs `\n`.

**Обход (жёсткий порядок):**
1. `old_text` — **ОДНА** короткая строка (≤ 120 символов) из **свежего** `read_files`. Никогда — из вывода `run_commands` (там склейка, табы, ANSI, мойбейк).
2. **Две неудачи подряд = СТОП**, не повторять якорь. По порядку: сузить до одной строки; перейти на **латинский якорь** (имя файла, `SKILL_`, бэктики, цифры); правка через `run_commands` (`-replace` с `[regex]::Escape`); пересоздать файл.
3. Уникальность якоря до правки:
   `$t=[IO.File]::ReadAllLines($p,[Text.Encoding]::UTF8); ($t|Select-String -SimpleMatch '<якорь>'|Measure-Object).Count` → ровно `1`.
4. После правки — `Select-String -Pattern '<маркер>'` — применилась.
5. **«text not found» после удачной правки = правка уже применена** (§16): прочитать файл, а не менять метод.

**Кириллица в якоре:** не матчится 1 раз → сразу латинский якорь; 2 промаха → Python-скрипт с `io.open(..., encoding="utf-8-sig")`, правка строки **по индексу** в массиве строк.

**Грабли внутри грабли:** правка ФРАГМЕНТА строки не удаляет остаток — якорь покрывает ВСЮ строку либо остаток удаляется отдельно.

**Правило дома:** `editor` — для коротких однострочных якорей; `old_text` > 5000 симв. — дробление или `-replace`/пересоздание.

## 2. `editor` СОЗДАЁТ ФАЙЛ БЕЗ BOM → КИРИЛЛИЦА В `.ps1` ЛОМАЕТ ПАРСЕР

**Симптом:** `Непредвиденная лексема "<кириллица>"`. PowerShell 5.1 без BOM читает как ANSI → мусор → парсер валится.

**Обход (всегда после создания русского `.ps1`):**
```powershell
$f='<файл.ps1>'; $t=$null;$e=$null
[void][System.Management.Automation.Language.Parser]::ParseFile($f,[ref]$t,[ref]$e)
if($e.Count -or ([IO.File]::ReadAllBytes($f))[0] -ne 0xEF){
    $txt=[IO.File]::ReadAllText($f,[Text.Encoding]::UTF8)
    [IO.File]::WriteAllText($f,$txt,(New-Object Text.UTF8Encoding($true)))   # $true = С BOM
}
```
**Правило:** русские `.ps1` после `editor` — всегда `ParseFile` + BOM; массовые замены — `UTF8Encoding($true)`.

---

## 3. `editor` МОЖЕТ СХЛОПНУТЬ ФАЙЛ В ОДНУ СТРОКУ

При перезаписи существующего файла заново возможны потеря `\n` и «съедание» `$переменных`. Для многострочных — `[IO.File]::WriteAllLines($путь, $массивСтрок, (New-Object Text.UTF8Encoding($true)))`. Проверка: `(Get-Content $f).Count` — если 1 при ожидаемых 40, файл схлопнут.

## 4. КАВЫЧКИ В `-Command` / `cmd /c` → ОБРЫВ ВЫЗОВА

**Симптомы:** `Непредвиденная лексема "сколько"`, `Отсутствует выражение после ","`, `Missing closing '}'`; `= : The term '=' is not recognized…`; `Test-Path : Missing an argument for parameter 'LiteralPath'` — внешняя оболочка съела `$переменную`.

**Причина:** вложенные кавычки не переживают двойную обработку PowerShell+cmd; `$var` в double-quoted `-Command` раскрывается внешним PowerShell до передачи в дочерний.

**Обход:**
0. **НИКОГДА** не гонять `$переменные` и кириллицу через `powershell.exe -Command "…"` — писать `.ps1` (UTF-8 **с BOM**) и запускать `powershell -File`, либо давать команды напрямую в `run_commands`. Сигнатура нарушения — `The term '=' is not recognized…`.
1. Файл-скрипт вместо inline.
2. Кириллицу и сложные строки — только через файл.
3. Перевод строки — `[Environment]::NewLine` или `` `n `` в double-quoted, не в `'...'`.

## 5. `;` В POWERSHELL: ЦЕПОЧКА ПРЕРЫВАЕТСЯ НА ПЕРВОЙ ОШИБКЕ

`powershell.exe` возвращает код ошибки при `2>&1` от native-команды → Cline видит «exited with code 1», вывод теряется. Разделять команды на отдельные вызовы; цепочка — `try { A } catch {}` + `B`; для native — `cmd /c "A 2>&1 & B"`.

Причины и обход — §1. Главное: якорь только из свежего `read_files`, не угадывать, 2 промаха = смена метода.

## 7. РЕГУЛЯРКИ: LOOKBEHIND ПЕРЕМЕННОЙ ДЛИНЫ НЕ ПОДДЕРЖАН

`Недопустимый шаблон (?<!A|B)`: .NET (PS 5.1) не умеет lookbehind переменной длины. Два последовательных `-replace`; позитивный lookbehind фиксированной ширины `(?<=\d)` — можно.

## 8. ЯКОРЬ «ЗАГОЛОВОК» СЪЕДАЕТ РАЗДЕЛ

`old_text` = строка заголовка → заменяется вместе с блоком, содержимое осиротело. `old_text` — минимум две строки ПОСЛЕ заголовка (заголовок входит в `new_text`). Проверка: `(Select-String -Path $f -Pattern '^## ' | Measure-Object).Count`.

## 9. БОЛЬШОЙ `new_text` (> 5–6 КБ) → ТАЙМАУТ `editor` И ПЕТЛЯ В `Thinking`

**Симптом:** `Editor input too large` (> 6000 символов), таймаут, порча кириллицы при обходе через `Set-Content`, бесконечная петля в `Thinking` при заворачивании Markdown в Python-скрипт с `'''...'''`.

**Обход:** не генерировать `.py` ради записи `.md`; не писать кириллицу через `Set-Content`. Создать `.md` через `editor` с коротким каркасом (шапка + пустые заголовки), заполнять разделы короткими вызовами по 2–3 КБ. Лимит дома: блок `editor` ≤ 4–5 КБ.

**Эмпирика (19.11.2026, проверено):** `Set-Content -Encoding UTF8` и `[IO.File]::WriteAllText(..., UTF8Encoding($true))` **сохраняют** кириллицу (сверено по кодам); кракозябры в консоли — артефакт вывода, проверять **чтением файла**. Для блока > 5–6 КБ допустимы оба пути: дробление `editor` или запись `run_commands` с обязательной проверкой чтением.

## 10. НЕОПРЕДЕЛЁННАЯ ПЕРЕМЕННАЯ = БЕЗЗВУЧНЫЙ ДЕФЕКТ

В PowerShell обращение к неопределённой переменной даёт `$null` без ошибки → условие тихо ложно, вывод тихо пуст. Живой факт (16.10.2026): в `check_3_skills_avail.ps1` `$ans` использовалась в 3 местах и нигде не задавалась → все отчёты «(пусто)».

**Правило:** после правки скрипта — проверка определённости:
```powershell
$uses = @(Select-String -Path $f -Pattern '\$var[^a-zA-Z]').Count
$defs = @(Select-String -Path $f -Pattern '\$var\s*=').Count
if ($uses -gt 0 -and $defs -eq 0) { "ДЕФЕКТ: $var не определена" }
```
`Set-StrictMode -Version Latest` в начале скрипта → PowerShell ругается на неопределённые.

## 11. БОЛЬШИЕ ФАЙЛЫ И КИРИЛЛИЦА В `print()`

1. Файл > 40 КБ целиком не читать — диапазонами по якорю (`Select-String` → `read_files` start/end).
2. Кириллица в `print()` в Windows-консоль — `` вместо текста. Вывод в файл `> out.txt 2>&1` и читать `Get-Content -Encoding utf8`; в ключевых `print()` — ASCII.

## 12. РЕГИСТР: POWERSHELL НЕ РАЗЛИЧАЕТ, PYTHON РАЗЛИЧАЕТ

Живой факт (16.10.2026): `RULES_REQUIRED` содержал `"ПРЕДПОЛОЖЕНИЕ"`, в законе — `"Предположение"`; `Select-String` (регистронезависим) находил, Python `in` — нет.

## 13. `python -c` ИЗ POWERSHELL ЛОМАЕТСЯ НА КАВЫЧКАХ

Симптомы: `Исключение при вызове "Create"…`, `Отсутствует имя типа после знака "["`, `Непредвиденная лексема ")"`. PowerShell разбирает строку до `cmd /c`; кавычки и скобки конфликтуют. **Правило:** инлайн `python -c` запрещён. Питон — файлом:
```powershell
# 1) .py через editor (кириллица — только editor/write_file)
# 2) запуск с редиректом, чтобы PS не глушил traceback
cmd /c "python -X utf8 <путь>.py > <путь>_out.txt 2>&1"
# 3) прочитать результат read_files
```
Временный `.py` — в урну `D:\AI\log\urn\<исполнитель>\`, удалить сразу.

## 14. КИРИЛЛИЦА В `old_text` — СМ. §1

## 15. СКРИПТ-ПИСАТЕЛЬ РОНЯЕТ CRLF → ВЕСЬ ФАЙЛ «ИЗМЕНЁН»

**Симптом:** `git diff --numstat` показывает `253 253`, хотя правил 6 строк. **Причина:** `io.open(P,"w",encoding="utf-8-sig",newline="")` + `"\n".join(lines)` пишет только LF, а файл был CRLF.

**Замер EOL (читать байты из файла):**
```powershell
$p='<файл>'; $b=[IO.File]::ReadAllBytes($p); $s=[IO.File]::ReadAllText($p)
"BOM=$(($b[0] -eq 239)) CRLF=$([regex]::Matches($s,\"`r`n\").Count) LF0=$([regex]::Matches($s,\"(?<!`r)`n\").Count)"
# НЕВЕРНО: git show ... | Out-File — Out-File ДОБАВЛЯЕТ CRLF → ложный регресс
```
**Обход:** замерить EOL до правки; писать тем же EOL (читать `newline=""`, не нормализовать, либо `replace("\r\n","\n").replace("\n","\r\n")`); после — счётчик CR и `git diff --numstat` до `git add`; поймал регресс после коммита → вернуть CRLF и `git commit --amend --no-edit -- <paths>`.

## 17. ФУНКЦИЯ «ЧТЕНИЕ» МОЖЕТ ПИСАТЬ — ПРОБА ИСПОРТИЛА ЖИВЫЕ НАСТРОЙКИ

## 18. ТРИ ПРИЗРАКА СВЯЗЕЙ: СВЯЗИ «ЕСТЬ», А ИХ НЕТ

Проверять всегда: (1) связь-в-шаблон (`SBORKA_MM`, `SBORKA_MFG`, `MM_PART`, `MFG_NC`) — не связь изделия; (2) связь не собрана движком («нет в `links`» ≠ «нет в файле»); (3) обрезка лимитом (`total > 120`, `slice(0,25)`). Проверка — SQL-счётом: `SELECT parent, child, qty FROM links WHERE parent=? OR child=?;`. Детали — `PLM\SKILL_plm_reader.md`.

## 20. POWERSHELL `-eq` НЕ РАЗЛИЧАЕТ РЕГИСТР → ПРАВКА ПРОПУСКАЕТСЯ

Симптом: скрипт не добавляет `МАТЕРИАЛ`, хотя параметра нет (в файле строчный `Материал`). PowerShell сравнивает регистронезависимо.

| Плохо | Правильно |
|---|---|
| `-eq` | **`-ceq`** |
| `-ne` | `-cne` |
| `-like` | `-clike` |
| `-match` | **`-cmatch`** |
| `-in` | `-cin` |
| `-contains` | `-ccontains` |

## 21. ЛОКАЛЬ ru-RU СТАВИТ ЗАПЯТУЮ В ДРОБНЫХ ЧИСЛАХ → ФАЙЛ ИСПОРЧЕН

Скрипт пишет `2,780000e-06` вместо `2.780000e-06`; Creo читает точку. Только `InvariantCulture`:
```powershell
$inv=[Globalization.CultureInfo]::InvariantCulture
$s = $v.ToString('0.000000e-00',$inv)    # -> "2.780000e-06"  (ТОЧКА)
```
Тот же капкан в `[double]::Parse()`: без `$inv` строка `2.78` разберётся как `278`.

## 22. `[string[]]` НЕ ИМЕЕТ `InsertRange`

`$arr = $t -split "`r`n"` даёт `string[]`; `InsertRange`/`.Add()`/`.RemoveAt()`/`.Insert()` есть только у `ArrayList`.
```powershell
$lines=$t -split "`r?`n"
$arr=New-Object System.Collections.ArrayList
foreach($ln in $lines){ [void]$arr.Add($ln) }
$arr.InsertRange($end+1,$ins)
```

## 23. БИНАРНЫЕ ФАЙЛЫ Creo НЕЛЬЗЯ ПРАВИТЬ ТЕКСТОМ

`.frm.1`, `.prt`, `.asm`, `.drw` — только через Creo. Текстовые правки — `.mtl`, `.mat`, `.pro`, `.inf`, `.txt`, `.md`.
```powershell
$b=[IO.File]::ReadAllBytes($p); $isBinary = ($b[0..199] -contains 0)
```

## 24. БЭКАП ВНУТРИ РАБОЧЕЙ ПАПКИ ЗАРАЖАЕТ СЧЁТЧИКИ

Счётчик показал 3286 вместо 2501 — разница 785 = бэкап внутри дерева. В замерах/правках исключать папки, начинающиеся с `_`:
```powershell
Get-ChildItem -LiteralPath $p -Recurse -Filter '*.mtl' -File |
  Where-Object { $_.FullName -notmatch '\\_[^\\]*\\' }
```
Бэкап — ВНЕ рабочего дерева.

## 25. ТРАНСПОРТ `run_commands`

1. Таймаут 30 с, `python -c` запрещён, `Test-Path` перед чтением созданного — `.clinerules` §4.5, §13.
2. **Таймаут 30 с убивает ДЕРЕВО процессов (включая дочерний python) — крах ≥5 раз.** Длинное — только `Start-Process` с детачем в лог, **не** `cmd /c start` (умирает вместе с консолью агента); после таймаута **НЕ ждать повторными опросами** (sleep-poll = петля) — проверить `Test-Path` результата.
3. **Сетевые загрузки — не группировать (20.11.2026):** в один `run_commands` не более 2 `Invoke-WebRequest` с `TimeoutSec >10` (суммарно < 30 с); долгие — по одной. Иначе `Command was aborted`.
4. Никогда не печатать имя/теги/аргументы инструмента (`</invoke>`, JSON) как текст — вызов только системный.

## 26. ТЕРМИНАЛ: GIT-ХУКИ, `PYTHONPATH`, ЭКРАНИРОВАНИЕ

1. **BOM в `.git\hooks\*`:** хук на PowerShell — UTF-8 с BOM, иначе `Непредвиденная лексема`. После `editor` перезаписать с BOM; проверка — первые 3 байта `EF BB BF`.
2. **`PYTHONPATH` в shell-хуках:** задавать явно в POSIX-форме — `export PYTHONPATH="/d/AI/repo:$PYTHONPATH"`.
3. **Экранирование `$` в `-Command`:** `$` съедается оболочкой — обратный апостроф или `.ps1`; кириллицу в `-Command` не передавать (`.clinerules` §4.4). См. §4 п.0.
4. **Проверка после правки хука:** `git hook run pre-commit` (или тестовый `git commit`) + чтение первых 3 байт файла на BOM.
5. **`Get-Content` без `-Encoding UTF8` = мойбейк (19.11.2026):** PS 5.1 читает UTF-8 как ANSI → `Р”РРЎРџ…`; это артефакт чтения, но при записи в файл мойбейк закрепится. Читать всегда `-Encoding UTF8`, писать `Set-Content -Encoding UTF8`.

## 27. МАТЕРИАЛЫ CREO: «МОЛЧАЛИВЫЙ ОТСЕВ» `.mtl`

Creo может не читать `.mtl` без ошибок: карточка есть, параметры не показываются. Три причины: нет UTF-8 BOM; смешанные EOL (CRLF + одиночный LF); `Type = Real` целым числом (`179` вместо `179.0`). Корень — пакетные скрипты точечной перезаписи сбили EOL/формат → 74 карты Стали перестали читаться. Правило: `.mtl` переписывать только целиком (`open(path,"w",encoding="utf-8-sig",newline="")`, единый CRLF) + чекер (BOM · CRLF · `Real`-с-точкой · 45 блоков). Детали — `Creo\STANDARDS\SKILL_material_parameters.md` §3а.
